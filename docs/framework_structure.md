# 프로젝트 폴더 구조

> ## 이 문서는 (STANDARD_LAYOUT.md 와의 관계)
>
> 이 문서(`framework_structure.md`)는 **실제 구현 소스 구조도**입니다 — 앱 코드가 어느 폴더에 사는지(`apps/ backend/ modules/ packages/ infra/ docs/`), 각 폴더가 뭐 하는 곳인지 설명하는 도감입니다.
>
> **framework 와 standard 는 "둘 중 하나 고르기"가 아니라 "기반 + 얹기" 관계입니다.**
>
> | 개발 방식 | 적용 문서 |
> |---|---|
> | **하네스 X** (그냥 코딩) | `framework_structure.md` **만** (소스 구조) |
> | **하네스 O** (AI 파이프라인) | `framework_structure.md` **+** `하네스설계/STANDARD_LAYOUT.md` (소스 구조 **위에** 하네스 규약 얹기) |
>
> - 이 문서(소스 구조)는 하네스를 쓰든 안 쓰든 **항상 깔리는 기반**입니다.
> - 하네스로 개발하면 여기에 더해 `STANDARD_LAYOUT.md`(하네스 작업 폴더 `0dev_haness_agents/` 규약)를 **얹습니다**.
> - **예약(reservation) 등 하네스 프로젝트 = framework + standard 둘 다 적용**.

## 구조도

```text
project/
├── ai/                              # AI에게 보여줄 대본 모음
│   ├── agents/                      #   AI 성격·할 수 있는 일·금지 사항
│   ├── prompts/                     #   AI에게 보여줄 질문 템플릿
│   ├── policies/                    #   AI가 지켜야 할 안전 규칙
│   └── evaluations/                 #   AI 답이 맞는지 채점할 정답지
│
├── apps/                            # 사용자가 보는 화면
│   ├── web/                         #   웹사이트
│   ├── mobile/                      #   휴대폰 앱
│   └── admin/                       #   운영자가 쓰는 관리 페이지
│
├── backend/                         # 화면 뒤에서 일하는 서버
│   ├── services/                    #   돌아가는 서버 프로그램들
│   │   ├── api/                     #     사용자 요청을 받고 답하는 메인 서버
│   │   ├── worker/                  #     시간 걸리는 일을 뒤에서 처리

│   └── platform/                    #   기반 도구 설정

│       ├── cache/                   #     빠른 임시 저장소 설정
│       └── queue/                   #     작업 대기열 설정
│
├── modules/                         # 이 프로젝트의 핵심 영역
│   ├── identity/                    #   사용자·조직·권한
│   ├── notification/                #   알림 발송
│   └── {main-domain}/               #   프로젝트 핵심 (쇼핑·예약·학습 등)
│
├── packages/                        # 여러 곳이 함께 쓰는 도구함
│   ├── types/                       #   공통 데이터 형식
│   ├── ui/                          #   공통 화면 부품
│   └── logger/                      #   기록(로그) 헬퍼
│
├── infra/                           # 배포·운영 자동화
│   └── docker/                      #   Docker 설정
│
└── docs/                            # 사람이 읽는 문서
    ├── architecture/                #   설계 도면
    ├── product/                     #   기획·요구사항
    ├── api/                         #   API 사용 설명서
    ├── ai/                          #   AI 사용 설명서
    ├── runbook/                     #   운영 매뉴얼
    ├── security/                    #   보안 정책
    ├── decisions/                   #   왜 이렇게 결정했는지 기록
    └── developer/                   #   개발 역할별 안내서
```

## `ai/` — AI 대본 보관함

AI 챗봇이나 자동 추천 같은 기능을 쓰는 경우에, AI에게 보여줄 자료들을 한곳에 모아둡니다. 프로그램 코드가 아니라 글과 표만 들어가서, 개발자가 아닌 기획자도 직접 손볼 수 있어요. AI를 쓰지 않는 프로젝트라면 비워둬도 됩니다.

- **`0dev_haness_agents/`** — AI가 어떤 성격으로 답하고, 어떤 도구를 쓸 수 있고, 무엇은 하면 안 되는지를 정의합니다. 예: "친절한 비서 모드", "엄격한 감사관 모드" 같은 페르소나가 각각 파일로 들어갑니다.
- **`ai/prompts/`** — AI에게 매번 보여주는 질문 템플릿이 버전별로 정리되어 있습니다. "이런 정보를 받아 이런 형식으로 답해줘" 같은 표준 양식이에요.
- **`ai/policies/`** — AI가 지켜야 할 안전 규칙입니다. 예: 개인정보를 답에 노출하지 말 것, 의료 진단처럼 위험한 답은 사람이 한 번 검토해야 할 것.
- **`ai/evaluations/`** — AI가 답을 잘 했는지 채점할 정답지입니다. 표준 질문과 모범 답안을 모아두고, AI나 프롬프트를 바꿀 때마다 점수가 떨어지는지 확인하는 용도입니다.

## `apps/` — 사용자가 보는 화면

사용자가 직접 보고 만지는 부분입니다. 프로젝트 종류에 따라 이 셋 중 일부만 씁니다.

- **`apps/web/`** — 브라우저에서 접속하는 웹사이트입니다. 컴퓨터로 보든 휴대폰으로 보든 같은 주소로 들어가는 그 화면이에요.
- **`apps/mobile/`** — 앱스토어에서 설치하는 휴대폰 앱입니다. iOS와 Android 양쪽을 모두 지원합니다.
- **`apps/admin/`** — 일반 사용자는 못 보고 운영자만 들어가는 관리 페이지입니다. 가입자 관리, 결제 처리, 장애 대응을 여기서 합니다.

---

## `backend/` — 화면 뒤에서 일하는 서버

사용자 눈엔 안 보여도, 사용자가 버튼을 누르면 뒤에서 일을 처리해 답을 돌려주는 부분입니다. 크게 두 갈래로 나뉩니다.

### `backend/services/` — 실제로 돌아가는 서버 프로그램

- **`services/api/`** — 사용자 요청을 받고 즉시 답을 돌려주는 메인 서버입니다. 화면에서 보내는 모든 요청은 여기로 와요.
- **`services/worker/`** — 시간이 오래 걸리는 일(이메일 발송, 큰 파일 처리, AI 분석)을 뒤에서 천천히 처리하는 일꾼입니다. 사용자가 기다리지 않게 비동기로 돌립니다.
- **`services/scheduler/`** — 매일 새벽 3시 백업, 매주 월요일 리포트 발송처럼 정해진 시간마다 자동으로 돌아가는 작업을 관리합니다.

### `backend/platform/` — 기반 도구 설정

- **`platform/database/`** — 데이터를 영구 보관하는 저장소(데이터베이스)의 설정과 구조 변경 이력입니다. 새 기능 때문에 테이블 모양을 바꿀 때 그 변경 기록이 여기 쌓여요.
- **`platform/cache/`** — 자주 쓰는 데이터를 빠르게 꺼내려고 잠깐 메모리에 저장해두는 임시 저장소의 설정입니다. 데이터베이스보다 훨씬 빠르지만 휘발성이에요.
- **`platform/queue/`** — 작업을 줄 세워두는 대기열 설정입니다. worker가 이 줄에서 작업을 하나씩 꺼내 처리합니다.

## `modules/` — 이 프로젝트의 핵심 영역

이 프로젝트가 실제로 무슨 일을 하는지가 들어가는 곳입니다. 쇼핑몰이라면 상품·주문, 병원 예약이라면 환자·예약처럼 프로젝트마다 가장 많이 달라지는 부분이에요.

- **`modules/identity/`** — 사용자·조직·권한 관리. 회원가입, 로그인, "이 사람이 이 기능을 쓸 수 있는가"를 판단합니다. 거의 모든 프로젝트에 공통으로 들어갑니다.
- **`modules/notification/`** — 알림 발송. 이메일, 카카오톡, 푸시 알림, 관리자에게 가는 슬랙 메시지 같은 통보를 한 곳에서 관리합니다.
- **`modules/{main-domain}/`** — 이 프로젝트만의 핵심 영역. 쇼핑몰이면 `catalog`/`order`, 헬스케어면 `appointment`/`patient` 같은 폴더로 갈아 끼웁니다. 프로젝트가 바뀌면 이 부분이 통째로 달라져요.

---

## `packages/` — 여러 곳이 함께 쓰는 도구함

웹·앱·서버가 따로따로 같은 코드를 쓰지 않도록 공통 코드를 한 곳에 모아둡니다.

- **`packages/types/`** — 데이터 형식 정의입니다. "사용자란 이름·이메일·생년월일을 가진다" 같은 약속을 웹·앱·서버가 모두 같은 정의를 보고 쓰게 합니다.
- **`packages/ui/`** — 버튼·입력창·표 같은 공통 화면 부품입니다. 디자인 색깔과 글꼴 규칙(디자인 토큰)도 여기에 둡니다.
- **`packages/logger/`** — 기록(로그)을 출력하는 공통 헬퍼입니다. 모든 서버가 같은 형식으로 로그를 남기게 통일합니다.

---

## `infra/` — 배포·운영 자동화

서버를 언제·어디에·어떻게 띄울지에 대한 자동화 설정입니다.

- **`infra/docker/`** — Docker는 "서버를 깡통 하나에 담아 어디서든 똑같이 띄우게 해주는 도구"입니다. 그 깡통을 어떻게 만들지에 대한 설계도가 여기 들어갑니다. 프로젝트가 커지면 이 폴더 옆에 클라우드 배포(`k8s`, `terraform`), 모니터링(`prometheus`, `grafana`) 폴더가 추가됩니다.

## `docs/` — 사람이 읽는 문서

코드가 아니라 사람이 읽는 글들이 모이는 곳입니다.

- **`docs/architecture/`** — 시스템 전체가 어떻게 생겼는지 보여주는 설계 도면입니다. 어느 서버가 어느 DB에 연결되는지, 데이터가 어디서 어디로 흐르는지를 그림과 글로 적어둡니다.
- **`docs/product/`** — 기획·요구사항. "왜 이 기능을 만드는가, 누가 쓸 것인가, 어떤 모습이 될 것인가"가 들어갑니다.
- **`docs/api/`** — API 사용 설명서. 외부 개발자나 같은 팀 다른 개발자가 이 서버를 어떻게 호출하는지를 정리합니다.
- **`docs/ai/`** — AI 기능을 어떻게 쓰는지에 대한 설명서. `ai/` 폴더가 자료라면, `docs/ai/`는 그 자료를 어떻게 다루는지에 대한 안내서입니다.
- **`docs/runbook/`** — 운영 매뉴얼. "이 알람이 울리면 이렇게 대응해라" 같은 장애 대응 절차서가 들어갑니다.
- **`docs/security/`** — 보안 정책. 개인정보 보호, 접근 권한, 사고 대응 절차 등.
- **`docs/decisions/`** — 왜 이렇게 결정했는지 기록(ADR). "A와 B 중에 왜 A를 골랐고, 어떤 단점은 감수하기로 했는지"를 남겨, 나중에 사람이 바뀌어도 배경을 알 수 있게 합니다.
- **`0dev_haness_agents/`** — 하네스 작업 폴더 (`.gitignore` 됨, 2026-05-21 `ai/` 접두 폐기). 구성:
  - `main_plan/` (사장님↔main 협업 S0 산출물) — `plan.md` + **`dag/d<N>_<도메인>/task_index.md` + `dag/d<N>_<도메인>/t<N>_*.md`** (2026-05-26 dag 표준, Airflow 정합) + `storyboard/` + `unit_test/` + `qa/`
  - `user_plan/` (사장님 원본 요구 입력 spec)
  - `last_report/` (main 점검 보고)
  - `<new-*>/` (16개 sub-agent 산출물 — handback / machine_summary / spec_match)
  - `_pipeline/schemas/` (machine_summary.schema.json)
- dag 구조 상세 = 글로벌 룰 `~/.claude/CLAUDE.md §도메인 DAG 룰` 참조. shop 프로젝트는 영구 제외.
