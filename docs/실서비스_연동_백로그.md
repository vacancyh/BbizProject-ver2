## 0. 현재 상태 요약

- **기능**: 스토어프론트(가입·상품·장바구니·체크아웃·주문·마이페이지·리뷰·문의·적립금·등급·쿠폰·동의·고객센터·배너·큐레이션·신상품·**베스트 랭킹**·**인기검색어**·비회원조회)와 관리자(주문·상품·회원·배송·정산·통계·쿠폰·리뷰/문의·약관·권한·감사·고객센터콘텐츠·배너·홈큐레이션·**2단계 인증(2FA)**) **구현 완료**, E2E 검증됨.
- **보안(무비용, 적용 완료)**: 관리자 **2FA(TOTP, 서버측 세션 게이팅·시크릿 암호화·백업코드·QR)**, 주문 IDOR 가드, 인증·검색어 rate limit(캐시 추상화 → Redis-ready), 비밀번호 정책, 입력 길이 상한, 보안 헤더/CSP. → §10 보안 체크리스트.
- **데모 한정(운영 전 교체 필요)**: 결제=무통장입금(수기)만, 이미지=picsum 플레이스홀더, 소셜로그인·본인인증=mock, 알림 발송·세금계산서 발행·배송추적=미연동.
- **인프라**: 로컬(Docker DB/Redis + 네이티브 Node). AWS·도메인·실 DB는 **아직 미사용**(개발 마무리 후 진행 예정 — 본 문서에 요건만 정리).

## 1. 실행 아키텍처 · 인프라 (AWS 권장 구성)

현재 로컬은 `Postgres(5434)`+`Redis(6381)` Docker, 백엔드(:9000)·스토어프론트(:8000)·관리자(:7002) 네이티브. 운영은 아래로 이관.

| 구성요소 | 로컬(현재) | 운영(권장) | 비고 |
|---|---|---|---|
| 백엔드(Medusa) | 네이티브 :9000 | **ECS Fargate** 또는 EC2(+PM2) | 컨테이너 이미지화, ALB 뒤 |
| 스토어프론트(Next) | 네이티브 :8000 | ECS/EC2 또는 **Vercel/Amplify** | SSR 필요 → Node 런타임 |
| 관리자(Next) | 네이티브 :7002 | ECS/EC2 (내부/사내 IP 제한 권장) | 관리자망 분리 |
| DB | Docker Postgres | **RDS for PostgreSQL**(Multi-AZ) | 자동백업·스냅샷 |
| 캐시/큐 | Docker Redis | **ElastiCache for Redis** | 세션/이벤트버스/워크플로우 |
| 이미지·정적 | 로컬/picsum | **S3 + CloudFront(CDN)** | §4 참고 |
| 도메인/DNS | localhost | **Route53** | shop.example / admin.example / api.example |
| TLS 인증서 | 없음 | **ACM** + ALB/CloudFront | HTTPS 강제 |
| 로드밸런서 | 없음 | **ALB**(경로/호스트 라우팅) | api/admin/store 분리 |
| 시크릿 | .env 파일 | **AWS Secrets Manager / SSM Parameter Store** | 커밋 금지 |
| 로그/모니터링 | 콘솔 | CloudWatch(Logs/Alarm) + (Sentry 등) | |

> 최소 시작 구성: RDS(1) + ElastiCache(1) + ECS 서비스 3(백엔드/스토어/관리자) + S3/CloudFront + ALB + Route53 + ACM.

## 2. 환경변수 · 시크릿 (운영 값으로 교체)

로컬 `.env`(커밋 금지)의 키를 운영에서 **Secrets Manager/SSM** 로 주입한다.

| 키 | 로컬 | 운영 |

| (신규) 결제 PG 키, 알림 provider 키, S3 자격 | — | §3·§4·§5 |

## 3. 결제(PG) 연동 — 🔴 최우선

현재 `pp_system_default`(무통장입금/수기)만 활성. 실제 카드·간편결제 승인이 없음.

### 3.1 선택지 (택1~다)
- **국내 PG**: 토스페이먼츠 · KG이니시스 · 나이스페이먼츠 · KCP
- **간편결제**: 카카오페이 · 네이버페이 · 페이코 (PG 경유 또는 직접)
- 정기결제(구독) 필요 시 빌링키 지원 PG 확인.

### 3.2 계약·준비
1. 사업자등록·통신판매업신고·정산계좌.
2. PG 가맹점 심사(수 영업일~수 주), 상점ID/시크릿 발급.
3. 결제 수수료(건당 %) · 정산주기 확인.

### 3.3 구현 (Medusa v2 Payment Provider)
- `backend/services/api/src/modules/<pg>-payment/` 모듈 생성 → `medusa-config.ts` 의 `modules` 에 등록, `payment` 모듈의 provider 로 연결.
- 구현 메서드: `initiatePayment`/`authorizePayment`/`capturePayment`/`refundPayment`/`cancelPayment`/`getPaymentStatus`/`getWebhookActionAndData`.
- **웹훅 수신 라우트**: `src/api/webhooks/<pg>/route.ts` — 승인/취소/부분취소/정산 통지 처리(서명 검증 필수).
- 스토어프론트 결제단계(`apps/web/src/modules/checkout/components/payment`)에 PG 위젯/리다이렉트 연동. `constants.tsx` `paymentInfoMap` 에 provider 표기 추가.
- 주문 상태 전이(승인→`captured`, 취소→`canceled`, 환불→`refunded`)를 기존 워크플로우/정산(`settlement-payout`)과 연결.

### 3.4 검증
- PG 테스트(샌드박스) 모드로 승인/취소/부분취소/환불 전 구간 확인 → 운영 전환.

## 4. 이미지 · 정적 자산 (데모 → 실제)

- **현재**: 상품/배너 이미지가 `picsum.photos` 플레이스홀더(데모). `apps/web/next.config.js` `images.remotePatterns` 에 picsum/unsplash 허용 추가돼 있음.
- **운영 전환**:
  1. 실제 상품 이미지를 **S3 버킷** 업로드 → **CloudFront** 배포(도메인 예: cdn.shop.example).
  2. Medusa File Provider 를 **S3** 로 설정(관리자 상품 등록 시 S3 업로드). `medusa-config.ts` file 모듈.
  3. `next.config.js` `remotePatterns` 에서 **picsum/unsplash 제거**하고 CDN 호스트만 허용.
  4. 상품 `image`/`thumbnail` URL 을 CDN 경로로 교체(데모 이미지 `id like 'img_demo_%'` 정리).

## 5. 알림 발송 (이메일 / SMS / 카카오 알림톡)

현재 비밀번호 재설정·재입고·주문 알림이 **접수/구독까지만** 동작(발송 provider 없음).

- **이메일**(🟡 저비용): SES 또는 SMTP → Medusa Notification Provider 모듈 + 템플릿. (회사 SMTP 사용 시 비용 거의 없음)
- **SMS / 카카오 알림톡**(🔴 과금): NHN Toast·알리고·솔라피 등 대행 계약 + **발신번호 사전등록** + **알림톡 템플릿 심사**.
- **재입고 발송 트리거**: 입고(재고 0→양수) 이벤트 subscriber 에서 `restock_subscription` 조회 후 발송(현재 구독 저장만 됨).
- 연동 포인트: 백엔드 Notification Provider, `restock-notification` 모듈 + 신규 subscriber, `password-reset`.

## 6. 본인인증 (PASS / NICE) — 🔴

- **현재**: 가입 휴대폰 인증이 클라이언트 mock(`phone-verify`).
- **필요**: 본인확인기관(NICE평가정보·KCB 등) 계약 → 인증 모듈 연동(가입/주문자 실명확인). 건당 요금.
- 연동: 가입 폼(`modules/account/components/register`), 주문자 정보.

## 7. 소셜 로그인 (카카오 / 네이버) — 🟡

- **현재**: `socialLoginMock()` 이 provider별 데모 계정으로 로그인(없으면 자동가입).
- **필요**: 카카오/네이버 개발자센터 OAuth 앱 등록 → REST 키/시크릿/redirect URI. 백엔드 `/auth/customer/{provider}` 콜백 + 토큰교환 + 고객 매핑. `apps/web/.../customer.ts` `socialLoginMock` → 실제 OAuth 교체. (앱 등록 무료, 비즈 검수 필요)

## 8. 배송 트래킹 · 세금계산서 발행

- **배송 트래킹**(🟡): 현재 운송장번호+외부조회 링크. 실시간 추적(집화→간선→배송출발→완료)은 **택배사/스마트택배 API 연동 필요**(일부 무료쿼터). 모듈 `carrier-adapter` 스캐폴딩 존재.
- **세금계산서 실발행**(🔴): 현재 신청 접수(`tax-invoice` pending)까지. 팝빌·바로빌 등 대행 계약 → 발행/전송/취소 API 연동.

## 9. 배포 파이프라인

1. **빌드**: 백엔드 `pnpm build`(.medusa/server) → 컨테이너 이미지. 스토어/관리자 `next build`.
2. **DB 마이그레이션**: 배포 시 `npx medusa db:migrate` (커스텀 모듈 포함). 롤백 대비 스냅샷.
3. **시드/초기데이터**: 운영은 **실제 데이터**로 등록(데모 시드·`img_demo_*`·데모 계정 제외). 지역/통화(KRW), 배송옵션, 약관, 상품정보고시, 결제 provider 는 운영 값으로.
4. **publishable key**: 운영 DB에서 재발급 → 스토어 env 반영.
5. **프로세스 관리**: ECS 서비스(오토스케일) 또는 PM2. 헬스체크 `/health`.
6. **CI/CD**: GitHub Actions → 빌드/테스트/이미지 push/ECS 배포(권장).

## 10. 보안 체크리스트 (운영 전)

- [ ] `JWT/COOKIE/REVALIDATE_SECRET` 강력 랜덤 재생성, Secrets Manager 보관(커밋 금지).
- [ ] `NODE_TLS_REJECT_UNAUTHORIZED=0` 제거, 전 구간 HTTPS.
- [x] **보안 헤더 적용**: `next.config`(스토어/관리자)에 X-Frame-Options(store=SAMEORIGIN, admin=DENY)·X-Content-Type-Options·Referrer-Policy·Permissions-Policy·HSTS·CSP. ⚠️ 운영: CSP `connect-src`/`img-src` 를 실제 도메인으로 좁히고 `'unsafe-eval'` 제거(nonce) 권장.
- [x] **비밀번호 정책**: 가입/재설정 시 8자+영문+숫자 강제(`middlewares.ts` passwordPolicyGuard, 로그인 제외). 클라이언트 폼 안내 병행.
- [x] **입력 길이 상한**: 리뷰/문의/1:1 사용자 콘텐츠에 최대 길이(내용 5000·제목 200·이름 50·이메일 254) 검증(`_utils/text.ts`) — 과대 payload 남용 방지.
- [x] **비밀번호 재설정 토큰 만료**: Medusa 코어 resetPassword 토큰은 JWT exp(기본 TTL, `AUTH_*` 설정) 내장 → 만료 후 무효. 운영에서 TTL 값 확인·조정.
- [x] **관리자 2FA(TOTP) + 서버측 세션 게이팅**: 구현·검증 완료(무비용, 옵트인). `admin-2fa` 모듈(`admin_totp`, `admin_totp_session` 테이블) + 순수 Node crypto TOTP(RFC 6238, `_utils/totp.ts`, 외부 의존 0). 라우트 `POST /admin/2fa/setup`(시크릿) → `activate`(활성) → 로그인 시 `verify`(6자리). 관리자 `설정 > 2단계 인증(/settings/security)`에서 등록/해제. 로그인 페이지가 비번 통과 후 2FA 활성 계정이면 코드 단계로 전환.
  - **서버측 게이팅(우회 차단)**: `verify` 성공 시 해당 로그인 토큰의 sha256 을 `admin_totp_session` 에 만료시각(24h)과 함께 저장. `/admin/*` 미들웨어(`twoFactorGuard`)가 2FA 활성 관리자의 **미검증 토큰**을 403(`2FA_REQUIRED`)로 차단 → 클라이언트 우회 불가. 관리자 클라이언트는 403 `2FA_REQUIRED` 수신 시 재로그인 유도. 2FA 해제 시 세션 폐기(`revokeSessions`). API 게이팅 13/13 + 실브라우저 로그인 흐름 검증 통과. 기본 admin 계정은 미활성(E2E 무영향).
  - **시크릿 암호화 저장**: AES-256-GCM(`_utils/secret-crypto.ts`)로 시크릿 암호화 후 저장(DB엔 `v1:...` 암호문, 원문은 응답에만). 키 = env `ADMIN_2FA_SECRET_KEY` > `COOKIE_SECRET`. ⚠️ 운영: 전용 키를 KMS/Secrets Manager 로 주입·로테이션.
  - **백업(복구) 코드**: 활성화 시 1회용 코드 10개 발급(해시 저장), 인증기 분실 시 로그인. `verify`가 TOTP 실패 시 백업 코드 소진 검증. 재발급(`POST /admin/2fa/backup-codes`, 현재 TOTP 확인)·해제 시 폐기. 관리자 화면에 코드 표시/남은개수/재발급 UI.
  - **QR 코드**: 외부 의존/네트워크 0 순수 JS QR 인코더(`_utils/qr.ts`, ISO/IEC 18004, byte 모드, RS·마스크·페널티 전 구현) → setup 응답 `qr_svg`(인라인 SVG, CSP 안전). 정확성은 실제 디코더(opencv)로 otpauth URI 왕복 검증. 관리자 화면에서 QR 스캔 또는 수동 키 입력 선택.
  - 참고: Medusa JWT 는 iat 초단위·jti 없음 → 같은 초 로그인은 동일 토큰(동일 세션). 운영에서 per-session jti 도입 시 게이팅 정밀도 향상.
  - 검증: 2FA 게이팅 13/13 + 강화(암호화·백업·QR) 18/18 + QR 디코딩 6/6 + 실브라우저 로그인 흐름 통과. 기본 admin 미활성(E2E 무영향).

- **인기 검색어 실집계**(무비용): 검색 시 `POST /store/popular-search-terms` 로 집계(금칙어 제외, **IP당 1분 30건 rate limit**) → `GET` 로 count DESC 노출(**최소 누적 2회 임계** — 1회성/오타 유입 방지). 스토어 검색 제안이 하드코딩 → 실집계로 전환(집계 없으면 폴백). 관리자 인기검색어 화면과 동일 데이터원.
