# 실서비스 연동 백로그 (외부 계약·비용 발생 항목)

> 작성: 2026-06-30 · 전체 기능 E2E 점검 후속 정리
> 목적: 로컬/데모에서는 동작(mock 또는 접수까지)하지만, **운영(실서비스) 전환 시 외부 서비스 계약·비용·키 발급이 필요한 항목**을 한곳에 정리한다.
> 무비용으로 즉시 구현 가능한 항목(고객센터 공지/FAQ 등)은 이미 반영했으며, 본 문서 마지막 "완료" 절에 요약한다.

---

## 분류 기준
- 🔴 **외부 계약·요금 발생**: 사업자 계약/심사/사용료가 필요 → 의사결정·계약 후 진행
- 🟡 **외부 계정·키 발급(무·저비용)**: 요금은 적거나 없으나 외부 앱 등록/심사 필요
- 🟢 **무비용·내부 개발**: 추가 비용 없음 (가능한 범위는 이미 구현)

---

## A. 실서비스 전환 필수

### A1. 실결제(PG) 연동 — 🔴 최우선
- **현재 상태**: 결제수단이 `pp_system_default`(무통장입금/수기) 1종만 활성. 주문→결제→완료 플로우는 정상이나 실제 카드/간편결제 승인이 일어나지 않음.
- **필요 작업**:
  - PG사 선정·가맹점 계약(예: 토스페이먼츠, KG이니시스, 나이스페이, 카카오페이, 네이버페이).
  - Medusa Payment Provider 모듈 구현(`backend/services/api/src/modules/<pg>-payment`) + `medusa-config.ts` 등록.
  - 스토어프론트 결제 위젯/리다이렉트 연동(`apps/web/src/modules/checkout/components/payment`).
  - 결제 승인/취소/부분취소 웹훅 수신 라우트, 정산(`settlement-payout`) 연동.
- **비용/계약**: 가맹점 심사 + 결제 수수료(건당 %). 사업자등록·정산계좌 필요.
- **코드 연동 포인트**: `checkout/components/payment/index.tsx`, 백엔드 payment 모듈, 주문 워크플로우.

### A2. 소셜 로그인 실연동(카카오/네이버) — 🟡
- **현재 상태**: `socialLoginMock()` 이 provider별 데모 계정(`kakao-demo@`, `naver-demo@`)으로 로그인(없으면 자동가입)하는 mock. 흐름 시연은 가능.
- **필요 작업**:
  - 카카오/네이버 개발자센터에 OAuth 앱 등록 → REST 키/시크릿/redirect URI 발급.
  - 백엔드 `/auth/customer/{provider}` 콜백 + 토큰 교환 + 고객 매핑.
  - `apps/web/src/lib/data/customer.ts`의 `socialLoginMock` → 실제 OAuth 교체.
- **비용/계약**: 앱 등록 무료. 네이버/카카오 비즈니스 검수 필요(서비스 도메인·개인정보 항목 심사).
- **코드 연동 포인트**: `customer.ts:socialLoginMock`, `modules/account/components/social-login`.

### A3. 본인인증(PASS / NICE 휴대폰 인증) — 🔴
- **현재 상태**: 회원가입 시 휴대폰 인증이 클라이언트 mock(`phone-verify`).
- **필요 작업**: 본인확인기관(NICE평가정보, KCB 등) 계약 → 인증 모듈 연동(가입/주문자 실명 확인).
- **비용/계약**: 기관 계약 + 인증 건당 요금. 사업자/이용약관 심사.
- **코드 연동 포인트**: 가입 폼(`modules/account/components/register`), 주문자 정보.

### A4. 알림 발송 채널(이메일/SMS/알림톡) — 🔴(SMS·알림톡) / 🟡(이메일)
- **현재 상태**: 비밀번호 재설정·재입고 알림·주문 알림이 **백엔드 접수·구독까지는 동작**하나, 실제 발송 provider 미설정(Medusa Notification provider 없음).
  - 비밀번호 재설정: `sdk.auth.resetPassword` 호출은 성공하나 메일이 실제로 가지 않음.
  - 재입고 알림: `restock_subscription` 에 구독은 저장되나 재입고 시 발송 트리거/발송 채널 없음.
- **필요 작업**:
  - 이메일: SMTP 또는 SendGrid/SES 등 Notification provider 모듈 + 템플릿. (회사 SMTP 사용 시 무비용 가능 → 🟢로 전환 가능)
  - SMS/카카오 알림톡: 발송 대행(예: NHN Toast, 알리고, 솔라피) 계약 + 발신번호 사전등록 + 템플릿 심사.
  - 재입고 발송 트리거: 입고(재고 0→양수) 이벤트 구독자(subscriber)에서 `restock_subscription` 조회 후 발송.
- **비용/계약**: 이메일 저렴/무료, SMS·알림톡 건당 과금 + 발신번호·템플릿 심사.
- **코드 연동 포인트**: 백엔드 Notification provider, `restock-notification` 모듈 + 신규 subscriber, `password-reset`.

## B. 화면/기능 — 외부 연동 필요분

### B7. 배송 트래킹 실연동 — 🟡
- **현재 상태**: 운송장 번호 표시 + 외부 배송조회 링크(`shipping-tracking`). 모듈 `carrier-adapter` 스캐폴딩 존재.
- **필요 작업**: 택배사 조회 API(스마트택배/굿스플로 등) 연동 → 실시간 배송상태 표시.
- **비용/계약**: 일부 무료 쿼터, 대량은 과금. API 키 발급.
- **코드 연동 포인트**: `modules/order/components/shipping-tracking`, 백엔드 `carrier-adapter`.

### B8. 세금계산서 실발행 — 🔴
- **현재 상태**: 현금영수증/세금계산서 **신청 접수**까지 동작(`tax-invoice` 모듈, 사업자번호 체크섬 검증). 실제 국세청 발행은 미연동.
- **필요 작업**: 발행 대행(팝빌, 바로빌 등) 계약 → 발행/전송/취소 API 연동.
- **비용/계약**: 대행사 계약 + 건당 요금.
- **코드 연동 포인트**: 백엔드 `tax-invoice` 모듈, `/store/orders/:id/tax-receipt`.

### B9. 위시리스트 회원 서버 동기화 — 🟢 (무비용·내부 개발 / 차후)
- **현재 상태**: 쿠키 기반(`lib/data/wishlist`)으로 비회원·회원 모두 동작. 다만 기기 간 동기화/로그인 연동 안 됨.
- **필요 작업**(외부 비용 없음): 백엔드 `/store/customers/me/wishlist` GET/POST/DELETE 신설(`product-curation` 모듈 확장) + 로그인 시 쿠키→서버 머지.
- **우선순위**: 낮음(현재도 사용 가능). 무비용이므로 다음 스프린트에 내부 구현 가능.

## 완료 (이번 점검에서 무비용 구현/검증)

- ✅ **B5. 고객센터 공지/FAQ 관리 (신규 구축)**
  - 백엔드 `cms` 모듈(`notice`/`faq` 테이블) + 마이그레이션.
  - Store API: `GET /store/notices`, `GET /store/faqs`.
  - Admin API: `GET/POST /admin/notices(/:id)`, `GET/POST /admin/faqs(/:id)` (RBAC: settings 메뉴).
  - 어드민 화면: `설정 > 고객센터 콘텐츠`(`/settings/customer-service`) — 공지/FAQ 탭 CRUD.
  - 스토어프론트: `/고객센터`가 정적 mock → **실데이터** 연동(mock 폴백 유지).
  - 초기 시드(공지 3 / FAQ 4) 이관.
- ✅ **B6. 리뷰/문의 어드민 답변·검수** — 기존 구현 동작 검증(검수 게시·답변→answered 정상).
- ✅ 스토어프론트 전체 사용자 여정 + 심층 상호작용(리뷰/문의/적립금/쿠폰/취소·반품/현금영수증/비회원조회/비밀번호재설정/재입고/탈퇴/소셜 mock) E2E 통과.
- ✅ 어드민 전 화면(28) 헬스 스윕 + 상호작용 통과.

> 재현 E2E: `apps/admin/e2e-storefront/{journey,deep,lookup-reset,interactions2,customer-service}.spec.ts`,

## 완료 (2026-06-30 2차 — 자주 쓰는 무비용 기능 보강)

- ✅ **우편번호 검색(다음 Postcode)** — `PostcodeSearch` 컴포넌트(무료·키 불필요). 체크아웃/계정 배송지 추가·수정 폼 연동. 스크립트 차단 시 수기입력 폴백.
- ✅ **메인 배너/팝업** — cms `banner` 모델 + admin `설정>배너·팝업`(`/settings/banners`) + Store `GET /store/banners`. 홈 hero 캐러셀 + 진입 팝업("오늘 하루 보지 않기"). 이미지는 URL 입력.
- ✅ **최근 본 상품** — localStorage 기반, 상품상세 하단 노출(`recently-viewed`).
- ✅ **무료배송 임계 안내** — 장바구니 요약 진행바(`FREE_SHIPPING_THRESHOLD`, 기본 ₩50,000).
- ✅ **신상품 진열** — 홈 `신상품` 섹션(최신순 자동).
- ✅ **홈 큐레이션(MD 추천)** — cms `home_curation` 모델 + admin `설정>홈 큐레이션`(저장 가능; 기존 read-only 갭 해소) + Store `GET /store/curated-products` + 홈 `MD 추천` 섹션.
- ✅ **1:1 문의(상품무관)** — Store `POST /store/support-inquiries`(review 모듈 type=inquiry·product_id=null 재사용) + 고객센터 작성 폼. 어드민 기존 `리뷰·문의` 화면에서 답변.

## 남은 무비용 항목 (🟢 차후 내부 개발)
- **기획전/이벤트 페이지** — 콘텐츠형 랜딩(상품 묶음+배너). collections 와 중첩 소지가 있어 별도 설계 필요.
- **베스트(판매량순) 진열** — 주문/판매 집계 기반 정렬 필요(현재 MD 추천이 "운영자가 미는 상품"을 대체). product-curation 모듈의 조회수 기반 베스트를 store 노출로 연결하면 됨.
- **사진 리뷰(이미지 첨부)** — 이미지 업로드 스토리지 필요(로컬 디스크는 무비용, S3 등은 비용).
- **개인 알림함 / 검색 자동완성·인기검색어** — 화면은 무비용이나, 알림 발송/대량 검색은 외부 연동(위 A4 참고).
- **위시리스트 회원 서버 동기화** — 현재 쿠키 기반 동작. `/store/customers/me/wishlist` 신설 시 기기간 동기화.

> 추가 재현 E2E: `apps/admin/e2e-storefront/{postcode,banners,recent-freeship,home-sections,support}.spec.ts`.
