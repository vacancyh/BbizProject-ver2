## 1. 사전 준비물

| 항목 | 버전/비고 |
|---|---|
| Node.js | 20+ (검증 환경 v24) |
| pnpm | 11.3.x — `corepack enable; corepack prepare pnpm@11.3.0 --activate` |
| Docker Desktop | DB(Postgres)·Redis 구동용 |
| Git | 작성자 정보 설정(`git config user.name/email`) |

> ⚠️ **사내망 TLS 검사(SSL MITM) 환경 주의**: 컨테이너 내부 빌드(`docker compose up --build`)는 `apk`/`pnpm`이 인증서 오류로 실패합니다. **DB·Redis만 Docker로 띄우고, 백엔드·프런트는 호스트에서 직접 실행**하세요(아래 2번). 호스트는 사내 루트 CA를 신뢰하므로 정상 동작합니다.

## 2. 로컬 구동 절차 (검증됨)

```powershell
# (0) 저장소 루트에서 — DB/Redis 컨테이너 (Postgres :5434, Redis :6381)
docker compose -f infra/docker/docker-compose.yml --project-directory . up -d shop-postgres shop-redis

# (1) 백엔드 (Medusa, http://localhost:9000)
cd backend\services\api
pnpm install
npx medusa db:migrate            # 최초 1회 — 스키마 + 기본 시드(상품/리전/퍼블리셔블키)
npx medusa user -e admin@shop.local -p admin1234!   # 관리자 계정(최초 1회)
npx medusa develop

# (2) 관리자 앱 (http://localhost:7002) — 필요 시
cd apps\admin
pnpm install
pnpm dev

# (3) 스토어프론트 (http://localhost:8000)
cd apps\web
pnpm install
pnpm dev
```

| 서비스 | 주소 |
|---|---|
| 스토어프론트 | http://localhost:8000 (리전 경로 예: `/dk`) |
| 관리자 | http://localhost:7002 (`admin@shop.local` / `admin1234!`) |
| 백엔드 API | http://localhost:9000 (`/health`, `/store`, `/admin`) |
| Postgres / Redis | 127.0.0.1:5434 / 127.0.0.1:6381 |

### 테스트 데이터
```powershell
cd backend\services\api
npx medusa exec ./src/scripts/seed-test-data.ts   # 상품·고객·주문·리뷰·적립금 15건씩(재실행 안전)
```

## 3. 환경 변수 (.env — git 제외, 각자 생성)

`.env` 류는 `.gitignore` 처리되어 커밋되지 않습니다. 아래 템플릿으로 각자 로컬에 생성하세요.

### `apps/web/.env.local`
```
NEXT_PUBLIC_MEDUSA_BACKEND_URL=http://localhost:9000
NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY=<DB에서 조회한 pk_... 값>
NEXT_PUBLIC_DEFAULT_REGION=dk
NEXT_PUBLIC_BASE_URL=http://localhost:8000
```
> 퍼블리셔블 키는 DB마다 다릅니다. 조회:
> ```powershell
> "select token from api_key where type='publishable';" | docker exec -i shop-postgres psql -U shop -d shop -t
> ```

### `apps/admin/.env.local`
```
NEXT_PUBLIC_BACKEND_URL=http://localhost:9000
```

> 백엔드(`backend/services/api/.env`)의 시크릿(JWT/COOKIE 등)은 별도 공유 채널로 전달받으세요(문서에 평문 금지).

## 4. 코드 구조 & 규약

### 0) 프런트 표준 스택 (확정)
> 신규 언어/프레임워크 도입 없음 — 기존 코드·Medusa 생태계·SEO·팀 일관성 기준으로 React/Next 유지.

| 구분 | 표준 |
|---|---|
| 언어 | **TypeScript** |
| 프레임워크 | **Next.js 15 (App Router) + React 19** |
| 스타일 | **TailwindCSS + `@medusajs/ui` / `ui-preset`** (공통 디자인 토큰) |
| 데이터 | `@medusajs/js-sdk` + `lib/data` 서버액션 패턴 |
| 렌더링 | 서버컴포넌트 우선 + 필요한 곳만 클라이언트. SEO 위해 SSR/SSG/ISR 활용 |
| 검증/폼 | (선택) zod |
| 테스트 | Playwright(E2E) + Vitest |

### 디렉터리 규약 (도메인 수직 분할)
```
apps/web/src/
  app/[countryCode]/(main)/{store,products/[handle],categories,collections,cart,order/[id],account}
  app/[countryCode]/(checkout)/checkout
  lib/data/*        # 백엔드 호출(서버액션/데이터 페칭) — 도메인별 1파일
  modules/*         # 도메인 UI 컴포넌트(account,cart,checkout,products,...)
  styles/ types/
```
- **신규 도메인**(리뷰·CS·CMS·위시리스트 등)은 `modules/<도메인>` + `lib/data/<도메인>.ts`로 추가.
- 데이터 호출은 **반드시 `lib/data`** 경유(컴포넌트에서 직접 fetch 금지). 백엔드 SDK는 `@medusajs/js-sdk`.
- 공통 UI는 `modules/common` 재사용. 디자인 토큰은 `@medusajs/ui-preset` + Tailwind.

### 계약 우선(contract-first)
1. `lib/data` 함수 시그니처 + `types`를 **인터페이스 PR로 먼저 확정** → 화면 병렬 구현.
2. 백엔드 store API 미구현 기능(리뷰·포인트·본인인증·PG 등)은 **`lib/data`에 mock + 타입 먼저** → 백엔드 준비 시 교체.
3. 관리자→프런트 캐시 무효화는 기존 `revalidate-contract`(백엔드)↔`revalidate-tags`(프런트) 패턴 유지.

### Git / PR
- `main` 직접 작업은 **현 단계(팀 분할 전)** 까지만. 팀 분할 후엔 `feature/<도메인>-<작업>` 브랜치 + PR + 상호리뷰로 전환.
- 커밋: 의도·이유 짧게. PR: 변경범위 / 도메인 / 테스트 방법 / 스크린샷 / 백엔드 의존성.

### 완료 정의(DoD)
화면 구현 + 모바일 우선 반응형 + 로딩/에러/빈상태 + 접근성 기본 + (가능 시) Playwright E2E 1개 + 리뷰 통과.
