# AI_52 — 스토어프론트 화면명세 · 백로그 (자기완결판)

> **이 문서의 목적 (AI 학습용)**
> 이 문서는 **레포지토리에 접근할 수 없는 다른 AI**가 `AI_5x` 문서만 읽고도
> "스토어프론트(고객용 쇼핑몰)에서 **어떤 화면을 만들어야 하는지**, 각 화면이
> **무엇을 하고, 어떤 데이터를 다루고, 지금 상태가 무엇인지**"를 정확히 알 수 있도록
> 작성한 **자기완결(self-contained) 화면 명세서**다. 길어도 괜찮으니 빠짐없이 적는다.
> 이 문서 하나로 화면 단위 작업을 시작할 수 있어야 한다.

- **대상 앱**: `apps/web` (Medusa Next.js Starter 기반 고객용 스토어프론트)
- **백엔드**: Medusa v2 + 한국형 커스텀 모듈. **아래 "mock 선개발"로 표기된 도메인 상당수는 이후 실 store API로 연동 완료**됨(검색·인기검색어·베스트·리뷰·위시·적립금·등급·쿠폰·동의·고객센터·약관 등).
- **작성 기준일 컨텍스트**: M0 공통기반 + M1 첫 표준패턴(리뷰 탭) 완료 시점.
- ⚠️ **갱신(2026-07-02)**: 이 문서는 초기 스냅샷입니다. **현재 화면 상태의 단일 소스는 [07 화면별 백로그](../01_팀원용/07_화면별_백로그.md)**, 백엔드 연동·보안 현황은 [실서비스_연동_백로그](../../../../실서비스_연동_백로그.md) 입니다. 아래 표의 ❌/mock 표기 중 다수는 이미 ✅ 실연동으로 바뀌었습니다(핵심 항목은 본문에 갱신 반영).

## 1. 개요

### 1.1 전제 — 그린필드가 아니다
스토어프론트는 **Medusa Next.js Starter** 기반이라, **기본 구매여정(상품 탐색 → 장바구니 → 체크아웃 → 주문완료 → 계정/주문조회)이 이미 코드로 존재**한다.
따라서 우리 작업은 "처음부터 만들기"가 아니라 **이미 있는 것을 점검하고, 한국형으로 고치고, 없는 것만 새로 추가**하는 일이다. 작업 성격은 3가지로 나뉜다.

### 1.2 범례 (상태/소스) — 표 전체 공통
| 기호 | 의미 |
|---|---|
| ✅ | **있음(검증만)** — 스타터에 이미 구현됨. 동작 확인·소규모 정리만 필요 |
| 🔧 | **있으나 현지화/보강** — 화면은 있지만 한국형으로 고쳐야 함(통화·문구·항목·정책) |
| ❌ | **신규(없음)** — 새로 만들어야 함. 백엔드 store API가 없으면 **mock 계약** 선개발 |
| 🟢 store | 데이터 소스가 **실제 백엔드 store API**(`@medusajs/js-sdk`, `sdk.store.*`) |
| 🔴 mock | 데이터 소스가 **레포 내 결정적(deterministic) mock**(백엔드 미구현 → 타입 계약 후 mock 반환) |

> **mock 표준 패턴**: 신규 도메인은 `lib/data/<도메인>.ts`에 **타입(계약) + 결정적 mock 함수**를 먼저 두고, 그 함수를 호출하는 서버 컴포넌트로 화면을 만든다. 백엔드 store API가 준비되면 **함수 내부 fetch만 교체**하고 화면/타입은 그대로 둔다. (현재 `lib/data/reviews.ts`가 이 패턴의 레퍼런스.)

### 1.3 핵심 사실(Facts) — 이미 결정/완료된 것
| 항목 | 값/상태 |
|---|---|
| 기본 리전 | **kr (한국)** |
| 기본 통화 | **KRW (₩)** |
| 진입 경로 | 루트 접속 시 **`/kr`** 로 리다이렉트 (라우트 구조 `app/[countryCode]/...`) |
| 통화 표기 | `lib/util/money.ts` 기본 locale을 `en-US` → **`ko-KR`** 적용 완료 ✅ |
| 헤더/푸터 | `modules/layout` 한국어화 + 푸터에 **사업자등록번호·통신판매업신고·대표자·주소·개인정보책임자·고객센터**(전자상거래법 필수, 플레이스홀더) 적용 완료 ✅ |
| 홈 | 컬렉션 2종(**베스트/신상품**) + 상품 12 시드로 채움 완료 ✅ (홈은 컬렉션 의존이라 0개면 빈 화면) |
| 상품 리뷰 탭 | `lib/data/reviews.ts`(타입 계약+mock) + `product-reviews` 서버컴포넌트(평균/분포/목록), **mock 표준 템플릿** 적용 완료 ✅ |
| 상품 탭 | 탭 라벨/항목 한국어화(소재/원산지/배송·교환 안내) 적용 완료 ✅ |

## 3. 화면별 명세표 (도메인별 · 빠짐없이)

표 컬럼 의미:
- **화면**: 만들 화면 이름
- **상태**: ✅/🔧/❌ (§1.2)
- **무엇을 하나**: 사용자가 이 화면에서 하는 일
- **핵심 데이터/엔티티**: 다루는 주요 데이터(백엔드 도메인 개념)
- **소스**: 🟢 store(실데이터) / 🔴 mock
- **lib/data**: 데이터 접근 모듈(있으면 파일명, 없으면 신규 생성)
- **비고/수용기준**: 한국형 보강 포인트, 완료 판정 기준

## 4. 관리자 도메인 ↔ 프런트 대응 (도메인 맥락)

> 프런트 개발자는 **관리자 앱을 만들지 않는다.** 관리자(운영자)가 입력/처리한 데이터를 고객용 몰이 "보여주는" 쪽이다. 운영자 기능을 알면 프런트가 다룰 데이터·흐름이 보인다. (관리자 앱: 4개 그룹 27개 화면)

| 관리자 화면(운영자가 하는 일) | → 프런트(고객) 대응 화면 | 다루는 데이터 |
|---|---|---|
| **주문 관리** (출고·송장·배송완료·환불·강제취소) | 마이 **주문내역/주문상세**, **주문상태 배지**, 취소/반품·교환 신청 | order, payment-status, fulfillment-status |
| **상품 관리** (등록·옵션·가격·이미지·고시 입력) | **상품 목록/상세**, 옵션 선택, **상품정보고시 탭** | product, variant, pricing, disclosure |
| **상품 통계·큐레이션** (조회/판매/위시/인기검색어) | 홈 **베스트/인기 상품**, **인기검색어** | curation |
| **타임세일** (기간·재고 한정 특가) | **타임세일 노출**, 남은 시간/수량 | time-sale |
| **상품 분류 체계** (분야→분류, 분류별 고시 필수항목) | 상품상세 **상품정보고시 탭(분류별 필수항목)** | catalog-types, disclosure |
| **카테고리** (트리·컬렉션·기획전·태그) | **카탈로그 내비**, 기획전 페이지, 태그 필터 | category, collection |
| **회원 관리** (회원/그룹·주소·이력, PII 마스킹) | **로그인/마이페이지**, 등급, 배송지 | customer, membership, address |
| **배송 관리 / 배송정책** (출고지·구역·배송비·택배사) | **배송 방법/예상 배송비** 표시, 배송 안내 | shipping-option, service-zone |
| **창고 관리** (위치별 재고) | 상품상세 **가용수량/품절(SOLD OUT)** 표시, 담기 제한 | inventory(manage_inventory·예약) |
| **쿠폰·프로모션** (쿠폰/캠페인 생성) | **체크아웃 쿠폰코드 입력**, **마이 쿠폰함** | promotion, coupon |
| **마케팅** (이메일·SMS·알림톡, CMS 공지/FAQ/배너/팝업) | **배너·팝업·공지/FAQ** 노출, 수신 동의 | CMS, consent |
| **리뷰·문의** (리뷰·1:1/Q&A 확인·답변) | 상품 **리뷰 탭**, CS **1:1문의/상품 Q&A** | review, inquiry |
| **반품·환불 사유** (사유 코드 관리) | 반품·교환 신청 시 **사유 선택 목록** | return-reason |
| **약관 관리** (이용약관·개인정보 버전) | **약관 페이지**, 가입 시 **동의 항목** | legal-doc |
| **점검 모드** (몰 ON/OFF) | 점검 중 **점검 안내 페이지** | ops(maintenance) |
| **API 연동키** (publishable 키 발급) | 프런트가 store API 호출 시 쓰는 **publishable 키**(환경설정) | - |
| **판매채널** (단독몰=1, 채널-상품 연결) | 몰에 **노출되는 상품** 결정 | sales-channel |
| 정산/통계·리포트/워크플로우 로그/권한·정책·감사로그 | (운영용, 직접 대응 없음 — 정책 값은 안내 문구에 간접 반영) | - |

### 4.1 알아둘 운영 개념(상태 표시용)
- **결제 상태**: 결제대기/결제완료/취소/부분환불 → 주문상세 **결제 상태 배지**
- **배송 상태**: 배송준비→배송중→배송완료 → 주문상세 **배송 단계/송장번호**
- **주문 상태**: 접수·처리중·완료·취소 → 주문내역 **상태 라벨**
- **재고/품절**: 변형별 재고 추적·예약·0이면 품절 → 상세 **품절(SOLD OUT)**·담기 제한
- **회원 vs 게스트**: 로그인 여부로 마이/주문조회 분기
- **등급·적립금·제재·동의**: 마이 **등급·적립금 표시**, 가입/주문 시 **동의 체크**
