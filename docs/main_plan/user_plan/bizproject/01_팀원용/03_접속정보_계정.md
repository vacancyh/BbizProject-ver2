프런트 개발 시 자주 쓰는 **주소·계정·키·DB 접속 정보** 빠른 참조.
구동 절차는 [02_개발환경_구축.md](./02_개발환경_구축.md) 참조.

> ⚠️ **여기 정보는 전부 "로컬 개발 전용"** 입니다. 운영(실서비스) 비밀번호/시크릿이 아니며, 운영에 그대로 쓰면 안 됩니다.

## 2. 계정 (관리자 · 프런트 고객)

### 2-1. 관리자(백오피스) — http://localhost:7002

| 이메일 | 비밀번호 | 역할 | 용도 |
|---|---|---|---|
| `admin@shop.local` | `admin1234!` | **super** | 주 관리자(전체 권한) · **로그인폼 기본값·E2E 기본 계정** |
| `ops@shop.local` | `ops1234!` | operation | 권한(RBAC) 테스트용 |
| `mkt@shop.local` | `mkt1234!` | marketer | 권한(RBAC) 테스트용 |

> 🔐 **로그인 자동입력 방식 변경(2026-07-28)**: 예전에는 관리자 계정/비밀번호가 로그인 페이지 코드에 **하드코딩**되어 있어
> 운영 빌드 시 브라우저 번들로 노출될 수 있었습니다. 지금은 **개발 환경 + 환경변수 주입** 시에만 자동입력됩니다.
> - 로컬 자동입력: `apps/admin/.env.local` 에 `NEXT_PUBLIC_DEV_ADMIN_EMAIL` / `NEXT_PUBLIC_DEV_ADMIN_PASSWORD`
> - E2E 계정 지정: `E2E_ADMIN_EMAIL` / `E2E_ADMIN_PASSWORD` (미지정 시 `admin@shop.local` / `admin1234!`)
> - 운영 빌드에서는 해당 분기가 제거되어 **번들에 값이 남지 않습니다.**

- 로그인: 관리자(:7002) 또는 API `POST /admin/auth/user/emailpass` (백엔드 :9000 → `POST /auth/user/emailpass`).
- 권한 체계: write는 등급별 제한, read는 보안메뉴(권한·정책·감사로그)만 super 전용. (역할 미할당=super처럼 동작하나 **점검모드 등 일부는 명시 super 필요** → admin 계정에 super 부여 완료)
- **2단계 인증(2FA)**: 관리자 `설정 > 2단계 인증`(`/settings/security`)에서 계정별 옵트인. 활성화 시 로그인이 비밀번호 → OTP 6자리 2단계로 바뀌고, 서버측 게이팅으로 미인증 토큰의 `/admin/*` 접근이 차단됨. **위 데모 계정은 기본 미활성**(E2E/데모 무영향). 활성화 후 인증기 분실 시 발급받은 **백업 코드**로 로그인.

### 2-2. 프런트(스토어프론트) — http://localhost:8000/kr

고객(쇼핑몰) 화면 접속·로그인 정보. 로그인은 화면 우상단 **내 계정**(`/kr/account`) 또는 API `POST /auth/customer/emailpass`.

**⭐ 등급별 데모 계정** (비밀번호 공통 `test1234!`) — 마이페이지(주문·적립금·등급·배송지) 데이터가 채워져 있어 화면 테스트에 바로 사용:

| 이메일 | 비번 | 등급 | 데이터(대략) |
|---|---|---|---|
| `test@kr-demo.local` | `test1234!` | 일반 | 주문 2 · 적립금 ~1,400 · 배송지 2 |
| `silver@kr-demo.local` | `test1234!` | 실버 | 주문 2 · 적립금 ~3,800 · 누적 ~57만 · 배송지 1 |
| `gold@kr-demo.local` | `test1234!` | 골드 | 주문 3 · 적립금 ~11,600 · 누적 ~153만 · 배송지 2 |
| `vip@kr-demo.local` | `test1234!` | VIP | 주문 3 · 적립금 ~24,000 · 누적 ~388만 · 배송지 1 |

> 등급 기준(정책 기본값): 일반 0 / 실버 30만 / 골드 100만 / VIP 300만 원(누적 구매액). 적립금·누적액은 주문 시 자동 적립되어 값이 점차 증가합니다.
> 🤖 팀원이 **동일 데모 데이터를 자기 로컬에 재현**하려면 → [AI_54. 데모 데이터 시드 프롬프트](../02_AI용/AI_54_데모데이터_시드_프롬프트.md)(AI에 복사·전달).

**기타 로그인 가능 계정**:

| 이메일 | 비밀번호 | 용도 |
|---|---|---|
| `qa-points@kr-demo.local` | `qa1234!` | 적립금/등급/주문 데이터 보유(기존 검증용) |
| `kakao-demo@kr-demo.local` | `kakaodemo1234!` | 소셜로그인(카카오) mock 데모 계정 |
| `member01~06@kr-demo.local` | (없음) | 비밀번호 미설정 → **로그인 불가**(관리자/주문 데이터용). 로그인 테스트는 신규 가입 권장 |

- **신규 가입 테스트 권장**: `/kr/account` → 회원가입(이메일/비번 직접 지정)으로 깨끗한 세션 생성.
- ℹ️ 위 등급별 데모 계정(test/silver/gold/vip)은 **수동 시드** 데이터입니다 → **DB 재시드 시 사라짐**. 재생성: `/kr/account` 회원가입(동일 이메일·`test1234!`) 후 `customer_membership`·`point_ledger` 시드를 다시 넣거나, 주문을 새로 생성하면 됩니다.
- **비회원 주문조회**: 로그인 없이 `/kr/order/lookup` (주문번호 `display_id` + 주문 이메일).
- 주요 화면 경로: 홈 `/kr` · 상품목록 `/kr/store` · 장바구니 `/kr/cart` · 마이페이지 `/kr/account` · 고객센터 `/kr/customer-service` · 위시리스트 `/kr/wishlist` · 비밀번호 재설정 `/kr/reset-password`.
- `/store` API 직접 호출 시 **`x-publishable-api-key` 헤더 필수**(아래 4번).

## 3. 데이터베이스 접속 (Postgres)

| 항목 | 값 |
|---|---|
| Host / Port | `127.0.0.1` / `5434` |
| DB / User / Password | `shop` / `shop` / `shop_local_2026` |

```powershell
# psql 접속(컨테이너)
docker exec -it shop-postgres psql -U shop -d shop
# 한 줄 쿼리
"select count(*) from product;" | docker exec -i shop-postgres psql -U shop -d shop -t
```

---

## 4. 퍼블리셔블 키 (스토어프론트 필수)

스토어프론트 `/store` 요청에 **`x-publishable-api-key` 헤더 필수**. 키는 **DB마다 다름** → 조회해서 사용:
```powershell
"select token from api_key where type='publishable';" | docker exec -i shop-postgres psql -U shop -d shop -t
```
- 현재 로컬 값(예시, 환경마다 다름): `pk_b6ad2b93e9dc8259b154ca021d051acf2d13d74eec95ce598dfc7d36276083aa`
- 여러 개면 **Default Sales Channel에 연결된 키** 사용. `apps/web/.env.local`의 `NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY`에 설정.

## 5. 리전 / 통화

- 기본: **한국(KRW)**, country `kr` → 스토어프론트 경로 `/kr`, `NEXT_PUBLIC_DEFAULT_REGION=kr`.
- 해외(EUR, Europe) 리전도 보존(테스트용). 가격은 항상 `currency_code` 기반 표기(하드코딩 금지).

## 6. env 파일 (템플릿 복사 — git 제외)

`apps/admin/.env.local`
```
NEXT_PUBLIC_BACKEND_URL=http://localhost:9000
```

## 8. 보안 주의
- 위 계정/비번/DB정보는 **로컬 개발 전용**. 운영 배포 시 전부 강력한 값으로 교체.
- 백엔드 `.env`의 JWT/COOKIE/REVALIDATE 시크릿은 **커밋·문서 금지**(별도 공유).
- `apps/admin/e2e/.auth/state.json`(E2E 세션 토큰)·테스트 산출물은 커밋하지 않음.
