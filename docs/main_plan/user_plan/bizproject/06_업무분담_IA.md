## 4. 분담 추천안 (대메뉴 기준)

> 7개 대메뉴를 4인이 분배. 라우트+`lib/data`+`modules`를 대메뉴 단위로 통째 소유 → 충돌 최소화.

| 담당 | 소유 대메뉴 | 성격 | 비고 |
|---|---|---|---|
| **A · 카탈로그** | ① 홈, ② 상품 | 트래픽 핵심·분량 큼 | curation/타임세일 백엔드 보강 협의 |
| **B · 구매/결제** | ③ 장바구니·주문·결제 | 단일 대메뉴지만 최대 난이도 | **PG 의존 큼** → 백엔드 협업 필수 |
| **C · 회원/마이** | ④ 마이페이지, ⑤ 회원/인증 | store API 신설 多 | 본인인증·소셜 의존 |
| **D · 공통/CS** | ⑥ 고객센터, ⑦ 공통/시스템 | 공통 게이트키퍼 | 디자인시스템·SEO·KRW 담당 |

### 부하 조정 옵션 (택1)
- **옵션 A(추천)**: 위 표. B가 결제 단독이라 무거우면 ④ 일부(취소/반품)를 B로 이관.
- **옵션 B(균형)**: ③ 결제를 B·C 분할(B=카트/체크아웃, C=결제수단/주문연계).
- **옵션 C(2인 페어)**: (A+B)=구매여정 / (C+D)=회원·CS·공통.

## 6. 공통 결정사항

1. **공통(⑦) 오너** — 디자인시스템/헤더/푸터/SEO 단일 책임(추천 D). 변경은 소형 PR + 사전공지.
2. **백엔드 의존 처리** — ③(PG)·⑤(본인인증/소셜)·④⑥(store API)는 미구현. 택1: (a) 1명 풀스택 겸임, (b) mock 계약 선개발 후 로드맵(Phase1 결제/Phase2 회원) 연동.
3. **KRW 전환** — 한국 리전/통화 시드를 M0에 포함할지(현재 eur).
4. **디자인 기준** — Figma/프로토타입 단일화 + 공통 토큰 확정.
5. **계약 우선** — `lib/data` 시그니처+타입 인터페이스 PR 담당·시점.
