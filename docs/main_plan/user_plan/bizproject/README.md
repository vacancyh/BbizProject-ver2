## ⚡ 30초 요약

- **무엇인가** — 한국형 쇼핑몰 풀스택. 백엔드(Medusa `:9000`) + 고객몰(`:8000`) + 관리자앱(`:7002`)
- **기반** — TypeScript · Next.js 15(App Router) · React 19 · Tailwind / Medusa v2 · PostgreSQL · Redis
- **국내 대응** — 통화·리전·세금·배송·가격 전부 **한국/KRW** (기본 진입 `/kr`)
- **개발 방식** — **AI 보조 개발**. `계약(타입) → mock → 화면 → 실 API 교체` 루프

## ✅ 지금 열어도 되는지 확인하는 법

문서를 일일이 대조하지 말고 **명령 두 개**로 확인하세요.

```bash
# ① 데이터·설정 점검 — 약관·시크릿·상품·재고·결제·권한
cd backend/services/api
npx medusa exec ./src/scripts/preflight-check.ts

# ② 고객 화면 점검 — 손님 눈에 무엇이 보이는지
cd docs/main_plan/user_plan/bizproject/04_점검기록/보안점검
STOREFRONT=http://localhost:8000 node storefront-readiness-probe.mjs
```

🔴 **BLOCK 이 0 건이어야 오픈합니다.** ①은 데이터를, ②는 실제 렌더링된 화면을 봅니다.
둘 다 필요합니다 — 예전에 이용약관 자리에 QA 테스트 문구가 떠 있는 걸 아무도 몰랐던 적이 있습니다.

## 🧷 작업할 때 지켜야 할 것

- 코드 변경 후 **최소한 타입체크 + 관련 테스트**를 돌립니다. CI 에서도 막힙니다.
- 새 `TODO` 는 분류 접두를 답니다: `TODO(사장님결정)` / `TODO(후속 사이클)` / `TODO(리팩터)`.
- **재고는 반드시 Admin API 로 조작**합니다. DB 직접 UPDATE 는 재고 캐시가 갱신되지 않아
  장바구니가 계속 실패합니다.
- dev 서버를 켠 채 `pnpm build` 하지 않습니다(`.next` 를 덮어써 dev 가 500).
- 자격증명은 코드에 넣지 않고 `.env.local` / 환경변수로 주입합니다.
