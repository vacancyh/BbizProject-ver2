# bizproject — 스토어프론트 프런트 개발 (팀 문서 허브)

스토어프론트(`apps/web`) 개발을 위한 **팀 문서 모음**입니다. 프런트 개발에 합류하면 **이 문서부터** 읽으세요.

---

## 0. 30초 요약 (꼭 알 것)

- **무엇을 만드나**: 고객용 스토어프론트(`apps/web`, Next.js). 관리자(`apps/admin`)·백엔드(Medusa)는 이미 있음.
- **기반**: TypeScript + **Next.js 15(App Router) + React 19** + Tailwind + `@medusajs/js-sdk`. (신규 프레임워크 도입 X)
- **데이터**: 백엔드 Medusa(:9000)의 **`/store` API만** 호출. 모든 호출은 `lib/data/*` 경유. 요청에 **퍼블리셔블 키 헤더 필수**.
- **국내 기반**: 통화·리전·세금·배송·상품가가 **한국/KRW로 설정 완료**, KRW 판매(주문) E2E 통과. 기본 리전 `kr`.
- **관리자/백엔드 상태**: 검색·필터·정렬·권한·핵심 연계까지 QA·수정·검증 완료(신뢰 가능). 일부 기능은 백엔드 store API 미구현 → mock 계약으로 선개발.

## 2. 분담 큰 그림 (상세는 ②)

7개 대메뉴를 4인이 나눠 소유(라우트+`lib/data`+`modules` 디렉터리 단위 → 충돌 최소화):

| 담당 | 소유 대메뉴 |
|---|---|
| **A 카탈로그** | ① 홈 · ② 상품(상세·고시·타임세일·리뷰탭·위시) |
| **B 구매/결제** | ③ 장바구니·주문·결제(무통장/간편/PG) |
| **C 회원/마이** | ④ 마이페이지(적립금·등급·쿠폰·위시·동의) · ⑤ 회원/인증(본인인증·소셜) |
| **D 공통/CS** | ⑥ 고객센터(공지·FAQ·문의·리뷰) · ⑦ 공통/시스템(디자인시스템·헤더/푸터·SEO·KRW) |

> 회의에서 ②의 §5 분담 확정표를 채운 뒤 `CODEOWNERS`로 반영.

## 4. 백엔드 의존 — 기능별 상태 (계약 우선 개발)

| 프런트 기능 | 백엔드 store API | 진행 방식 |
|---|---|---|
| 상품·카테고리·컬렉션·검색·장바구니·주문조회 | ✅ 있음 | 바로 연동 |
| 상품정보고시 표시 | ✅ 데이터 있음 | 연동 |
| 결제(무통장/간편/PG) | ❌ 미구현 | **mock 계약 선개발** → 백엔드 합류 시 교체 |
| 본인인증·소셜로그인 | ❌ 미구현 | mock/목업 후 연동 |
| 리뷰·포인트·쿠폰·위시(고객) | ⚠️ 관리자 API만 | store 라우트 신설 필요 → 그 전엔 mock |

> 규칙: `lib/data` 함수 시그니처+타입을 **인터페이스 PR로 먼저 확정**하고 화면을 병렬 구현. 미구현 API는 mock으로 막히지 않게.
