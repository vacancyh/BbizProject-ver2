## 2. 연계(Linkage) 검증 결과 — 전부 PASS

### 주문 생명주기 11/11
주문 생성 → **재고 예약** → 결제 캡처 → 출고 → **재고 차감(예약 해제)** → 송장(배송중) → 배송완료 → 부분환불(payment_status·refunded_total) → 취소 → **재고 복구** → 모든 write **감사로그 자동 기록**.

### 회원·정책·큐레이션 14/14
포인트 적립/사용, 멤버십 누적→**등급 재산정**, 제재 단계상승→**로그인 차단**/해제, 동의 철회/동의+이력, 정책 **이중확인(409)**·변경·이력, 큐레이션 조회수/금칙어/금칙어-검색어 제외.

### RBAC 권한
- **write**: operation/marketer 등 등급별 매트릭스대로 정확히 강제(미허용 메뉴 write → 403). 교차 검증 완료.
- **read**: 보안 메뉴(권한·정책·감사로그)는 super만 조회(403 차단), 그 외 메뉴는 전원 조회 허용.
- super(또는 역할 미할당)는 전체 허용(부트스트랩 안전장치). 마지막 super 강등 차단 가드 존재.

### 검색 정밀(1~3글자+)
상품·카테고리·고객그룹·주문(이메일/이름/번호) 검색은 1~3자·영문·부분 모두 정상. 회원은 성/이름/풀네임/이메일/전화 정상.

## 5. 국내(한국/KRW) 전환 + 최종 판매가능 검증 (추가)

해외(EUR/USD) 기반을 **국내 기반(KRW)** 으로 전환(additive — 기존 EUR 흐름 보존). 재현 스크립트: `backend/services/api/src/scripts/setup-korea.ts`.
- store KRW 통화(+기본), **한국 region(KRW/kr)**, **KR 세금리전(부가세 10%)**, **전 상품 변형 KRW 가격(65개)**, **국내 배송옵션(3,000 KRW)** 추가.
- 스토어프론트 기본 리전 `kr` 로 변경(`apps/web/.env.local`).

**판매가능 E2E (KRW) 6/6 PASS**: 한국 리전 카트 → 국내배송 → 결제 → 주문(통화 krw, 금액·세금 계산) → 관리자 조회. EUR 회귀(기존 흐름)도 정상.

**최종 종합 정밀 검증 전 항목 PASS**: 목록 16종 200 / 국내설정 5종 / 검색 1~3자·풀네임 / 정렬(금액·이름) / RBAC write·read 강제(보안메뉴 super 전용).

> ⚠️ 참고: Medusa 데모 상품(예: T-Shirt)의 KRW 가격은 기존 EUR 금액을 그대로 복사(예: 10원)해 비현실적입니다. 실제 운영가는 상품별로 재설정 필요(kr-test 상품은 19,000~ 정상). 결제 흐름·통화 처리는 정상.

## 6-1. 브라우저 E2E + 쓰기흐름 최종 점검 (2026-06-22 추가)

**브라우저 레벨 E2E(Playwright)** — 관리자앱 실제 렌더/클릭 검증:
- 통과: 대시보드(위젯→도메인 진입·정산 KPI), 설정 전반(판매채널·API키 발급+감사·워크플로우로그·반품사유·정책변경+이력·약관게시·권한관리·write→감사), 주문 목록→상세 진입(엔드포인트 변경 반영 후).
- 주문 일부 스펙(qa_002 QA-002~006)은 **포트 7001(도커)·하드코딩 주문ID** 로 작성된 **옛 환경 기준 테스트** — 네이티브(:9000)에서 ECONNREFUSED. 제품 버그 아님, 추후 네이티브 기준으로 재작성 필요.

**쓰기/액션 흐름(API)** — 전부 정상:
- 정산 상태머신 open→closed→paid, 타임세일 생성, 카테고리·고객그룹 생성, 점검모드 ON/OFF.

**발견·조치 — 점검모드 권한**: `/admin/ops/maintenance` 토글은 **명시적 'super' 역할 전용**. 기본 admin 계정은 역할 미할당(RBAC상 super처럼 동작하나 이 라우트는 명시 super 요구)이라 403. → **admin 계정에 super 역할 부여**로 해결(권장 설정). 신규 환경도 동일 부여 필요.

## 6. 결론
관리자 화면 기능은 **검색·탭·필터·정렬·권한·핵심 연계 + 국내(KRW) 판매가능까지 점검·수정·검증 완료**되어, 프런트 팀이 관리자 데이터/동작을 신뢰하고 스토어프론트 개발을 진행할 수 있는 상태입니다. 남은 항목(3장)은 모두 "백엔드 신규 작업" 범주로 분리되어 프런트 진행을 막지 않습니다.
