# 오픈 전 비용 발생 항목 체크리스트

> 작성: 2026-08-03
> 용도: **서버 올리기 직전** 이 문서 하나만 보고 계약·결제가 끝났는지 확인한다.
> 여기 있는 항목은 전부 **돈이 들어서** 개발로 해결할 수 없다.

---

## 0. 30초 요약

| 우선순위 | 항목 | 없으면 |
|---|---|---|
| 🔴 **1순위** | 결제 PG | **주문 자체가 불가능하다** |
| 🔴 **1순위** | 서버·DB 인프라 | 서비스가 뜨지 않는다 |
| 🔴 **1순위** | 도메인 + SSL 인증서 | 접속 불가 / 브라우저 경고 |
| 🟠 **2순위** | 택배사 API | 운송장을 전부 수기 입력 |
| 🟠 **2순위** | SMS·알림톡 | 주문·배송 알림이 안 나가 CS 폭증 |
| 🟡 3순위 | 모니터링 | 사이트가 죽어도 모른다 (**무료 티어 가능**) |
| ⚪ 선택 | 세금계산서 자동발행 / 본인인증 / 소셜로그인 | 수기 처리 또는 기능 미제공 |

**🔴 3개가 없으면 오픈 자체가 불가능하다.** 나머지는 열고 나서 붙여도 되지만,
🟠 2개는 없으면 운영이 매우 고통스러워진다.

## 1. 🔴 결제 PG — 가장 먼저

현재 상태: **수동/시스템 provider 만 등록돼 있다**(`pp_system_default`).
즉 결제창이 뜨지 않고 실제 돈이 오가지 않는다. 테스트용 상태다.

### 확인할 것

- [ ] PG사 선택 및 계약 (토스페이먼츠 · 포트원 · KG이니시스 · NHN KCP 등)
- [ ] **전자결제 심사 통과** — 사업자등록증·통신판매업 신고증이 필요하고 심사에 며칠~2주 걸린다.
      **오픈 일정에서 가장 자주 병목이 되는 항목이다. 가장 먼저 시작할 것.**
- [ ] 정산 주기·수수료율 확인 (일반적으로 결제금액의 2~3%대, 계약별로 다름)
- [ ] 테스트(샌드박스) 키로 결제·취소·부분취소 검증
- [ ] 운영 키로 교체 후 **소액 실결제 1건 + 실환불 1건** 반드시 테스트

### 개발 측 준비 상태

결제 연동 지점은 Medusa 표준 payment provider 방식이라 **PG 어댑터만 붙이면 된다.**
환불·부분환불·취소 흐름은 이미 구현·검증돼 있다.

> ⚠️ **PG 연동 후 반드시 재검증할 것**: 환불 동시 요청 방어는 현재 수동 provider 기준으로만
> 검증했다. 실제 PG 는 응답 지연·타임아웃 양상이 달라 다시 확인해야 한다.
> 검증 도구: `docs/.../보안점검/audit3-concurrency-probe.mjs`

## 2. 🔴 서버 · DB 인프라

현재 상태: 로컬 개발 환경(Docker Postgres + Redis)에서만 동작.

### 최소 구성

| 구성요소 | 용도 | 없으면 |
|---|---|---|
| 애플리케이션 서버 | 백엔드 + 스토어프론트 + 어드민 | — |
| **PostgreSQL** | 주문·회원·상품 데이터 | 서비스 불가 |
| **Redis** | 캐시 · 세션 · **분산 락** | 아래 경고 참조 |
| 오브젝트 스토리지 | 상품 이미지, **백업 사본** | 서버와 함께 데이터가 사라진다 |

> 🔴 **Redis 는 선택이 아니다.**
> `REDIS_URL`(또는 `LOCKING_REDIS_URL`)이 없으면 분산 락이 메모리 방식으로 떨어진다.
> 그 상태에서 서버를 2대 이상 띄우면 **적립금 이중 사용·환불 이중 집행이 실제로 발생한다**
> (2026-08-03 실측으로 확인된 결함이며, 락으로 막아 둔 상태다).

### 확인할 것

- [ ] 서버 사양 결정 (초기에는 소규모로 시작해 트래픽 보고 증설)
- [ ] PostgreSQL **자동 백업** 활성화 (관리형 DB 를 쓰면 대부분 기본 제공)
- [ ] Redis 인스턴스 준비
- [ ] 백업 파일을 **서버 밖 저장소**에도 보관 (서버가 통째로 죽는 경우 대비)
- [ ] 배포 후 `preflight-check.ts` 실행해 BLOCK 0 건 확인

## 3. 🔴 도메인 + SSL

- [ ] 도메인 구매
- [ ] DNS 연결
- [ ] SSL 인증서 (Let's Encrypt 는 무료. 관리형 로드밸런서를 쓰면 대부분 자동)
- [ ] **`COOKIE_SECURE=true` 설정** — HTTPS 인데 이 값이 없으면 세션 쿠키가 평문으로 오간다

## 4. 🟠 택배사 API

현재 상태: 스텁(가짜) 어댑터. 운송장 번호와 배송추적 URL 이 가짜 값이다.

### 없으면 어떻게 되나

- 운송장 번호를 **주문마다 손으로 입력**해야 한다
- 고객에게 배송추적 링크가 나가지 않는다 → "제 물건 어디 있나요" 문의가 늘어난다
- 대량 발송일수록 부담이 커진다

### 확인할 것

- [ ] 택배사 계약 (CJ대한통운 · 롯데 · 한진 · 우체국 등)
- [ ] API 키 발급
- [ ] 계약 단가 확인 (물량에 따라 협상 여지가 크다)

## 5. 🟠 SMS · 알림톡

현재 상태: 미연동. **주문·배송 알림이 고객에게 나가지 않는다.**

### 없으면 어떻게 되나

주문했는데 아무 연락이 없으면 고객은 불안해하고 곧바로 문의한다.
**CS 부담이 가장 크게 늘어나는 항목이다.**

### 확인할 것

- [ ] 발송 대행사 선택 (알리고 · 솔라피 · NHN Toast 등)
- [ ] **카카오 알림톡** 사용 시: 발신프로필 등록 + 템플릿 사전 심사 (심사에 며칠 걸린다)
- [ ] 건당 단가 확인 (SMS 10~20원, 알림톡이 더 저렴한 편)
- [ ] 최소 다음 시점의 알림은 준비: 주문완료 · 발송 · 배송완료 · 취소/환불

## 6. 🟡 모니터링 — 무료로 시작 가능

현재 상태: **미연동. 사이트가 죽어도 아무도 모른다.**

새벽에 서버가 내려가면 아침에 고객 전화를 받고서야 알게 된다.
**무료 티어만으로도 충분히 시작할 수 있으니 반드시 붙일 것.**

### 확인할 것

- [ ] **가동 감시** — UptimeRobot 등 (무료 티어로 5분 간격 감시 가능)
      감시 대상: `https://api도메인/hc` 와 `https://쇼핑몰도메인/api/health`
      (2026-08-03 신설 · 인증 불필요 · 장애 시 503. 기존 `/health` 는 DB 가 죽어도 OK 를 반환하므로 쓰지 말 것)
- [ ] **오류 추적** — Sentry (무료 티어 있음). 환경변수 `NEXT_PUBLIC_SENTRY_DSN` 자리는 이미 있다
- [ ] 알림 받을 담당자 연락처 등록 (이것을 빼먹으면 감시의 의미가 없다)

## 7. ⚪ 선택 항목

| 항목 | 비용 | 없으면 | 판단 기준 |
|---|---|---|---|
| 세금계산서 자동발행 (팝빌 등) | 건당 소액 | 수기 발행 | B2B 주문이 많으면 도입 |
| 본인인증 (PASS/NICE) | 건당 과금 | 만 14세 미만 가입을 막을 수 없다 | 연령 제한 상품을 팔면 **필수** |
| 소셜로그인 (카카오·네이버) | 무료 (심사 필요) | 가입 단계 이탈이 늘어난다 | 전환율 개선 목적 |
| 이미지 CDN | 트래픽 종량 | 이미지가 느리게 뜬다 | 상품 수가 많아지면 검토 |

## 8. 오픈 직전 최종 체크

돈 문제가 아닌 것들은 대부분 준비돼 있다. 아래 명령으로 한 번에 확인한다.

```bash
cd backend/services/api
npx medusa exec ./src/scripts/preflight-check.ts
```

**🔴 BLOCK 이 0 건이어야 오픈한다.** 현재(2026-08-03) 남아 있는 BLOCK 은 다음과 같다.

| BLOCK 항목 | 성격 |
|---|---|
| 실 PG 미연동 | 이 문서 §1 (비용) |
| 이용약관·개인정보처리방침의 자리표시자 | 사장님이 실제 본문 작성 |
| `REVALIDATE_SECRET` 개발용 기본값 | 무작위 값으로 교체 |
| 테스트 상품 15건 잔존 | 실제 상품으로 교체 |
| 데모 관리자 계정 3건 | 실제 계정 생성 후 삭제 |

마지막 4개는 **돈이 들지 않는다.** 시간만 있으면 해결된다.

## 9. 권장 진행 순서

병목이 긴 것부터 시작해야 오픈 일정이 밀리지 않는다.

```
1주차  PG 심사 신청 ────────────────────────┐ (가장 오래 걸림, 최우선)
       알림톡 템플릿 심사 신청 ─────────────┤
       사업자 정보 준비 / 통신판매업 신고 ──┘
2주차  서버·DB·도메인 준비 + SSL
       약관·개인정보처리방침 작성 (법무 검토)
3주차  PG 샌드박스 연동 → 실결제·실환불 테스트
       택배사 계약 및 API 연동
4주차  실제 상품 등록, 데모 데이터 정리
       모니터링 연결, 백업 자동화 확인
       preflight-check 로 BLOCK 0 확인 → 오픈
```
