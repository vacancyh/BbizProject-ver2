## 1단계 — 로테이션 (먼저, 즉시)
노출된 값을 "이미 유출됐다"고 가정하고 **먼저 교체**합니다. (이력 스크럽 전에 해도 무방)
- **admin 비밀번호**: 관리자 화면 또는 CLI 로 변경
  ```bash
  cd backend/services/api
  npx medusa user -e admin@shop.local -p "<새 강력 비밀번호>"   # 또는 관리자 화면에서 변경
  ```
- **운영 JWT/COOKIE 시크릿**: 환경별 신규 생성 후 시크릿매니저/`.env`(비커밋)에 주입
  ```bash
  openssl rand -base64 48   # JWT_SECRET
  openssl rand -base64 48   # COOKIE_SECRET
  openssl rand -base64 32   # REVALIDATE_SECRET · ADMIN_2FA_SECRET_KEY
  ```
- **Postgres 비밀번호**: 운영 DB 는 반드시 신규 값. 로컬 도커는 재사용해도 되나 운영과 분리.

## 2단계 — git 이력 스크럽 (협업자 조율 후)
> 히스토리 재작성 = 강제 푸시. **모든 협업자가 이후 재클론/rebase 필요** → 사전 공지 필수.

**권장: git-filter-repo** (BFG 대안)
```bash
pip install git-filter-repo   # 또는 brew install git-filter-repo

# 백업(중요)
git clone --mirror https://github.com/vacancyh/BbizProject-ver2.git backup-mirror

# 대상 파일 전체 이력 제거
git filter-repo --path apps/admin/e2e/.auth/state.json --invert-paths

# 특정 문자열(비밀번호/시크릿) 이력 치환 (replacements.txt 에 규칙 작성)
#   djemalsdlqslek12!@==>REDACTED
#   supersecret==>REDACTED
git filter-repo --replace-text replacements.txt

# 원격 강제 반영 (협업자 공지 후)
git push origin --force --all
git push origin --force --tags
```
- 스크럽 후 **GitHub 캐시/포크/PR** 에 잔존할 수 있으니, 민감도 높으면 GitHub Support 에 캐시 퍼지 요청.
- 협업자: 기존 클론 폐기 후 재클론(또는 `git fetch` + `git reset --hard origin/main`).

## 3단계 — 재발 방지 (이미 코드로 적용됨)

- ✅ `.env.template`·`.env.example` placeholder 화
