# 금액 정합 · 타임존 점검 (2026-07-28, 실측)

지금까지 "적립금이 공급가액 기준"이라는 메모만 있었고 **수치로 확인된 적은 없었다.** 실제로 측정했다.

---

## 1. 🔴 적립금 사용 시 부가세만큼 초과 할인 (실측 확인)

### 측정
| 항목 | 적용 전 | 적용 후 |
|---|---:|---:|
| item_total | 16,500 | 15,400 |
| tax_total | 1,500 | 1,400 |
| discount_total | 0 | 1,100 |
| **total** | **16,500** | **15,400** |

**적립금 1,000p 사용 → 최종 결제액 1,100원 감소** (= 사용액의 **110%** 혜택).

### 원인
Medusa 프로모션은 **공급가액(pre-tax)** 에 적용된다. 1,000원 할인 → 과세표준이 1,000원 줄고
부가세도 100원 줄어 총액은 1,100원 감소한다.

### 영향
- 적립금 사용량에 비례해 **매출의 10%가 추가로 빠진다**(부가세 10% 기준).
- 회계상 "1p = 1원" 을 가정했다면 원장(1,000p 차감)과 실제 할인(1,100원)이 어긋난다.

### 적용한 조치 (opt-in)
`POINTS_DISCOUNT_POST_TAX=true` 를 켜면 프로모션 값을 실효 세율로 나눠 등록해
**세금 포함 총액이 정확히 사용액만큼** 감소한다.

| 모드 | 1,000p 사용 시 총액 감소 | 잔액 차감 | 취소 후 복원 |
|---|---:|---:|---|
| 기본(OFF, 기존 동작) | **1,100** (⚠️ 100 초과) | 1,000 | ✅ 정확 |
| `POINTS_DISCOUNT_POST_TAX=true` | **999.9** (원 단위 반올림 오차 0.1) | 1,000 | ✅ 정확 |

- 기본은 **OFF** — 기존 동작을 바꾸지 않는다. 운영 전환 시 회계와 합의 후 결정할 항목.
- 함께 수정: 적립금 **취소 복원액을 프로모션 값이 아니라 원장의 실제 차감액 기준**으로 변경.
  (post-tax 모드에서 프로모션 값 < 차감액이라, 기존 로직대로면 취소할 때 고객 적립금이 줄어들었다.)

## 2. ✅ 타임존 — 문제 없음

- 백엔드 프로세스 TZ: `Asia/Seoul`, DB 저장은 **UTC(ISO Z)** — 표준적인 구성.
- 타임세일 `starts_at`/`ends_at` 도 UTC 로 저장되고 KST 로 표시된다
  (예: `2026-07-28T03:14Z` = 07-28 12:14 KST).
- 판정/필터는 서버 `now` 기준 UTC 비교라 **자정 경계 문제 없음**.

### 남은 주의(운영 배포 시)
- 컨테이너/서버 TZ 가 UTC 로 바뀌어도 **저장·비교는 UTC 라 영향 없음**. 다만 **로그·리포트 표기**는
  KST 로 포맷하는지 확인 필요(정산 일자 집계가 로컬 TZ 에 의존하면 하루 밀릴 수 있음).
- 정산 마감·휴면 판정처럼 "날짜 단위" 로직은 KST 기준 날짜로 명시적으로 계산할 것.
