# 장애 화면 · 접근성 · SEO 보완 — 2026-08-12

> 영어화를 끝낸 뒤 "또 할 만한 게 있는지" 전방위로 훑은 결과다.
> 값 결정이나 비용이 필요 없고, **고객이 실제로 겪는** 것부터 골라 고쳤다.

---

## 1. 없는 주소로 들어오면 맨 "404" 가 나왔다

가장 컸다. 없는 상품·카테고리·컬렉션·약관 주소로 들어오면 이런 화면이 나갔다:

```
404
```

한국어도, 링크도, 헤더도 없다. 고객은 **갈 곳을 잃는다.**

### 원인 — Next 는 not-found 를 위로 찾아 올라가지 않는다

`app/[countryCode]/(main)/not-found.tsx` 를 만들어 뒀으니 다 잡힐 줄 알았다. 아니었다.

**`notFound()` 에 대해 Next 는 그 세그먼트의 `not-found.tsx` 만 찾는다.** 상위로 올라가지 않는다.
그래서 `products/[handle]` 에서 `notFound()` 를 부르면 `(main)/not-found.tsx` 는 무시되고
프레임워크 기본 404 가 나간다.

확인 방법은 단순했다 — `products/[handle]/not-found.tsx` 를 하나 만들어 보니 **그건 쓰였다.**
그때까지는 "왜 안 잡히지" 를 추측만 하고 있었다.

> 곁다리로 `generateMetadata` 안의 `notFound()` 도 걷어냈다. metadata 생성은 렌더 트리
> 밖에서 일어나 어차피 세그먼트 404 를 못 그린다. 판정은 페이지가 한다.

### 고친 것

`modules/common/components/not-found-view` 하나로 화면을 모으고, `notFound()` 를 부르는
세그먼트마다 얇은 `not-found.tsx` 를 뒀다(상품·카테고리·컬렉션·약관·주문완료).

**404 화면 안에 이동 링크를 직접 넣었다** — Next 는 `notFound()` 화면에 상위 레이아웃을
붙여 주지 않아 헤더·푸터가 사라지기 때문이다. 홈 · 전체 상품 · 고객센터 세 곳으로 갈 수 있다.

## 2. 오류가 나면 헤더까지 사라졌다

오류 경계가 `app/global-error.tsx` 하나뿐이었다. 그건 **root layout 을 통째로 대체**하므로
고객은 헤더도 푸터도 없는 화면을 본다. 서버 렌더 중 예외면 아예 HTTP 500 빈 화면이었다
(2026-08-12 백엔드 재기동 중 `/kr` 이 실제로 500 을 냈다).

→ `(main)` · `(checkout)` 세그먼트에 `error.tsx` 를 뒀다. 실측 결과:

```
status=500  경계=O  재시도버튼=1  헤더=1
ko: 일시적인 오류가 발생했습니다 … 다시 시도 · 홈으로 가기 · 고객센터
en: Something went wrong …
```

**결제 화면은 문구를 따로 뒀다.** 결제 중 오류가 나면 고객이 가장 먼저 궁금해하는 건
"돈이 나갔나?" 다. 그래서 "다시 시도" 대신 **주문 내역 확인**을 앞에 둔다 —
결제 요청을 무심코 다시 보내는 것보다 상태를 확인하는 편이 안전하다.

### 곁다리 — 캐시 덕에 백엔드가 죽어도 화면은 떴다

검증하려고 백엔드를 실제로 내렸는데 홈·상품목록이 **200 으로 그대로** 떴다.
Next 데이터 캐시가 살아 있어서다. 회복력이 생각보다 좋다는 뜻이다.
오류 화면이 필요한 건 캐시가 비어 있는 순간(배포 직후 등)이다.

## 3. 접근성 — CRITICAL 위반이 있었는데 검사 목록에 없었다

axe 로 7화면 × 2언어를 재니 이렇게 나왔다.

```
[CRITICAL] button-name     4건 (상품상세, 양 언어)
[SERIOUS]  color-contrast  2건 (로그인 — 네이버 버튼)
```

**a11y 테스트는 이미 있었다.** 그런데 검사 목록에 **상품상세가 빠져 있었다.**
하필 거기에 CRITICAL 이 있었다. 목록에 없는 화면은 영원히 안 잡힌다.

### ① 아코디언 버튼에 이름이 없었다

상세 탭(상품 정보 / 배송·교환반품)의 제목이 **Trigger 밖**에 있고, Trigger 안에는
+/− 아이콘만 있었다. 그래서:

- 스크린리더가 **"버튼, 접힘"** 만 읽고 무엇을 여는지 알 수 없었다
- 제목을 눌러도 안 열리고 **작은 아이콘만** 눌러야 했다

제목을 Trigger 안으로 넣으니 둘 다 해결됐다. 줄 전체가 눌린다.

### ② 네이버 버튼 대비 2.25:1

```
#03C75A + 흰 글씨 = 2.25:1   (WCAG AA 는 4.5:1)
#FEE500 + #191600 = 14.20:1  (카카오는 통과)
```

`#02803B` 로 낮춰 **5.06:1** 을 맞췄다. 네이버 초록으로 알아볼 수 있는 범위다.

> ⚠️ 실제 OAuth 를 붙일 때 공식 브랜드 버튼 에셋을 쓰게 되면 브랜드 가이드와 접근성 중
> 무엇을 따를지 다시 정해야 한다. 지금은 데모라 우리 판단으로 갔다.

### 게이트를 넓혔다

- 검사 화면 5개 → **8개**(상품상세·주문조회·위시리스트 추가)
- `color-contrast` 를 **게이트에 포함**했다. 예전에는 "브랜드 색이라 어쩔 수 없다"며
  빼 뒀는데, 원인을 고쳤으니 면제할 이유가 없다. 면제 목록은 이제 **비어 있다** —
  새로 면제할 일이 생기면 **이유와 함께** 적도록 주석을 남겼다.

결과: 한국어 8/8 · 영어 8/8 **위반 0 · 면제 0**

## 4. 검색엔진이 영어 페이지를 볼 수 있게 했다

언어가 쿠키에만 있었다. 그래서:

| | 전 |
|---|---|
| 구글봇(쿠키 없음) | **항상 한국어만** 봤다 → 영어 콘텐츠는 색인 불가 |
| 영어로 보다 링크 공유 | 받는 사람은 한국어로 열렸다 |

→ **언어를 주소에 담았다.**

```
/kr/store      → 한국어  (기본 언어는 접두사 없음 — 기존 주소가 그대로 산다)
/en/kr/store   → 영어
```

### 라우트를 복제하지 않았다

언어별로 페이지를 두 벌 만들면 유지가 안 된다. 미들웨어가 `/en` 을 떼어내고
`rewrite` 한 뒤 언어를 요청 헤더(`x-ui-locale`)로 넘긴다. `getUiLocale()` 이 그걸 읽고,
콘텐츠 번역 헤더(`x-medusa-locale`)도 같은 판단을 쓴다 — 버튼만 영어이고 상품명은
한국어인 상태가 생기지 않는다.

### 주소가 쿠키를 이긴다

`/kr/...` 은 쿠키에 영어가 남아 있어도 한국어다. 그래야 링크가 공유 가능하다.
쿠키는 "마지막에 고른 언어"를 기억할 뿐이고, **국가코드 없는 주소로 들어올 때만**
반영된다(`/` → `/en/kr`).

### 두 번 막혔다

**① 링크가 접두사를 안 물고 갔다.** 내부 링크는 전부 `LocalizedClientLink` 를 거치므로
(다행히 `next/link` 직접 사용처는 그 하나뿐이었다) 거기서 붙이면 됐다.
주소를 손으로 만드는 `router.push` 두 곳(검색·주문조회)도 같이 고쳤다.

**② 전환기가 주소는 바꿨는데 화면 언어가 안 바뀌었다.**

```
주소 /en/kr/store  인데  <html lang="ko">
```

`router.push` 로 클라이언트 이동을 하면 **루트 레이아웃이 다시 렌더되지 않는다.**
그래서 `<html lang>` 과 `I18nProvider` 가 이전 언어로 남고, 서버 컴포넌트만 새 언어로
그려져 **한 화면에 두 언어가 섞였다.** 전환은 전체 페이지 로드로 바꿨다 —
자주 하는 동작이 아니므로 새로고침 비용이 맞다.

### 검색엔진에 알리는 것

- **hreflang** — 페이지마다 `ko-KR` · `en` · `x-default` 3종
- **canonical** — 보고 있는 주소 그대로
- **sitemap** — 모든 경로를 언어 수만큼 펼치고 서로를 alternates 로 연결
  (72건 = 한국어 36 + 영어 36, hreflang 링크 144개). 카테고리·컬렉션도 이때 함께 넣었다 —
  상품 상세만 올려 두고 목록 페이지가 빠져 있었다.
- **`Vary: Cookie`** — 국가코드 없는 주소의 진입 리다이렉트가 쿠키를 보기 때문.
  안 알리면 CDN 이 한 언어로 만든 응답을 다른 언어 방문자에게 내보낸다.

### 테스트의 계약도 바뀌었다

기존 다국어 테스트는 **쿠키를 심어** 언어를 바꿨다. 이제 쿠키를 심어도 `/kr/...` 은
한국어이므로 5건이 실패했다 — 옛 계약을 그대로 담고 있었던 것이다.
`e2e/_locale.ts` 헬퍼를 만들어 주소로 지정하도록 전부 바꾸고, 새 계약을 검사하는
테스트 3건을 추가했다:

- 주소가 쿠키를 이긴다
- 쿠키 없는 방문자도 영어 주소를 볼 수 있다(**검색엔진이 이 경로다**)
- 전환기가 주소까지 바꾼다

## 5. 개발 서버가 느려지는 문제

작업 중 화면이 눈에 띄게 느려졌다. 재기동 전후:

| | 전 | 후 |
|---|---|---|
| 여유 메모리 | **519 MB** / 16 GB | 6,680 MB |
| 노드 총 사용량 | 6,099 MB | 2,740 MB |
| 스토어프론트 한 프로세스 | **4,282 MB** | — |

148 개 파일을 고치는 동안 핫리로드가 누적되고 E2E 를 여러 번 돌린 결과다.
전부 스왑에 걸려 느렸던 것이지 코드 문제가 아니었다.

→ `scripts/restart-dev.ps1` 로 만들어 뒀다.

```
pwsh ./scripts/restart-dev.ps1
```

**백엔드는 반드시 `pnpm dev` 로 띄워야 한다.** `node .../@medusajs/cli/cli.js develop` 로
직접 띄우면 `Cannot find module '@medusajs/locking'` 로 죽는다 — pnpm 이 엄격한
node_modules 를 쓰는데 이 패키지는 전이 의존성이라(선언된 건 `@medusajs/locking-redis`)
경로로 직접 진입하면 해석되지 않는다. 이걸 모르고 한 번 헤맸다.
