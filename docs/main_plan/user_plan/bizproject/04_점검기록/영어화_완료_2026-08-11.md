## 어떻게 쟀나 — 소스 grep 은 쓸모가 없었다

처음에 `grep '[가-힣]'` 로 세었더니 1,300줄이 나왔다. 열어 보니 **대부분이 주석**이었다.
이 코드베이스는 주석을 전부 한국어로 쓴다.

그래서 두 가지를 따로 만들었다.

1. **소스 추출기** — 주석·문자열 상태를 추적하며 파싱해 **주석을 지운 뒤** 세는 스크립트
2. **화면 스캐너** — 영어로 설정한 브라우저로 실제 페이지를 열어 **DOM 텍스트 노드를 긁는** 스크립트
   (`placeholder`·`aria-label`·`title`·`alt` 까지 포함)

화면 스캐너가 유일한 근거다. 소스에 남아 있어도 화면에 안 나오면 상관없고,
반대로 백엔드가 내려주는 문장은 소스에 없어도 화면에 뜬다.

## 고친 것 — 라벨 교체만으로는 안 되는 것들이 있었다

### ① 백엔드가 **완성된 한국어 문장**을 내려주고 있었다

```
GET /store/coupons  →  { name: "5,000원 할인 쿠폰", benefit: "5,000원" }
```

화면은 받은 문자열을 그대로 찍을 수밖에 없다. 영어로 바꿀 방법이 아예 없었다.

→ **판단에 필요한 값만** 내려주도록 바꿨다.

```
{ discount_type: "fixed", discount_value: 5000, currency_code: "krw", name: null }
```

문장은 화면이 만든다. 운영자가 캠페인 이름을 붙였으면 그 이름이 이긴다.

같은 이유로 **주문 상태**(`shipped` → 배송 중 / In transit)와 **적립금 사유**(`purchase` → 구매 적립 /
Earned on a purchase)도 코드로 내려주고 화면에서 번역한다.

### ② 날짜가 화면마다 따로 놀았다

`Intl.DateTimeFormat("ko-KR")` 이 9곳에 흩어져 있었다. 영어 화면인데 날짜만
**"2026년 7월 27일"** 로 남았다. `@lib/util/format-date` 하나로 모았다.

### ③ 관리자에서 고친 값이 고객 화면에 안 반영됐다

상품을 고치면 Medusa 가 이벤트를 쏘고 구독자가 캐시를 지운다.
그런데 **번역 저장은 이벤트를 발행하지 않는다**(`@medusajs/translation`).
상품 목록은 `force-cache` 라 시간이 지나도 안 바뀐다.

→ `POST /admin/translations-revalidate` 를 만들고, 관리자 화면이 저장 직후 부르게 했다.
캐시 무효화가 실패해도 저장은 유지한다 — 저장이 되돌아가는 게 더 나쁘다.

### ④ 관리자 저장 키와 화면 표시 키가 어긋나 있었다 (상품고시)

관리자는 `field_key`(`material`·`origin`)로 저장하는데, 스토어프론트는 **받은 객체의 키를
그대로 항목명으로** 찍고 있었다. 즉 운영자가 관리자에서 고시를 입력하면 고객 화면에

```
material   면 100%          ← "소재" 여야 한다
origin     대한민국          ← "제조국" 여야 한다
```

라고 나왔다. 시드된 두 건만 한글을 키로 갖고 있어서 화면상 멀쩡해 보였을 뿐이다.
→ store 라우트가 상품유형 템플릿에서 항목명을 붙여 내려주도록 고쳤다(정렬 순서까지).

### ⑤ 영어 라벨이 짧아 버튼이 못 누르는 크기가 됐다

```
button "All" 15×20     ← 한국어 "전체"일 때는 폭이 넓어 넘어갔다
```

필터 버튼은 원래 높이가 **20px** 이었다. 한국어가 가려 주고 있었을 뿐이다.
글자 크기는 그대로 두고 누르는 영역만 24×24 로 넓혔다(WCAG 2.5.8).

> 이게 **양 언어로 검사해야 하는 이유**다. 한 언어만 보면 이런 게 안 잡힌다.

## 콘텐츠 — 확인할 데이터 자체가 없었다

시드된 상품은 이름·가격·이미지만 있고 나머지가 비어 있었다.

```
subtitle ∅ · material ∅ · 상품유형 ∅ · 태그 0개 · 상품고시 19건 중 2건
```

번역 대상 필드가 비어 있으니 **번역이 걸리는지 확인할 방법이 없었다.**

### 채운 것

| 스크립트 | 내용 |
|---|---|
| `seed-product-details.ts` | 상품 15종의 부제·상세 설명·소재·상품유형·태그·상품고시(14건 신규) |
| `seed-content-en.ts` | 상품·카테고리·컬렉션·옵션·유형·태그·배송방법·배너·공지·FAQ 의 en-US 번역 62건 |
| `seed-legal-en.ts` | 약관·개인정보처리방침 영문본 |

모두 `seed-all.ts` 에 등록했고, **이미 번역이 있으면 덮어쓰지 않는다**(운영자 수정본 보호).

### 곁다리로 발견한 것 — 카테고리가 순번 나머지로 붙어 있었다

```
구스다운 패딩 → 신발     캔버스 토트백 → 하의     스니커즈 → 상의
```

기존 시드가 `index % 5` 로 배정하고 있었다. 양 언어 공통 문제라 번역과 무관하게 잘못이었다.
15종 전부 제대로 재배정했다.

## 정정 — 잘못 짚은 것

처음에 "테스트 잔여 번역 20건이 고객 화면에 상품명으로 노출되고 있다"고 봤는데,
확인해 보니 **전부 소프트 삭제된 상태**였다. 첫 조회에서 `deleted_at` 을 안 걸렀다.
자가정리 테스트는 제대로 작동하고 있었다.

다만 **약관 쪽은 진짜였다** — QA 자동화가 만든 테스트 약관 10건이 `published` 로 남아 있었다.
`cleanup-test-data.ts` 가 이미 잡아내도록 돼 있었는데 **실행을 안 하고 있었다.** 정리했다.

## 사고 하나 — messages.ts 가 0바이트가 됐다

사전을 편집하던 파이썬 스크립트가 `open(p, "w")` 로 파일을 연 **직후** 인코딩 예외로 죽었다.
write 모드는 여는 순간 파일을 비우므로 원본이 사라졌다. 커밋본으로 되돌리면 그날 추가한
키를 전부 잃는 상황이었다.

turbopack dev 산출물이 모듈 소스를 그대로 품고 있어서 거기서 ko/en 객체를 뽑아 복구했다
(230키 × 2, 키 집합 일치 확인).

이후 편집은 **임시 파일에 쓰고 `os.replace` 로 갈아끼우도록** 바꿨다. 쓰다가 죽어도 원본이 남는다.

## 관리자 E2E 22개 중 **3개만 돌고 있었다**

곁다리로 나온 것 중 가장 큰 문제다.

`playwright.config.ts` 가 프로젝트마다 `testMatch` 로 **파일 하나씩** 등록하는 구조였다.
e2e 폴더에 스펙이 22개 있는데 `npx playwright test` 는 3개만 돌았고, 나머지 19개는
**한 번도 자동 실행되지 않았다.** 등록을 빠뜨렸다는 사실조차 드러나지 않는 구조였다 —
파일을 지정해 돌리면 어느 프로젝트에도 안 걸려 `No tests found` 가 뜬다.

→ `qa` 프로젝트 하나가 global-setup 을 뺀 전부를 잡도록 바꿨다. **3개 → 81개**가 실행된다.
새 스펙을 추가하면 등록 없이 바로 돌아간다.

돌려 보니 그동안 안 돌던 것들에서 **문제 3건**이 나왔다. 전부 고친 뒤 **81/81 통과**.

### ① QA 테스트가 고객에게 보이는 약관을 덮어쓰고 있었다

`qa_011` 의 QA-008 이 약관 초안을 만들고 **게시(publish)까지** 한다.
약관은 게시하는 순간 기존 게시본을 밀어내고 **현행 약관**이 된다. 그래서 고객이
`/content/terms-of-use` 에서 이런 걸 보고 있었다:

```
QA-008 자동화 테스트 약관 본문입니다. createDraft API 왕복 검증.
```

E2E 를 돌릴 때마다 하나씩 쌓여 10건이 published 로 남아 있었다.

→ 문서 종류를 `terms_of_service` → **`marketing_consent`** 로 바꿨다. store 라우트의
slug 매핑에 없는 종류라 **고객 화면에 노출되지 않는다.** 작성·게시 API 왕복 검증은 그대로다.
쌓여 있던 것은 `cleanup-test-data.ts` 로 정리했다(이미 잡아내도록 돼 있었는데 실행을 안 하고 있었다).

곁다리로 `seed-legal-en.ts` 가 **QA 약관에 영문본을 붙이는** 것도 발견해 막았다
(가장 최근 게시본을 고르는데 그게 QA 문서였다).

### ② 내 시드가 기존 테스트의 전제를 깼다

`qa_015` 는 "영어 제목을 비우면 미입력 표시(•)가 붙는다"를 확인하는데, 이제 시드가
설명·소재까지 넣어 두므로 제목만 비워도 번역이 남는다. 게다가 **비우면 시드된 영어 제목을
지워 버린다.**

→ 원래 값을 기억해 뒀다 되돌리도록 바꿨다. 미입력 표시 검사는 원래 번역이 없던 경우에만 한다.

### ③ 전체 실행에서만 나는 타임아웃

`menu-click`(30개 메뉴 순회)·`QA-001`·`QA-015` 가 전체 실행 중 30초를 넘겼다.
단독으로 돌리면 각각 5.5분(테스트 자체가 김) · 15.7초 · 14.8초로 통과한다.
22개를 순차로 15분 넘게 돌리는 동안 dev 서버가 느려지는 것이 원인이다.

→ 로직 문제가 아니라 시간 문제이므로 테스트 제한 시간을 30초 → **90초**로,
단정(expect) 대기를 **15초**로 올렸다(스토어프론트 설정과 동일). 근거는 주석에 남겼다.
`qa_001` 의 URL 이동 단정에 박혀 있던 10초 하드코딩도 걷어내 설정을 따르게 했다 —
개별 파일에 시간이 박혀 있으면 설정을 고쳐도 안 먹는다.
