### 3-1. 테스트 데이터가 고객 화면에 새던 문제 (2026-07-30)

판매 화면에 시드/자동화 흔적이 그대로 보이고 있었다. `scripts/cleanup-test-data.ts` 로 정리한다.

```bash
# 미리보기(기본 — 아무것도 바꾸지 않음)
npx medusa exec ./src/scripts/cleanup-test-data.ts

# 실제 적용 + 카테고리 이름·주소 정리
CLEANUP_APPLY=true CLEANUP_RENAME_TEST_CATEGORIES=true   npx medusa exec ./src/scripts/cleanup-test-data.ts
```

정리 내용:

- **카테고리 이름** — `상의(kr-test)` → `상의`. 사이드바·푸터에 태그가 그대로 노출되고 있었다.
- **카테고리 주소(handle)** — `상의` → `tops`. 한글 handle 은 URL 인코딩된 채 라우트에 들어와
  **카테고리 페이지가 전부 404** 였다(`/kr/categories/상의` → 404). ASCII 로 바꿔 5개 모두 200 확인.
  표시 이름은 한글 그대로 유지된다.
- **시드 스크립트도 함께 수정** — `seed-test-data.ts` 가 애초에 깨끗한 이름 + ASCII handle 로 만든다.
  테스트 데이터 식별은 상품 handle / 주문 metadata 의 `seed_tag` 로 한다.

**보고만 하고 손대지 않는 것**(오너 판단 필요):

- 시드 상품 15건 — 주소가 `/products/kr-test-p1` 형태. handle 이 시드 재실행 판정 키라 자동 변경하지 않는다. 실제 상품으로 교체하거나 비공개 처리.
- 자동화 테스트 계정 42건 — 주문·적립금이 얽혀 있어 자동 삭제하지 않는다.

> ⚠️ **알게 된 함정**: `medusa exec` 는 서버와 **별개 프로세스**라 in-process 이벤트버스의
> `storefront-revalidate` 구독자가 붙지 않는다. 워크플로우가 `product-category.updated` 를
> 발행해도 스토어프론트는 `force-cache` 된 옛 이름을 계속 보여준다.
> → 정리 스크립트가 `POST /api/revalidate` 를 **직접** 호출하도록 했다.

## 3-2. 🔴 동시성 결함 3건 — 실제 금전 손실 (2026-08-03 수정)

전면 점검에서 **실측으로 돈이 새는 것을 확인**한 결함이다. 상세는
[`보안점검/AUDIT-2026-08-03.md`](보안점검/AUDIT-2026-08-03.md) 참조.

| 경로 | 실측된 손실 | 원인 | 수정 |
|---|---|---|---|
| 적립금 사용 | 10,000P 로 **30,000원 할인**, 잔액 -20,000P | 락 키가 카트 단위인데 잔액은 고객 단위 자원. 잔액 검사도 락 밖 | 고객 단위 락 + 검사를 락 안으로 |
| 환불 | 1,000원 요청에 **3,000원 환불**(refund 3행) | 멱등키 검사~집행 사이 락 없음 | 멱등키 단위 락 |
| 강제취소 | 동시 이중 취소 + **만료 멱등키 재실행 허용** | 위와 동일 + fail-open | 주문 단위 락 + fail-closed |

세 건 모두 `검사 → (락 없음) → 집행` 이라는 **같은 뿌리**다.
순차 요청으로는 전부 정상 동작해서 지금까지 드러나지 않았다 — **동시 요청만 뚫렸다.**

> ⚠️ **운영 전제**: 분산 락은 `LOCKING_REDIS_URL`(없으면 `REDIS_URL`)이 있을 때만 유효하다.
> 둘 다 없으면 in-memory 로 떨어지고, API 를 2대 이상 띄우는 순간 **세 결함이 그대로 부활**한다.
