# 양 언어(한국어·영어) 기능 검증 — 2026-08-06

> 기존 테스트는 **전부 한국어 기준**이었다. 영어로 열었을 때 기능이 온전한지,
> 화면이 깨지지 않는지는 검증된 적이 없었다. 이 문서는 그 공백을 메운 기록이다.
>
> 원칙: 눈으로 확인한 것만 PASS 로 적었다.

---

## 왜 따로 봐야 하는가

영어 화면에서만 조용히 망가지는 것이 두 종류 있다.

1. **레이아웃** — 영문은 길어지는 문구가 많다
   (`정렬`(2자) → `Sort`(4자), `장바구니에 담기`(7자) → `Add to cart`(11자))
   좁은 버튼·모바일 뷰포트에서 넘치거나 잘린다.
2. **동작 단절** — 라벨만 번역되고 클릭 핸들러·쿼리는 안 붙는 경우.
   화면은 멀쩡해 보이므로 스윕만으로는 안 잡힌다.

---

## 1. 구매 전 과정 — 영어로 끝까지

`journey-probe.mjs` 에 `LOCALE` 옵션을 추가해 **모든 요청에 `x-medusa-locale`** 을 붙였다.

```
LOCALE=en-US node journey-probe.mjs   → 19/19 단계 통과
```

가입 → 로그인 → 상품조회 → 담기 → 배송지 → 배송수단 → 적립금 → 주문 → 조회 → 적립.
**금액이 한국어 실행과 동일**했다(33,000 + 배송 3,300 = 36,300원 · 적립 165P).
번역 적용이 금액·재고·주문 흐름을 건드리지 않는다는 뜻이다.

## 2. 체크아웃 E2E — 양 언어

`storefront-checkout.spec.ts` 에 `E2E_LOCALE` 지원을 추가해 같은 흐름을 두 언어로 돌렸다.

| | 비회원 결제 | 회원 + 적립금 사용 |
|---|---|---|
| 한국어 | PASS | PASS |
| 영어 (`E2E_LOCALE=en-US`) | PASS | PASS |

## 3. 전 화면 × 양 언어 × 두 뷰포트

신규 `storefront-bilingual.spec.ts` — 공개 화면 10종.
HTTP 200 · pageerror 0 · console error 0 · 본문 렌더 · **가로 넘침 ≤ 1px** 를 모두 본다.

| 뷰포트 | 결과 |
|---|---|
| 데스크톱 (Desktop Chrome) | **20/20** (한 10 + 영 10) |
| 모바일 (Pixel 7) | **20/20** |

**가로 넘침 0px** — 영문이 길어지는 화면에서도 레이아웃이 버틴다.

### 회원 전용 화면 (로그인 상태)

마이페이지·회원정보·주문내역·배송지·적립금·쿠폰·등급·약관동의 8종 × 2언어 = **18/18**
(넘침 0px · JS 에러 0)

## 4. 실제 조작 — 양 언어

신규 `storefront-bilingual-flow.spec.ts` — **눌러서 일이 일어나는지**를 본다.

| 검사 | 한국어 | 영어 |
|---|---|---|
| 목록 → 상세 이동, 담기 버튼이 해당 언어로 렌더 | PASS | PASS |
| 정렬 변경 → **URL 쿼리와 목록이 실제로 바뀜** | PASS | PASS |
| 로그인 실패 → 에러 메시지 노출 | PASS | PASS |
| 비회원 주문조회 → 없는 주문에 안내 표시 | PASS | PASS |

> 정렬은 **라벨이 아니라 `value`(=id)로** 집었다. 라벨만 번역되고 동작이 안 붙는 경우를 잡기 위해서다.

## 5. 접근성 — 양 언어

## 발견해 고친 것

### QA-015 E2E 가 실제 상품에 테스트 번역을 남기고 있었다

```
상품 목록(en-US) 조회 →  "QA English Title 1785977541632"
```

테스트가 만든 영어 상품명이 **지워지지 않고 남아** 영어 고객에게 그대로 보이는 상태였다.
반복 실행하면 계속 쌓인다.

→ 테스트가 **화면에서** 번역을 비워 저장하도록 고쳤다.
뒷정리이면서 동시에 **"번역 삭제" 경로 검증**이 된다(지운 뒤 미입력 표시 `•` 복귀 + 원문 유지 확인).

실행 후 잔여 번역 **0건** 확인.

> 곁다리로 확인한 것: 번역 삭제 시 화면에서 저장을 누르기 전에
> **React 상태 반영을 기다려야 한다.** 바로 누르면 비우기 전 값으로 저장돼 삭제가 안 된다.

## 결론

**한국어·영어 양쪽에서 기능 차이가 없다.**
구매·결제·계정·조회 전 경로가 두 언어에서 동일하게 동작하고, 금액도 같다.
레이아웃은 데스크톱·모바일 모두 넘침이 없다.

단, UI 라벨은 **점진 전환 중**이라 미전환 화면은 영어 모드에서도 한국어로 나온다.
이는 깨짐이 아니라 의도된 폴백이다 — 전환 현황은
[12. 다국어 가이드](../01_팀원용/12_다국어_가이드.md) 참조.

```bash
cd docs/.../통합테스트

# 전 화면 × 양 언어
cd apps/web
npx playwright test --project=bilingual          # 데스크톱
npx playwright test --project=bilingual-mobile   # 모바일
npx playwright test --project=bilingual-flow     # 실제 조작

# 체크아웃·접근성을 영어로
E2E_LOCALE=en-US npx playwright test --project=checkout

```
