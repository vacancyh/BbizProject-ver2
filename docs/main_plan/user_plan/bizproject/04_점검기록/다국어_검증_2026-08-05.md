## 검증 중 발견해 고친 것

### ① fresh 환경에서 언어 선택기가 안 뜬다

`db:migrate` 만 하면 `locale` 테이블에 51개 언어가 시드되지만
**스토어의 지원 언어는 비어 있어** `/store/locales` 가 `{"locales":[]}` 를 돌려준다.
→ 스토어프론트 언어 선택기가 **화면에 나타나지 않는다.**

새 팀원·새 배포마다 이 상태가 되므로 통합 시드(`seed-all.ts`)에 넣었다.

```
▶ 다국어(지원 언어·번역 대상) …
  [translation] 스토어 지원 언어 설정 — (없음) → ko-KR,en-US
```

### ② 관리자 아이콘 버튼에 접근성 이름이 없었다

공지·FAQ·배너의 수정/삭제 버튼이 **아이콘만** 있고 `aria-label` 이 없어
스크린리더로는 무슨 버튼인지 알 수 없었다. 6개에 이름을 붙였다.

> 발견 경위: 검증 스크립트가 버튼을 못 찾아서. 자동화가 못 찾으면 사람도 못 읽는다.

### ⚠️ 테스트 흔들림의 진짜 원인 — 기록해 둔다

검증 중 어드민 E2E 가 **2회 실패했다가 재실행하면 통과**하는 일이 반복됐다.
재실행으로 넘기지 않고 원인을 봤더니 **환경 문제**였다.

```
node 프로세스 40개 · 총 4.8GB · 시스템 여유 메모리 1.09GB
→ 정리 후: 여유 5.45GB
→ 어드민 QA 11.3분 / 2건 실패  →  5.3분 / 43건 전부 통과
```

세션 중 띄운 백그라운드 프로세스(백엔드 재기동·테스트 서버·Playwright)가 정리되지 않고 쌓였다.
**"재실행하면 되는 실패"는 대개 환경이 원인이다.** 같은 증상이 보이면 먼저 프로세스·메모리를 확인할 것.

## 운영 배포 시 필요한 설정

```ts
// medusa-config.ts
featureFlags: { translation: true },          // ← 없으면 관련 라우트가 전부 404
modules: [{ resolve: "@medusajs/translation" }],
```

```bash
npx medusa db:migrate
npx medusa exec ./src/scripts/seed-all.ts     # 다국어 설정 포함
```

지원 언어 변경: `TRANSLATION_LOCALES=ko-KR,en-US,ja-JP npx medusa exec ./src/scripts/setup-translation.ts`
