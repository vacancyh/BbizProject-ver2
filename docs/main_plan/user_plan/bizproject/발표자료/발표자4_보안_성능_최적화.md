## 1. 관리자 2단계 인증 (2FA) - 보안 강화 (1분 30초)

**[슬라이드: 보안 문제]**

관리자 페이지는 민감한 데이터를 다룹니다. 비밀번호만으로는 부족하다고 판단했어요.

### 문제 상황:

- 관리자 계정 해킹되면 고객 정보, 주문 전부 노출
- 비밀번호 유출 사고는 늘 일어남
- 추가 보안 장치 필요

그래서 2FA(Two-Factor Authentication)를 도입하기로 했습니다.

```
관리자 로그인에 2단계 보안 추가하고 싶어.
(※ 2단계 보안: 비밀번호 외에 추가 확인 절차)

방식: 스마트폰 앱으로 6자리 숫자 확인

흐름:
1. 관리자가 보안 활성화
   - QR 코드 생성
   - 앱으로 스캔
   - 백업 코드 발급 (앱 못 쓸 때용)
   
2. 로그인 시
   - 이메일/비밀번호 입력
   - 앱에 나오는 6자리 숫자 입력
   - 둘 다 맞아야 로그인

어떻게 만들면 돼?
```

```
AI 답변:

"필요한 라이브러리: 
- speakeasy (6자리 숫자 생성)
- qrcode (QR 코드 이미지 만들기)

만들어야 할 것:

1. 보안 정보 저장 테이블
   - 관리자 번호
   - 비밀 키 (암호화 저장)
   - 활성화 여부
   - 백업 코드들 (암호화, 1회용)

2. 기능
   - 보안 활성화 → 비밀 키 생성, QR 반환
   - 설정 확인 → 6자리 숫자로 검증
   - 로그인 시 확인 → 6자리 숫자 맞는지 체크

3. 보안 검사
   - 관리자 요청마다 2단계 보안 확인
   - 활성화됐는데 숫자 없으면 차단

[상세 코드...]"
```

### 구현 중 이슈:

```
비밀 키를 데이터베이스에 그냥 저장하면 안 될 것 같은데
암호화는 어떻게 해?
```

```
AI: "암호화 기능 사용하세요:
     (※ 암호화: 데이터를 알아볼 수 없게 변환)

과정:
1. 저장할 때: 평문 → 암호화 → DB 저장
2. 사용할 때: DB 조회 → 복호화 → 평문

[암호화/복호화 코드]

비밀 키 저장 시: encrypt(비밀키)
확인 시: decrypt(저장된값)"
```

이렇게 암호화해서 저장했습니다.

### UI 구현:

```
관리자 보안 설정 화면 만들어줘.

화면:
1. 현재 상태 (활성화/비활성화)
2. 활성화 버튼 클릭 시
   - QR 코드 표시
   - 백업 코드 10개 생성 (복사 가능)
   - 6자리 숫자 입력 (확인용)
3. 비활성화 버튼 (비밀번호 재확인 후)
```

테스트해보니 잘 작동했고, 실제로 Google Authenticator 앱으로 로그인까지 확인했습니다.

## 2. 요청 제한 - 서버 남용 방지 (1분)

**[슬라이드: 서버 남용]**

보안 점검하다 보니 서버 요청을 무한정 보낼 수 있는 게 문제였어요.
(※ 요청: 화면에서 서버로 데이터 주고받는 것)

### 문제:

- 로그인 시도를 무한정 할 수 있음 (비밀번호 대입 공격)
- 검색을 계속 하면 서버 부하
- 악의적인 대량 요청 공격에 취약

```
서버 요청 제한 기능 추가하고 싶어.

규칙:
- 로그인: 같은 IP에서 분당 5회만
- 회원가입: 같은 IP에서 시간당 3회만
- 검색: 같은 IP에서 분당 20회만
- 일반 요청: 같은 IP에서 분당 100회만

빠른 저장소(Redis)로 횟수 관리하고
제한 초과하면 에러

어떻게 구현하면 돼?
```

```
AI: "요청 제한 라이브러리 사용:

설치: express-rate-limit, rate-limit-redis

[설정 코드 생성]

사용 방법:
// 로그인에 엄격한 제한 적용
로그인 주소에 적용: 5회/분

// 일반 요청에 여유있는 제한
나머지에 적용: 100회/분
"
```

### 테스트:

```
요청 제한이 제대로 동작하는지 테스트하고 싶어.

테스트 상황:
1. 로그인을 6번 연속 시도
   → 6번째는 에러
2. 1분 기다린 후 다시 시도
   → 성공

테스트 코드 작성해줘
```

AI가 테스트 코드 만들어줬고, 실제로 돌려보니 정상 작동했습니다.

## 3. 베스트 랭킹 최적화 - 성능 개선 (1분 30초)

**[슬라이드: 성능 문제]**

베스트 상품 랭킹 기능을 만들었는데, 메인 페이지가 너무 느렸어요.

### 문제 분석:

- 베스트 상품 순위: 최근 7일 판매량 기준 TOP 10
- 페이지 로드할 때마다 데이터베이스 계산
- 복잡한 계산으로 3~4초 소요

```
베스트 순위 조회가 너무 느려.
(※ 조회: 데이터를 찾아오는 것)

현재 방식:
매번 최근 7일간 판매 데이터를 계산해서
인기 상품 순위를 만듦

이거 매번 계산하면 느린데 어떻게 빠르게 해?
```

```
AI: "3가지 방법:

1. 미리 저장하기 (가장 빠름)
   (※ 캐싱: 결과를 미리 저장해두고 재사용)
   - 빠른 저장소(Redis)에 결과 저장
   - 10분마다 새로 계산
   - 첫 번째만 느리고 이후는 빠름

2. 데이터베이스에 미리 계산해두기
   - 10분마다 자동 갱신

3. 실시간 업데이트
   - 주문 완료될 때마다 카운터 증가
   - 항상 최신이지만 구현 복잡

추천: 1번 (미리 저장하기)"
```

### 미리 저장하기 구현:

```
베스트 순위 미리 저장하는 기능 만들어줘.

동작:
1. 빠른 저장소(Redis)에서 'ranking:best' 조회
2. 있으면 바로 반환 (빠름!)
3. 없으면 데이터베이스 계산 → Redis 저장 (10분 유지) → 반환

초기화:
- 관리자가 수동으로 초기화할 수 있는 기능도 필요
```

```
AI: [미리 저장하는 코드]

순위 조회 기능:
  1. Redis에 저장된 게 있나 확인
  2. 있으면 바로 반환
  3. 없으면:
     - 데이터베이스에서 계산
     - Redis에 10분 동안 저장
     - 반환

초기화 기능:
  Redis에서 삭제 (다음 조회 시 다시 계산됨)
```

### 성능 비교:

테스트 결과:
- 저장 전: 평균 3.2초
- 저장 후: 평균 0.05초 (64배 빠름!)

훨씬 빨라졌습니다!

## 4. 인기 검색어 - 실시간 추적 (1분)

**[슬라이드: 검색어 분석]**

고객들이 무엇을 검색하는지 추적해서 메인에 보여주고 싶었습니다.

```
인기 검색어 기능 만들어줘.

요구사항:
- 고객이 검색할 때마다 키워드 기록
- 실시간 TOP 10 (1시간 기준)
- 메인 페이지에 표시

빠른 저장소(Redis)로 구현하면 좋을 것 같은데
어떻게 하면 돼?
```

```
AI: "순위 저장 기능 사용:
     (※ Sorted Set: 점수별로 자동 정렬되는 저장 방식)

검색할 때:
키워드 점수 1점 증가

TOP 10 조회:
점수 높은 순으로 10개 가져오기

1시간마다 초기화:
자동 작업으로 매시간:
- 이전 데이터 백업
- 새로운 집계 시작

[상세 구현...]"
```

간단하게 점수 증가 방식으로 구현했고, 매시간 자동으로 초기화되게 했습니다.

### UI:

```
메인 페이지에 인기 검색어 위젯 만들어줘.

디자인:
- 1~10위 숫자와 검색어
- 클릭하면 해당 검색어로 검색
- 순위 변동 표시 (▲▼ 화살표)
```

AI가 화면을 만들어줬고, 실제로 검색하면 바로 순위에 반영되는 걸 확인했습니다.

## 5. 나의 소감 및 종합 정리 (30초)

**[슬라이드: 소감]**

보안/성능 작업하면서:

**1. 보안은 나중이 아니라 처음부터**
- 기능 다 만들고 보안 추가하려니까 힘들었어요.
- 설계 단계에서 AI한테 "보안 이슈는?" 물어보세요.

**2. 성능 문제는 측정부터**
- "느린 것 같다"가 아니라 실제로 측정해야 합니다.
- AI한테 "이 기능 성능 분석해줘" 하면 문제점 찾아줘요.

**3. 미리 저장하기는 효과 좋음**
- Redis 미리 저장하기만 잘 써도 성능 엄청 개선됩니다.
- AI가 저장 전략(언제 갱신할지, 언제 지울지)도 잘 제안해줍니다.

**4. AI는 보안 기본 방법을 알고 있다**
- "이 코드 보안 문제 있어?" 물으면 찾아줍니다.
- 일반적인 보안 취약점 확인해줍니다.

## 전체 프로젝트 종합 소감 (30초)

**[슬라이드: 프로젝트 완성]**

2개월간 AI와 함께 쇼핑몰을 만들면서 깨달은 점:

**AI 활용의 핵심:**
1. **구체적으로 물어보기** - 애매하면 애매한 답 나옴
2. **검증하면서 진행** - AI 맹신 금물, 항상 테스트
3. **단계별로 나누기** - 한 번에 다 하지 말기
4. **에러는 친구** - 에러 로그 공유하면 대부분 해결
5. **문서 남기기** - AI한테 README 만들어달라고 하기

**프로젝트 성과:**
- 2개월 만에 50,000줄 코드
- 주문, 결제, 회원, 상품, 보안, 최적화 전부 구현
- 4명이 각자 모듈 개발, 충돌 거의 없음
- AI 없었으면 6개월 걸렸을 거예요

**앞으로:**
- AI는 도구일 뿐, 설계와 판단은 개발자의 몫
- 하지만 이 도구를 잘 쓰면 생산성 10배
- 평범한 개발자도 AI와 함께라면 충분히 할 수 있습니다

이상으로 저희 쇼핑몰 프로젝트 발표를 마치겠습니다. 감사합니다!
