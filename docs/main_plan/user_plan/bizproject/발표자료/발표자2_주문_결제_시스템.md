# 발표자 2: 주문/결제 시스템 개발 (4~5분)

**[자기소개]**

안녕하세요, 두 번째 발표 맡은 OOO입니다. 저는 주문과 결제 프로세스를 담당했습니다. 쇼핑몰에서 가장 복잡하고 중요한 부분이죠. 이 과정에서 AI를 어떻게 활용했는지 보여드리겠습니다.

## 1. 주문 프로세스 설계 - 복잡한 작업 흐름 (1분 30초)

**[슬라이드: 주문 흐름도]**

한국 쇼핑몰의 주문은 생각보다 복잡합니다. 단순히 "구매 버튼 누르면 끝"이 아니에요.

### 요구사항 정리:

- 장바구니 → 주문서 → 결제 → 주문 완료
- 재고 체크 (동시 주문 시 오버셀 방지)
- 쿠폰 할인, 적립금 사용
- 배송비 계산 (5만원 이상 무료)
- 주문 상태 관리 (대기→결제→배송→완료)

이걸 어떻게 만들지 막막해서 AI한테 물어봤습니다.

### 프롬프트:

```
"한국 쇼핑몰 주문 과정 설계해줘.
(※ 주문 과정: 장바구니 → 결제 → 주문 완료까지의 흐름)

처리할 것들:
1. 재고 확인 및 차감 (두 사람이 동시에 주문해도 문제없게)
2. 쿠폰 할인 적용
3. 적립금 사용
4. 배송비 계산 (5만원 이상 무료, 미만 3000원)
5. 주문 생성
6. 결제 대기

중간에 하나라도 실패하면 전부 취소돼야 해.
어떻게 구현하면 좋을까?"
```

### AI 답변:

```
"단계별로 나눠서 처리하는 워크플로우를 추천합니다.
(※ 워크플로우: 여러 작업을 순서대로 처리하는 흐름)

작업 단계들:
1. 장바구니 검증
2. 재고 확인 (동시 주문 방지)
3. 쿠폰 할인 계산
4. 적립금 차감
5. 배송비 계산
6. 주문 생성
7. 재고 예약
8. 결제 정보 생성

각 단계가 실패하면 이전 작업들을 자동으로 되돌립니다.

[상세 코드 구조...]"
```

좋은데, 복잡한 상황들이 걱정됐어요.

## 2. 복잡한 상황 검증 - AI와 함께 허점 찾기 (1분)

**[슬라이드: 검증 과정]**

설계 받고 바로 코딩하지 않았습니다. 먼저 문제 상황을 시뮬레이션해봤어요.

### 동시 주문 문제:

```
"재고 1개 남았는데 2명이 동시에 주문하면 어떻게 해?"
```

```
AI: "데이터베이스 잠금 기능을 사용하면 됩니다.
     (※ 잠금: 먼저 온 사람이 작업 끝날 때까지 다른 사람은 대기)

재고 확인할 때:
1. 재고 데이터에 잠금 걸기
2. 재고가 충분한지 확인
3. 부족하면 에러
4. 충분하면 진행

이렇게 하면 첫 번째 주문이 끝날 때까지 
두 번째 주문은 자동으로 대기합니다."
```

### 할인 순서 문제:

```
"쿠폰이랑 적립금 둘 다 쓸 때 순서가 중요한데,
어떤 게 먼저야?"
```

```
AI: "일반적으로:
1. 쿠폰 할인 먼저 (정가 기준)
   예: 100,000원 - 10% = 90,000원
2. 적립금 차감 (할인된 가격 기준)
   예: 90,000원 - 5,000P = 85,000원

이유: 쿠폰은 판매자 혜택, 적립금은 고객 자산
쿠폰 먼저 적용하는 게 일반적입니다."
```

이런 식으로 의심되는 부분을 계속 물어봤습니다.

## 3. 단계별 구현 - 하나씩 만들어서 합치기 (1분 30초)

**[슬라이드: 실제 구현]**

설계가 확정되고 본격적으로 코딩 시작했습니다. 한 번에 다 만들면 문제 찾기 어려워서 단계별로 작업했어요.

### 1단계: 재고 확인 기능

```
"재고 확인 기능 먼저 만들어줘.

입력: 
- 상품 번호들
- 필요한 수량들

처리:
- 잠금 걸고 재고 조회
- 수량 부족하면 에러
- 충분하면 재고 정보 반환"
```

AI가 코드 생성 → 테스트 → 에러 발생:

```
"잠금이 안 걸리는데?
[에러 로그]"
```

```
AI: "작업 묶음(트랜잭션) 안에서 실행해야 합니다.
     (※ 트랜잭션: 여러 작업을 하나로 묶어서 처리)

설정에 이 부분 추가:
transaction: true  // 작업들을 하나로 묶기
"
```

추가하니까 해결됐습니다.

### 2단계: 할인 계산 기능

```
"할인 계산 기능 만들어줘.

입력:
- 상품 금액 합계
- 쿠폰 코드 (있으면)
- 고객 번호

처리:
1. 쿠폰 확인
   - 쿠폰이 유효한지
   - 기간이 지나지 않았는지
   - 사용 횟수 남았는지
   - 최소 금액 충족하는지
2. 할인 계산
   - 퍼센트면: 금액 × 비율
   - 고정 금액이면: 정해진 금액
3. 할인 금액 반환"
```

테스트했더니 문제 발견:

```
"할인 금액이 주문 금액보다 크면 어떻게 돼?
마이너스가 나오는데?"
```

```
AI: "좋은 지적입니다. 최종 금액이 0보다 작으면 안 됩니다.

할인 계산 후:
최종금액 = 주문금액 - 할인금액
만약 최종금액이 0보다 작으면 → 0으로 설정

이렇게 하면 마이너스 방지됩니다."
```

### 3단계: 적립금 차감 기능

```
"적립금 차감 기능 만들어줘.

입력:
- 고객 번호
- 사용할 포인트
- 주문 금액 (할인 후)

처리:
1. 고객 포인트 잔액 확인
2. 포인트가 부족하면 에러
3. 사용 포인트가 주문 금액보다 크면 에러
4. 포인트 차감 (주문 성공하면 확정)

출력:
- 차감 후 최종 금액"
```

### 4단계: 전체 흐름 합치기

```
"이제 위에서 만든 기능들을 합쳐서 
주문 전체 흐름 완성해줘.

순서:
1. 장바구니 검증
2. 재고 확인 (잠금)
3. 할인 적용
4. 적립금 차감
5. 배송비 계산
6. 주문 생성
7. 재고 예약
8. 결제 정보 생성

중간에 실패하면:
- 재고 → 되돌리기
- 포인트 → 복구하기
등등"
```

AI가 전체 코드를 만들어줬고, 저는 이걸 테스트했습니다.

## 4. 관리자 주문 관리 - 프론트와 연동 (30초)

**[슬라이드: 관리자 화면]**

백엔드 API가 완성되니까 이제 관리자 화면이 필요했습니다.

```
"관리자 주문 관리 화면 만들어줘.

기능:
- 주문 목록 보기 (페이지 나누기, 필터)
- 주문 상태 변경 (결제 대기 → 결제 완료 → 배송 중 → 배송 완료)
- 주문 상세 보기 (고객 정보, 상품, 결제, 배송지)
- 송장번호 입력"
```

AI가 화면 코드 생성 → 실행해보니 디자인이 조금 아쉬워서:

```
"테이블 디자인 개선해줘.
주문 상태는 색깔 있는 뱃지로 표시 (대기=노랑, 완료=초록)
필터는 위쪽에 선택 상자로"
```

이렇게 수정하면서 완성했습니다.

## 5. 실제 테스트 - 전체 과정 검증 (30초)

**[슬라이드: 테스트]**

마지막으로 전체 흐름을 테스트했습니다.

```
"주문 전체 흐름 테스트 코드 작성해줘.

테스트 상황들:
1. 정상 - 주문 성공
2. 재고 부족 - 주문 실패, 되돌리기 확인
3. 쿠폰 만료 - 주문 실패
4. 포인트 부족 - 주문 실패
5. 동시 주문 - 한 명만 성공"
```

테스트 돌려보니 5번에서 실패:

```
"동시 주문 테스트에서 둘 다 성공하는데?
잠금이 안 걸린 건가?"
```

```
AI: "테스트 환경에서 데이터 처리가 제대로 안 됐을 수 있습니다.

테스트 시작 전에:
데이터 작업 시작

테스트 끝난 후:
데이터 작업 취소

또는 실제 데이터베이스로 완전히 테스트해보세요."
```

실제 데이터베이스로 다시 테스트하니까 정상 동작했습니다.

## 6. 나의 소감 및 배운 점 (30초)

**[슬라이드: 소감]**

주문/결제 시스템을 AI와 함께 만들면서:

**1. 복잡한 기능도 단계별로 나누면 된다**
- 전체를 한 번에 만들려고 하면 어렵습니다.
- 하나씩 만들고 테스트하고 합치세요.

**2. 복잡한 상황은 반드시 물어보기**
- "이런 경우엔 어떡해?" 계속 질문해야 합니다.
- AI가 처음부터 완벽한 답을 주지 않아요.

**3. 에러는 빠르게 공유하고 고치기**
- 에러 내용을 AI에게 보여주면 대부분 해결해줍니다.
- 혼자 끙끙대지 말고 바로 물어보세요.

**4. 테스트가 생각보다 중요**
- 주문/결제는 실수하면 큰 문제가 됩니다.
- AI한테 테스트 코드도 같이 만들어달라고 하세요.
