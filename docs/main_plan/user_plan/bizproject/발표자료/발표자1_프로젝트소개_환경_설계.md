## 1. 프로젝트 배경 (30초)

**[슬라이드: 프로젝트 개요]**

저희는 회사 bizproject 프로그램의 일환으로 한국형 쇼핑몰을 개발했습니다. 

- **팀**: 4명
- **핵심 포인트**: AI를 적극 활용한 개발

솔직히 말씀드리면, 저희는 쇼핑몰 개발 경험이 많지 않았습니다. 그래서 처음부터 AI를 최대한 활용하기로 했고, 설계부터 코딩, 테스트까지 모든 과정에서 AI와 함께 작업했습니다.

오늘은 **"평범한 개발자가 AI를 어떻게 활용해서 프로젝트를 완성했는지"** 그 과정을 보여드리겠습니다.

## 2. 기술 스택 선정 - AI와의 첫 대화 (1분)

**[슬라이드: 기술 스택]**

가장 먼저 한 일은 어떤 기술을 쓸지 결정하는 거였습니다. 이것부터 AI한테 물어봤어요.

### 실제 프롬프트:

```
나: "한국 쇼핑몰을 만들려고 하는데, 어떤 기술이 좋을까?
    
    요구사항:
    - 관리자와 고객용 화면 둘 다 필요
    - 상품, 주문, 재고 관리
    - 결제 연동 가능해야 함
    - 쿠폰, 적립금 같은 한국 쇼핑몰 기능
    - 빠르게 개발하고 싶음
    
    오픈소스 쇼핑몰 프레임워크 추천해줘"

AI: "Medusa.js를 추천합니다.
     (※ Medusa: 쇼핑몰 개발을 위한 오픈소스 도구)
     
     장점:
     - 관리자 화면 기본 제공
     - 기능별로 나눠서 개발 가능
     - 결제/배송 쉽게 추가
     
     필요한 기술들:
     - 백엔드(서버): Medusa v2
     - 프론트(화면): Next.js
       (※ Next.js: 웹사이트 만드는 도구)
     - 데이터베이스: PostgreSQL
       (※ 데이터 저장하는 곳)
     - 캐시(빠른 저장소): Redis
       (※ 자주 쓰는 데이터를 빠르게 꺼내기 위한 저장소)"
```

이렇게 AI가 추천해준 기술들을 기본으로 가기로 했습니다. v1과 v2가 있다고 해서 다시 물어봤어요.

```
나: "Medusa v1이랑 v2 차이가 뭐야? 뭐 쓰는 게 좋아?"

AI: "v2가 최신이고:
     - 모듈 시스템 개선 (기능별로 코드 정리가 더 잘됨)
     - 복잡한 작업 처리 기능 추가
     - 안정성 강화
     
     v2 추천합니다"
```

그래서 v2로 결정했습니다.

## 3. 개발 환경 셋업 - AI가 만들어준 설정 (1분)

**[슬라이드: 환경 설정]**

기술이 정해지고 나니까 개발 환경을 만들어야 했습니다. 이것도 AI한테 맡겼어요.

### 데이터베이스 설정 파일 생성:

```
나: "Medusa v2 프로젝트 개발 환경 만들고 싶어.
    
    필요한 거:
    - PostgreSQL (데이터베이스)
    - Redis (빠른 저장소)
    - 데이터는 내 컴퓨터에 저장
    
    docker-compose.yml 파일 만들어줘"
    (※ docker-compose: 여러 프로그램을 한번에 실행하는 설정 파일)

AI: [설정 파일 생성]
```

받아서 실행했더니 바로 데이터베이스가 준비되더라고요.

### 환경 설정 파일:

```
나: "서버 설정 파일(.env)도 만들어줘.
    위에서 만든 데이터베이스에 연결되게"
    (※ .env: 서버 접속 정보를 담은 설정 파일)

AI: [설정 파일 생성]
    DATABASE_URL=postgresql://...  (데이터베이스 주소)
    REDIS_URL=redis://...  (캐시 주소)
    JWT_SECRET=...  (보안 키)
```

근데 여기서 문제가 생겼어요.

```
나: "서버 시작하면 DB 연결 안 된다는 에러 나는데?
    [에러 로그]"

AI: "데이터베이스가 아직 준비 안 됐을 수 있습니다.
     데이터베이스 테이블 먼저 만들어보세요
     명령어: medusa migrations run"
```

AI가 알려준 명령어 실행하니까 해결됐습니다. 이런 식으로 AI가 에러도 같이 해결해줬어요.

## 4. 프로젝트 전체 설계 - AI와 함께 그린 청사진 (2분)

**[슬라이드: 전체 구조]**

이제 본격적으로 프로젝트 구조를 설계했습니다. 이 부분이 가장 중요했어요.

### 초기 설계 프롬프트:

```
나: "한국 쇼핑몰 데이터베이스 설계 도와줘.
    (※ 데이터베이스: 회원, 상품, 주문 정보를 저장하는 곳)
    
    필요한 기능:
    - 회원 (일반/관리자, 등급별 혜택)
    - 상품 (옵션, 재고)
    - 주문 (결제, 배송)
    - 쿠폰, 적립금
    - 리뷰, 문의
    - 배너, 추천 상품
    
    Medusa의 기본 구조 활용하면서
    한국 쇼핑몰에 필요한 부분 추가해줘"

AI: "Medusa 기본 구조 활용 + 추가:
     
     [기본으로 제공되는 것]
     - User → 회원 정보
     - Product → 상품
     - Order → 주문
     - Cart → 장바구니
     
     [우리가 추가할 것]
     - customer_level (등급: BRONZE/SILVER/GOLD/VIP)
     - customer_points (적립금 내역)
     - review (리뷰)
     - inquiry (1:1 문의)
     - banner (배너)
     - curated_product (추천 상품)
     
     [상세 구조...]"
```

이렇게 초안을 받았는데, 저희가 생각하지 못한 부분들이 있었어요.

### 설계 검증:

```
나: "쿠폰이 상품별, 카테고리별, 전체 할인 이렇게 3가지인데
    어떻게 설계하면 돼?"

AI: "할인 테이블 구조 추천:
     - type: 상품별 / 카테고리별 / 전체
     - target_id: 대상 상품이나 카테고리 번호
     - discount_type: 퍼센트 / 금액
     - value: 할인율 또는 할인 금액
     
     이렇게 하면 여러 종류 쿠폰을 유연하게 관리할 수 있어요"

나: "적립금은 주문할 때마다 쌓이고, 사용할 때 차감되는데
    내역 관리는 어떻게 해?"

AI: "적립금 거래 내역 테이블 추가:
     - customer_id (고객 번호)
     - type: 적립 / 사용 / 만료
     - amount: +/- 금액
     - order_id: 어느 주문에서 발생했는지
     - expired_at: 만료일
     
     현재 잔액은 모든 거래 내역을 합산해서 계산"
```

이런 식으로 여러 번 대화하면서 구조를 다듬었습니다.

### 기능별 폴더 구조 설계:

```
나: "기능별로 어떻게 폴더를 나누면 좋을까?
    
    우리가 추가할 기능:
    - 적립금
    - 등급
    - 리뷰/문의
    - 쿠폰
    - 배너/추천상품
    - 베스트 랭킹
    - 관리자 보안 강화"

AI: "각 기능을 독립된 폴더로 나누세요:
     (※ 모듈: 기능별로 나눈 코드 묶음)
     
     backend/services/api/src/modules/
       ├── customer-level/      (등급 관리)
       ├── customer-points/     (적립금 관리)
       ├── review/             (리뷰)
       ├── inquiry/            (문의)
       ├── discount/           (쿠폰)
       ├── banner/             (배너)
       ├── curation/           (추천 상품)
       ├── ranking/            (베스트 랭킹)
       └── admin-2fa/          (관리자 보안)
     
     각 폴더 안에:
     - models/ (데이터 구조)
     - service.ts (기능 구현)
     - routes/ (화면과 연결)
     - workflows/ (복잡한 작업 흐름)
     
     이렇게 나누면 각자 다른 기능 작업해도 충돌 안 남"
```

이 구조 그대로 프로젝트를 만들었고, 나중에 팀원들이 각자 기능 개발할 때 충돌이 거의 없었습니다.

### 서버 주소 설계:

```
나: "서버 주소(API)도 정리해줘. 
    관리자용이랑 고객용 분리해야 하고"
    (※ API: 화면과 서버가 데이터 주고받는 통로)

AI: "주소 구조:
     
     [고객용 - /store]
     - GET /store/products (상품 목록)
     - GET /store/products/:id (상품 상세)
     - POST /store/cart (장바구니 담기)
     - POST /store/orders (주문하기)
     - GET /store/me (내 정보)
     - POST /store/reviews (리뷰 작성)
     
     [관리자용 - /admin]
     - GET /admin/products (상품 조회)
     - POST /admin/products (상품 등록)
     - GET /admin/orders (주문 조회)
     - PATCH /admin/orders/:id (주문 상태 변경)
     - GET /admin/customers (회원 조회)
     
     [로그인/인증]
     - POST /auth/customer/register (회원가입)
     - POST /auth/customer/login (로그인)
     - POST /admin/auth/2fa/enable (관리자 보안 설정)"
```

이렇게 주소 체계를 정리하고, 나중에 화면 개발할 때 이걸 기준으로 작업했습니다.

## 5. README 문서화 - AI가 정리한 프로젝트 (30초)

**[슬라이드: 문서화]**

마지막으로 설정과 설계가 끝나고 나니까, 이걸 문서로 남겨야 나중에 팀원들이 보기 편하겠더라고요.

```
나: "지금까지 만든 환경 설정, DB 스키마, 모듈 구조, API 명세
    이거 다 정리해서 README.md 만들어줘.
    
    새로운 사람이 와도 바로 시작할 수 있게"

AI: [README.md 생성]
     - 프로젝트 소개
     - 기술 스택
     - 환경 설정 방법
     - DB 스키마 다이어그램
     - 모듈 구조
     - API 엔드포인트 목록
     - 개발 가이드
```

이 README가 나중에 엄청 유용했어요. 팀원들이 작업하다가 막히면 여기 보고 해결하는 경우가 많았습니다.

## 6. 나의 소감 및 배운 점 (30초)

**[슬라이드: 소감]**

제가 초기 환경 설정과 설계를 담당하면서 느낀 점은:

**1. AI는 빠른 프로토타이핑에 최고**
- 혼자 했으면 며칠 걸렸을 환경 설정을 몇 시간 만에 끝냈어요.
- 여러 선택지를 빠르게 비교할 수 있었습니다.

**2. 하지만 검증은 필수**
- AI가 준 설계 그대로 쓰면 나중에 문제 생깁니다.
- "이렇게 하면 이런 문제 있지 않아?" 계속 물어봐야 해요.

**3. 문서화가 중요**
- AI한테 README 만들어달라고 한 게 정말 잘한 일이었어요.
- 팀원들이 이거 보고 바로 작업 시작할 수 있었습니다.

**4. 초기 설계가 탄탄하면 나중이 편함**
- 기능별 폴더 구조를 처음에 잘 잡아놔서 나중에 기능 추가가 쉬웠어요.
- AI가 제안한 구조가 실제로 유용했습니다.
