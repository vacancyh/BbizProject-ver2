# 상세기획서 — shop 관리자 (Medusa 어드민 리플랫폼)

> 이 문서 하나로 프로젝트 전체(목표·범위·아키텍처·도메인 분해·진행 전략)를 파악한다.
> 상세 도메인 목차는 `dag/dag_index.md`, 도메인별 기능 목차는 각 `dag/d<n>_*/task_index.md` 참조.

## 1. 목표
- 단독몰(자사몰) **관리자(어드민)** 를 Medusa v2.15.3 기반으로 리플랫폼한다.
- Medusa core 기능은 **호출/래핑**으로 재사용한다(복사·재구현·포크 금지).
- 한국 단독몰 운영에 필요한 기능 갭은 custom module 로 보강하고 `(메두사기능없음)` 배지로 식별한다.

## 2. 범위
- **In**: 관리자 메뉴 12개 도메인(대시보드·주문·상품·카테고리·회원·배송·정산·쿠폰프로모션·리뷰문의·통계리포트·쇼핑몰설정·마케팅) = 73 기능(task) + 횡단 엣지 DAG(d13) 10 task = 83 task.
- **Out**: 스토어프론트 전용(장바구니·위시리스트·고객 쇼핑 플로우), 인프라(docker·nginx·포트), 타 프로젝트. 인증(login/reset/invite)은 d5 t003_관리자계정에 흡수.

## 3. 아키텍처 (요약)
- Node v24 · Medusa v2.15.3 · Postgres 17(5434) · Redis 7(6381).
- Admin 앱 `apps/admin`(7002), 백엔드 `backend/services/api`.
- custom module = `src/modules/`(rma-extension·legal-kr·state-machine·payment-kr 등). 갭B 기능은 module 추가.

## 4. 갭 처리 원칙
- **호출/래핑**: Medusa 실물 라우트(§2 35 라우트)는 우리 앱 화면에서 호출/래핑.
- **갭A**(Medusa 有 / 우리 메뉴 미정의): 신규 화면 설계까지 이전(예: 판매채널·API키·워크플로우로그).
- **갭B**(우리 필요 / Medusa 無): custom module + `(메두사기능없음)` 배지(예: 한국식쿠폰·정책저장소·RBAC·감사로그·SMS·알림톡·CMS).
