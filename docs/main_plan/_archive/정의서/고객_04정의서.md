# 고객(Customer) 도메인 정의서

> Medusa v2.15.3 | `@medusajs/customer` | 확인 경로: `node_modules/.pnpm/@medusajs+customer@2.15.3.../dist/models/`

---

## 1. 도메인 개요

고객 도메인은 쇼핑몰 이용자의 프로필 정보, 배송지 주소록, 고객 그룹을 관리합니다.
인증(Auth) 모듈과 분리되어 있으며, Auth 모듈이 자격증명을 관리하고
Customer 모듈이 프로필·주소록을 관리합니다.

---

## 2. 핵심 데이터 모델(엔티티)과 주요 필드

### 2.1 Customer (고객)

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | string (PK) | 고유 식별자 (prefix: `cus_`) |
| `company_name` | string \| null | 법인명 (B2B 지원) |
| `first_name` | string \| null | 이름 |
| `last_name` | string \| null | 성 |
| `email` | string \| null | 이메일 |
| `phone` | string \| null | 전화번호 |
| `has_account` | boolean | 가입 계정 보유 여부 (false = 비회원) |
| `created_by` | string \| null | 생성 주체 (admin user ID 등) |
| `metadata` | JSON \| null | 커스텀 메타데이터 |
| `created_at` | datetime | 생성 일시 |
| `updated_at` | datetime | 수정 일시 |
| `deleted_at` | datetime \| null | 소프트 삭제 일시 |

### 2.2 CustomerAddress (주소록)

Customer 에 등록된 배송지/청구지 목록.

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | string (PK) | 고유 식별자 |
| `address_name` | string \| null | 주소 별명 (예: "집", "직장") |
| `is_default_shipping` | boolean | 기본 배송지 여부 |
| `is_default_billing` | boolean | 기본 청구지 여부 |
| `company` | string \| null | 회사명 |
| `first_name` / `last_name` | string \| null | 수령인 이름 |
| `address_1` / `address_2` | string \| null | 도로명/상세 주소 |
| `city` | string \| null | 도시 |
| `country_code` | string \| null | 국가 코드 (예: `kr`) |
| `province` | string \| null | 도/시 (예: 경기도) |
| `postal_code` | string \| null | 우편번호 |
| `phone` | string \| null | 수령인 전화번호 |
| `metadata` | JSON \| null | 커스텀 메타데이터 |

### 2.3 CustomerGroup (고객 그룹)

고객을 묶어 가격·프로모션 적용 단위로 활용.

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | string (PK) | 고유 식별자 |
| `name` | string | 그룹명 (예: "VIP", "도매") |
| `created_by` | string \| null | 생성 주체 |
| `metadata` | JSON \| null | 커스텀 메타데이터 |

## 3. 엔티티 간 관계

```
Customer
  ├── 1:N ── addresses (CustomerAddress)
  └── N:N ── groups (CustomerGroup)
                └── N:N ── customers (역참조)
```

---

## 4. 주요 기능/유스케이스

1. **회원가입**: Auth 모듈에서 자격증명 생성 → Customer 레코드 연결
2. **프로필 관리**: 이름·이메일·전화번호 수정
3. **주소록 관리**: 배송지 추가/수정/삭제, 기본 배송지 지정
4. **고객 그룹 관리**: VIP·도매 등 그룹 분류 → 가격 규칙 연동
5. **비회원 주문**: `has_account = false` 고객 레코드로 주문 이력 관리

## 5. 대표 API 엔드포인트

### Admin API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/admin/customers` | 고객 목록 조회 |
| `POST` | `/admin/customers` | 고객 생성 |
| `GET` | `/admin/customers/:id` | 고객 단건 조회 |
| `POST` | `/admin/customers/:id` | 고객 정보 수정 |
| `DELETE` | `/admin/customers/:id` | 고객 삭제 |
| `GET/POST/DELETE` | `/admin/customers/:id/addresses` | 주소록 CRUD |
| `GET/POST` | `/admin/customer-groups` | 그룹 목록/생성 |
| `POST` | `/admin/customer-groups/:id/customers` | 그룹에 고객 추가 |

### Store API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/store/customers/me` | 내 정보 조회 |
| `POST` | `/store/customers/me` | 내 정보 수정 |
| `GET/POST/DELETE` | `/store/customers/me/addresses` | 내 주소록 CRUD |

## 6. 관련 워크플로우 / 이벤트

- `createCustomerWorkflow`: 고객 생성
- `updateCustomerWorkflow`: 고객 정보 수정
- `deleteCustomersWorkflow`: 고객 삭제
- `createCustomerAddressesWorkflow`: 주소 추가
- **이벤트**: `customer.created`, `customer.updated`

---

## 7. 이 프로젝트에서의 활용/확장 포인트

### 7.1 한국 법규 연동

- `Customer.metadata`: 마케팅 수신 동의 여부 (개인정보보호법 §22), 만 14세 미만 처리 여부 저장 가능
- 한국 전화번호 형식 (`010-XXXX-XXXX`): `phone` 필드 검증 레이어 필요 (추가 확인 필요)

### 7.2 회원 등급제 (한국 특화)

- `CustomerGroup` 으로 일반/VIP/VVIP 그룹 구성
- `PriceList` 모듈과 연동하여 그룹별 할인가 적용

### 7.3 개인정보 처리 방침

- GDPR 및 국내 개인정보보호법 준수: `deleted_at` 소프트 삭제 지원
- 고객 탈퇴 시 주문 이력 보존 + 개인정보 분리 보관 구현 필요 (추가 확인 필요)
