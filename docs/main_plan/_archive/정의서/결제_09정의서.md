# 결제(Payment) 도메인 정의서

> Medusa v2.15.3 | `@medusajs/payment` | 확인 경로: `node_modules/.pnpm/@medusajs+payment@2.15.3.../dist/models/`

---

## 1. 도메인 개요

결제 도메인은 주문의 금전적 트랜잭션 전체를 관리합니다.
PaymentCollection → PaymentSession → Payment 의 흐름으로 결제가 진행되며,
Stripe 등 PG 사 연동은 FulfillmentProvider 패턴과 유사한 PaymentProvider 인터페이스로 추상화됩니다.

이 프로젝트에서는 Stripe(`@medusajs/payment-stripe`) 가 기본 PG 로 설정됩니다.

## 3. 엔티티 간 관계

```
PaymentCollection
  ├── N:N ── payment_providers (PaymentProvider)
  ├── 1:N ── payment_sessions (PaymentSession)
  │             └── 1:1 ── payment (Payment)
  └── 1:N ── payments (Payment)
               ├── 1:N ── captures (Capture)
               └── 1:N ── refunds (Refund)
                           └── N:1 ── refund_reason (RefundReason)
```

---

## 4. 주요 기능/유스케이스

1. **결제 세션 생성**: PG 사에 결제 의도(PaymentIntent) 생성 → PaymentSession
2. **결제 승인**: PG 콜백 수신 → PaymentSession `authorized` 상태 전환
3. **결제 캡처**: 실제 청구 처리 → Capture 생성
4. **부분 캡처**: 여러 번의 Capture 로 분할 청구
5. **환불 처리**: Refund 생성 → PG 사 환불 API 호출
6. **결제 취소**: 미캡처 Payment 취소

## 5. 대표 API 엔드포인트

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/admin/payments` | 결제 목록 |

## 6. 이 프로젝트에서의 활용/확장 포인트

- **Stripe 연동**: `@medusajs/payment-stripe` 패키지 설치됨, KRW 지원 확인 필요 (추가 확인 필요)
- **청약철회 환불 기산점**: `RefundReason` + `WithdrawalReasonRecord.claimed_at` 기준 3영업일 이내 환불 의무 (전자상거래법 §18 ①)
- **상태머신 연동**: `state-machine` 모듈의 `StateHistory` 로 Payment 상태 전이 기록 (`domain = "payment"`)
- **한국 PG 연동**: 이니시스, KCP, 토스페이먼츠 등 한국 PG 사의 PaymentProvider 구현 필요 (추가 확인 필요)
