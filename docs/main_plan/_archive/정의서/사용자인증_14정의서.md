# 사용자/인증(User/Auth) 도메인 정의서

> Medusa v2.15.3 | `@medusajs/user` + `@medusajs/auth` | 확인 경로: `node_modules/.pnpm/@medusajs+user@2.15.3.../dist/models/`

---

## 1. 도메인 개요

Medusa v2 에서 사용자(User)와 인증(Auth)은 분리된 두 모듈입니다.

- **User 모듈**: 관리자 계정 프로필 (이름·이메일·아바타) 관리
- **Auth 모듈**: 자격증명(이메일/비밀번호, OAuth) 관리. 관리자(Admin)와 고객(Customer) 모두 Auth 모듈을 통해 인증

---

## 2. 핵심 데이터 모델(엔티티)과 주요 필드

### 2.1 User (관리자 사용자)

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | string (PK) | 고유 식별자 (prefix: `user_`) |
| `first_name` | string \| null | 이름 |
| `last_name` | string \| null | 성 |
| `email` | string | 이메일 (고유) |
| `avatar_url` | string \| null | 프로필 이미지 URL |
| `metadata` | JSON \| null | 커스텀 메타데이터 |
| `created_at` | datetime | 생성 일시 |
| `updated_at` | datetime | 수정 일시 |

### 2.2 Invite (초대)

관리자가 다른 사용자를 초대하는 레코드.

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | string (PK) | 고유 식별자 |
| `email` | string | 초대 대상 이메일 |
| `accepted` | boolean | 수락 여부 |
| `token` | string | 초대 토큰 |
| `expires_at` | datetime | 만료 일시 |
| `metadata` | JSON \| null | 커스텀 메타데이터 |

## 3. 인증 흐름

```
[Auth 모듈]
  ├── EmailPassProvider: 이메일/비밀번호 인증
  ├── GithubProvider: GitHub OAuth (관리자용)
  └── GoogleProvider: Google OAuth

인증 성공 → AuthIdentity 생성 (actor_type + provider + entity_id)
  ├── actor_type = "user" → User 모듈 연결 (관리자)
  └── actor_type = "customer" → Customer 모듈 연결 (고객)
```

---

## 4. 주요 기능/유스케이스

1. **관리자 계정 생성**: User 생성 + Auth Identity 등록
2. **관리자 초대**: Invite 토큰 발송 → 수락 → User 생성
3. **고객 로그인**: `/store/auth/customer/emailpass` → JWT 발급
4. **OAuth 로그인**: GitHub/Google Provider 사용
5. **RBAC (역할 기반 접근 제어)**: `feature-flag rbac` 활성화 시 (추가 확인 필요)

## 5. 대표 API 엔드포인트

### Admin API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET/POST` | `/admin/users` | 사용자 목록/생성 |
| `GET/POST/DELETE` | `/admin/users/:id` | 단건 관리 |
| `GET/POST` | `/admin/invites` | 초대 목록/발송 |
| `POST` | `/admin/invites/:id/accept` | 초대 수락 |

### Auth API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `POST` | `/auth/user/emailpass` | 관리자 로그인 |
| `POST` | `/store/auth/customer/emailpass` | 고객 로그인 |
| `POST` | `/auth/user/emailpass/register` | 고객 회원가입 |
| `POST` | `/auth/session` | 세션 갱신 |

---

## 6. 이 프로젝트에서의 활용/확장 포인트

- 고객 회원가입 시 이메일 인증 플로우 (Notification 모듈 연동)
- 소셜 로그인 (카카오·네이버) 연동: 커스텀 AuthProvider 구현 필요 (추가 확인 필요)
- JWT 만료 시간 설정: 한국 금융감독원 권고 기준 적용 고려
