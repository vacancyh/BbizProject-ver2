# QA-KR-001 = 청약철회 7일 자동 승인

**출처**: `main_plan/이식설계/스프리_RMA_이식.md` §6.1-6.4 (`legal-kr/withdrawal-7day` 모듈)
**근거 법령**: 전자상거래 등에서의 소비자보호에 관한 법률 §17 ① / §17 ② / §17 ③ / §18 ①
**우선순위**: P1 (필수, 한국 D2C 의무)

---

## 사전 조건

- `legal-kr/withdrawal-7day` 모듈 활성화
- `rma-extension` 모듈 활성화 + `ReturnsPolicy` 시드 (`withdrawal_period_days = 7`)
- Return Reasons 시드 = `customer_change_of_mind` / `product_defect` / `wrong_delivery` / `other`
- 배송 완료된 주문 1건 (`delivery.delivered` 이벤트 발행)

---

## 시나리오 단계

### 1. delivered_at 기산점 등록

- qa_014 의 "Mark as delivered" 실행
- `delivery.delivered` event 발행 -> `legal-kr/withdrawal-7day/subscribers/on-order-completed.ts` 또는 `on-delivery-delivered.ts` 가 `WithdrawalEligibility` row 자동 생성
  - `delivered_at` = 현 시각
  - `withdrawal_deadline` = `delivered_at + 7일`
  - `is_eligible` = true (기본)

### 2. 7일 내 청약철회 (단순변심)

1. delivered_at + 1일 시점 (영업일·공휴일 포함, 달력 7일)
2. Storefront 또는 Admin 에서 Return 생성
3. 사유 = `customer_change_of_mind` (단순변심)
4. `return.requested` event 발행 -> `on-return-requested.ts` subscriber 의 `autoApproveIfEligible(return_id)` 호출
5. 검증:
   - `WithdrawalKrService.validateKoreanWithdrawal` -> `{ eligible: true, reason: "customer_change_of_mind", shipping_fee_bearer: "customer" }`
   - `Return.status = approved` 자동 전이 (관리자 개입 X)
   - `ReturnShippingFeePolicy.bearer = customer` -> 환불 금액에서 반품 배송비 차감

### 3. 7일 초과 청약철회 (단순변심)

1. delivered_at + 8일 시점
2. Return 생성, 사유 = `customer_change_of_mind`
3. 검증:
   - `WithdrawalKrService.validateKoreanWithdrawal` -> `{ eligible: false, reason: "deadline_exceeded" }`
   - `Return.status = requested` (수동 검수 필요, 자동 승인 X)
   - 관리자가 정책 따라 reject 또는 special approve

### 4. 사업자 귀책 (상품불량 / 오배송) = 청약철회 적용

1. delivered_at + 1일 시점, 사유 = `product_defect`
2. 검증:
   - `validateKoreanWithdrawal` -> `{ eligible: true, reason: "product_defect", shipping_fee_bearer: "merchant" }`
   - `Return.status = approved` 자동
   - `ReturnShippingFeePolicy.bearer = merchant` -> 환불 금액에 배송비 가산 (전액 환불)
3. 사유 = `wrong_delivery` 도 동일하게 사업자 부담

### 5. 환불 timing (영업일 3일)

- 전자상거래법 §18 ① 인용: "사업자는 청약철회 통지 받은 날로부터 영업일 기준 3일 이내 환불 의무"
- `WithdrawalKrService.scheduleRefundDeadline(return_id)` 호출 -> 영업일 3일 후 deadline 산출 (주말 / 공휴일 제외)
- Scheduled job 으로 deadline 임박 시 관리자 알림
- Deadline 초과 시 §18 ② 지연이자 hook 트리거

### 6. 청약철회 예외 (전자상거래법 §17 ② 단서)

- 소비자 책임으로 멸실·훼손 -> `is_eligible = false`
- 사용·소비로 가치 현저히 감소 (예: 귀걸이 시착 후 위생 문제) -> `is_eligible = false`
- 시간 경과로 재판매 곤란 (jewelry 영역에선 한정) -> `is_eligible = false`
- 복제 가능한 디지털 콘텐츠 -> N/A (jewelry shop)

---

## PASS 기준

- `WithdrawalEligibility` row 자동 생성 (delivered_at 시점)
- 7일 내 + 적격 사유 -> `Return.status = approved` 자동 전이
- 7일 초과 또는 부적격 -> 자동 승인 차단, manual 처리
- `ReturnShippingFeePolicy.bearer` 정합 (단순변심 = customer, 불량/오배송 = merchant)
- 환불 deadline = 영업일 3일 = scheduled job 동작
- 한국 공휴일 데이터 활용 (영업일 계산)

## FAIL 케이스 (박제)

| 케이스 | 예상 결과 |
|---|---|
| `delivered_at` 미설정 (Mark as delivered 누락) | `WithdrawalEligibility` 미생성 = 청약철회 불가 |
| `withdrawal_deadline` 컬럼 = null | `validateKoreanWithdrawal` 실패 |
| 사유 enum invalid | reject (4가지 + `other` 만 허용) |
| 영업일 3일 환불 누락 | §18 ② 지연이자 hook 트리거 (alert) |
| 사용·소비 후 청약철회 (jewelry 시착) | manual 검수, `is_eligible = false` 가능 |
