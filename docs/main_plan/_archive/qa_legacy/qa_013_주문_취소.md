# QA-013 = 주문 취소 (Cancel Order)

**출처**: `메두사_www_apps_user-guide_app_orders_manage_page.mdx` §Cancel an Order
**한국 모듈 연동**: `state-machine` (Cancelled state 전이)
**우선순위**: P1 (필수)

---

## 사전 조건

- 테스트 주문 1건 (fulfillment 미진행 / 미배송 상태)
- Admin 로그인

---

## 시나리오 단계 (메두사 user-guide 원문 인용)

user-guide 인용: "You can cancel an order if no items have been fulfilled. Canceling an order will: Change the order's status to canceled. Refund any captured payments. Cancel any authorized payment. Notify the customer about the cancellation."

### 1. 주문 취소

1. 주문 상세 -> 첫 섹션 (주문 번호) 헤더 EllipsisHorizontal
2. "Cancel" 클릭
3. 팝업 "Continue" 클릭 confirm

### 2. 사후 검증

- `order.status = canceled`
- Captured payment -> 자동 refund 트리거
- Authorized payment -> 자동 cancel
- 고객 이메일 알림 발송

---

## PASS 기준

- `order.status` = canceled
- `order.canceled_at` timestamp 갱신
- Reservation 자동 해제 (재고 복구)
- Payment refund 자동 트리거 -> `payment.captured_amount` 환불
- 알림 발송

---

## FAIL 케이스 (박제)

| 케이스 | 예상 결과 |
|---|---|
| 이미 fulfilled 된 주문 취소 | user-guide 인용: "If the order has been paid for or fulfilled, you'll receive an error message preventing you from canceling the order." |
| Cancel 된 주문 재취소 | 차단 (이미 cancelled) |
| Refund 실패 (PG 응답 지연) | 주문은 cancelled 이지만 환불 pending 상태 별도 추적 필요 |

---

## 한국 모듈 연동 검증

- `state-machine` Order = `Cancelled` state 전이
- 벤듀어 형 가드: `Shipped` / `Delivered` 상태에서 `Cancelled` 전이 차단 검증
- 한국 청약철회와 구분: 본 시나리오는 **배송 전 취소** (전자상거래법 §17 청약철회와 다름)
