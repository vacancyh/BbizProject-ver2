# 기획 가이드 (S0 작업 흐름 표준)

본 가이드는 모든 프로젝트의 S0 (기획) 단계 작업 흐름을 정의합니다. 신설일: 2026-05-23.

## 6단계 작업 흐름 (사장님 verbatim 2026-05-23)

> "1.내가 user_plan 에 1차 기획 문서 넣는다.
> 2.상세기획서 main_plan 만든다.
> 3.task 작성한다.
> 4.task별 스토리보드 만든다.
> 5.task 별 단위 테스트 문서 만든다.
> 6.task 별 qa문서 만든다.
> 기존에는 에이전트에게 문서 작성을 맡겼지만, 그건 시기상조 같아.. 우리 에이전트는 순수 개발 에이전트로 간다."

| # | 단계 | 담당 | 형식 | 산출물 위치 |
|---|---|---|---|---|
| 1 | 1차 기획 | 사장님 단독 | .md | `main_plan/user_plan/<프로젝트>_요구사항.md` |
| 2 | 상세 기획서 | 사장님 + main | .md | `main_plan/plan.md` |
| 3 | task 작성 | 사장님 + main | .md | `main_plan/task/task_index.md` + `task_001~NNN_<주제>.md` |
| 4 | task별 스토리보드 | **main + 사장님 협업** | .md | `main_plan/storyboard/story_001~NNN_<주제>.md` (★ new- sub-agent 소비용 표준) |
| 4-옵션 | Word storyboard | ★ **사장님 별도 명령 시만** | .docx | `main_plan/storyboard/story_001~NNN_<주제>.docx` |
| 5 | task별 단위 테스트 | 사장님 + main | .md | `main_plan/unit_test/unit_001~NNN_<주제>.md` |
| 6 | task별 QA | 사장님 + main | .md | `main_plan/qa/qa_001~NNN_<주제>.md` |

## main_plan/ 5 폴더 + plan.md 구조

```
main_plan/
├── plan.md                                  # 2단계 상세 기획서
├── user_plan/<프로젝트>_요구사항.md          # 1단계 사장님 원본 요구
├── task/
│   ├── task_index.md                         # task 인덱스 (선후관계 / blocker 포함)
│   └── task_001_*.md ~ task_NNN_*.md         # 각 task 상세
├── storyboard/
│   ├── story_001_*.md ~ story_NNN_*.md       # 4단계 main+사장님 협업 (★ new- 소비용 표준)
│   └── story_001_*.docx ~ story_NNN_*.docx   # 4-옵션 사장님 별도 명령 시만 생성
├── unit_test/
│   └── unit_001_*.md ~ unit_NNN_*.md         # 5단계 단위 테스트 문서
└── qa/
    └── qa_001_*.md ~ qa_NNN_*.md             # 6단계 QA 문서
```

## task 분할 룰 (사장님 verbatim 2026-05-23)

> "task 가 결국 단위 테스트 단위로... 우린 단위 테스트를 기능별로 쪼개지 않고, **업무별로 쪼갤꺼야**.. 기능별로 쪼개면 너무 많아져서 감당이 안돼."

- task 분할 단위 = **업무별** (기능별 X)
- task 간 의존성 = `task_index.md` 에 명시 (선후관계 / blocker 표시)
- 1 task = 1 storyboard + 1 unit_test + 1 qa (1:1:1:1 매핑)

## task 간 연계 룰 (사장님 verbatim 2026-05-23)

> "task별 문서 작성 시 task간 연계를 어떻게 하는지가 중요... task 는 프로젝트별 상이.. 내가 너한테 기획서 토대로 만들어 명령 주고 검수 > 수정"

- task 간 의존성 / 공유 자원 / 데이터 흐름 = `task_index.md` 에 명시
- main 은 사장님 명령 받아 작성 → 사장님 검수 → 수정 사이클

## 에이전트 = 순수 개발 (사장님 verbatim 2026-05-23)

> "기존에는 에이전트에게 문서 작성을 맡겼지만, 그건 시기상조 같아.. 우리 에이전트는 순수 개발 에이전트로 간다."

- 기존: 에이전트에게 문서 작성 위임 → 시기상조 → 폐기
- 현재: 모든 기획 문서 (S0 산출물) = 사장님 (+ main) 작성
- 에이전트 (new-pm 외 15개 sub-agent) = **순수 개발만**
- 에이전트 진입 = 1~6 단계 완료 후 (new-pm 오케스트레이터 dispatch)

## new 파이프라인 진입 사전 조건

- `main_plan/plan.md` 존재 (비어있지 않음)
- `main_plan/task/task_index.md` 존재 (task 1건 이상)
- 미존재 시 즉시 BLOCKED (new-pm 진입 거부)

## 파일명 규칙

- 모든 task / storyboard / unit_test / qa 파일명 = `<유형>_NNN_<주제>.<확장자>`
  - 예: `task_004_케어세션.md`, `story_004_케어세션.md`, `unit_004_케어세션.md`, `qa_004_케어세션.md` (★ `story_004_케어세션.docx` = 사장님 별도 명령 시만 추가 생성)
- NNN = 3 자리 zero-pad (001 ~ 999)
- 주제 = task_index.md 의 task 명 그대로 (한글 가능)

## 위치 표준

- 적용 위치 = `{project}/0dev_haness_agents/main_plan/`

- main 이 `main_plan/` 외 영역에 S0 산출물 작성 → 메타룰 v2 위반
- 에이전트가 `main_plan/` 안 문서 작성 → §V0 위반 (재발 방지 의무)
- 1~6 단계 건너뛰고 new 파이프라인 진입 → BLOCKED
