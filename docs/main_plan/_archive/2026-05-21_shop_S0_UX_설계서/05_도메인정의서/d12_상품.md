## 1. 도메인 개요·책임 범위

- **1줄 책임**: 상품 CRUD·옵션·재고·이미지·검색·타임세일·재고 동시성
- **포지션**: 트래픽이 가장 집중되는 도메인. 카탈로그 조회 (캐시 친화) + 재고/주문 흐름 (강한 동시성·정합성) 두 축을 동시에 책임.
- **핵심 가치**: (1) 옵션 SKU 단위 정확한 재고 표시 (2) 동시 주문 시 음수 재고·중복 차감 0건 (3) 타임세일·쿠폰 동시 진행 시 가격 정합.
- **책임 경계 (out)**: 주문 트랜잭션·결제 차감은 order/payment 도메인. 본 도메인은 **재고 차감/복구 API**와 **이벤트 발행**만 책임. 리뷰·문의는 review 도메인. 위시리스트는 wishlist 도메인 (본 도메인은 `product.restocked` 이벤트 발행만).

## 2. 핵심 엔티티

### 2.1 products (상품 본체)

| 필드 | 타입 | 제약 | 비고 |
|---|---|---|---|
| id | VARCHAR(21) | PK (nanoid) | |
| name | VARCHAR(200) | NOT NULL | |
| slug | VARCHAR(200) | UNIQUE NOT NULL | URL용 영문 슬러그 |
| category_id | UUID | FK → categories.id NOT NULL | |
| price | DECIMAL(10,0) | NOT NULL | 판매가 |
| original_price | DECIMAL(10,0) | NULL | 원가 (판매가 < 원가 차단용, PRD-A-002) |
| status | ENUM | NOT NULL DEFAULT 'draft' | draft / active / sold_out / discontinued / hidden |
| description | TEXT | NULL | |
| brand | VARCHAR(100) | NULL | |
| gender | ENUM | NULL | F / M / U |
| view_count | BIGINT | DEFAULT 0 | 통계 캐시 |
| sales_count | BIGINT | DEFAULT 0 | 통계 캐시 (BEST 자동 산정용) |
| purchase_limit_per_member | INT | NULL | 1인당 구매 수량 제한 (PRD-A-047) |
| created_at | TIMESTAMPTZ | NOT NULL | |
| updated_at | TIMESTAMPTZ | NOT NULL | |
| deleted_at | TIMESTAMPTZ | NULL | 소프트 삭제 (PRD-A-005) |

**파생 필드** (응답 시 계산):
- `is_new` = `now - created_at < NEW 노출 기간 (P-NEW)` (PRD-A-028)
- `is_best` = `sales_count` 상위 N% 포함 여부 (PRD-A-029)
- `is_sale` = 진행 중 time_sales 존재 여부

**인덱스**: `idx_slug`, `idx_category_status`, `idx_status_created_at`, `idx_sales_count`, `idx_deleted_at`

### 2.2 product_options (옵션 축)

| 필드 | 타입 | 제약 |
|---|---|---|
| id | UUID | PK |
| product_id | VARCHAR(21) | FK → products.id |
| type | ENUM | color / size |
| name | VARCHAR(50) | NOT NULL (예: "색상") |
| value | VARCHAR(50) | NOT NULL (예: "블랙") |
| additional_price | DECIMAL(10,0) | DEFAULT 0 |
| display_order | INT | DEFAULT 0 |

**제약**: `UNIQUE(product_id, type, value)`. **현 MVP는 2차 옵션까지** (`색상 × 사이즈`, §8 참조).

### 2.3 product_skus (옵션 조합 SKU)

| 필드 | 타입 | 제약 |
|---|---|---|
| id | UUID | PK |
| product_id | VARCHAR(21) | FK |
| option_combo | JSONB | NOT NULL (예: `{"color":"블랙","size":"M"}`) |
| stock | INT | NOT NULL CHECK (stock >= 0) |
| sku_code | VARCHAR(50) | UNIQUE NULL |
| created_at | TIMESTAMPTZ | NOT NULL |

**핵심 제약**: `CHECK (stock >= 0)` — 음수 재고 DB 레벨 차단 (PRD-A-052). 옵션 조합 단위 재고 (PRD-U-012/012B).
**인덱스**: `idx_product_id`, `UNIQUE(product_id, option_combo)`.

### 2.4 product_images

| 필드 | 타입 | 제약 |
|---|---|---|
| id | UUID | PK |
| product_id | VARCHAR(21) | FK |

| alt | VARCHAR(200) | NOT NULL (접근성, PRD-U-030) |
| display_order | INT | DEFAULT 0 |
| is_main | BOOLEAN | DEFAULT FALSE |

**제약**: 상품당 최대 10장 (PRD-A-008). 대표 이미지 1개 필수 (PRD-A-003, status='active' 전환 시).

### 6.4 SKU·라인 분산 락 표준 (Tier2 §3.1 — F1·F2 구현 표준)

> 기존 F1 (`stock >= 0` + 비관락 OR Redis 분산 락)·F2 (옵션별 독립 락) 룰의 구체 구현 표준을 박제. "둘 중 하나" 모호성을 3 Layer 표준으로 명확화.

| Layer | 메커니즘 | 사용 시점 | 키 패턴 |
|---|---|---|---|
| **Layer 1: DB 비관락** | `SELECT FOR UPDATE` | 결제 승인 webhook 단일 트랜잭션 내 정합성 (≤ 2초) | (직접 row 락) |
| **Layer 2: Redis 분산 락 (Redlock)** | `SET NX PX <ttl>` + auto-extend | 트랜잭션 경계 외 중복 차단 — 동일 라인 반품·교환 / 부분 환불 N회 동시성 / 다건 교환 그룹 | `sku_lock:{sku_id}` / `line_action_lock:{order_item_id}` / `refund_lock:{payment_id}` |
| **Layer 3: DB UNIQUE 제약 (마지막 안전망)** | UNIQUE INDEX | 라인 단위 중복 액션·멱등 sub-key·webhook dedupe | `UNIQUE(order_item_id, action_type)` / `UNIQUE(refunds.idempotency_sub_key)` / `UNIQUE(payment_webhooks.dedupe_key)` |

#### 6.4.1 분산 락 룰 (신규)

| # | 룰 | 적용 |
|---|---|---|
| F-LOCK-01 | DB 비관락 = 단일 트랜잭션 내 SKU·라인 정합성 (≤ 2초) | 결제·환불 트랜잭션 |
| F-LOCK-02 | Redis 분산 락 = 트랜잭션 경계 외 중복 차단 (TTL 5초 + auto-extend, max 30초) | 라인 액션·다건 교환 |
| F-LOCK-03 | DB UNIQUE 제약 = 마지막 안전망 (모든 멱등성 sub_key) | 멱등 보장 |
| F-LOCK-04 | Redlock acquire 실패 = 100ms backoff × 3회 → 409 응답 | 분산 락 영역 |
| F-LOCK-05 | 락 release = 본인 소유 확인 후만 (Lua script atomic check-and-delete) | 모든 락 |
| F-LOCK-06 | 락 누수 방지 = TTL 강제 (auto-extend 최대 30초) | 모든 락 |

#### 6.4.2 격리 수준 (Tier2 §3.3)

| 트랜잭션 | 격리 수준 | 사유 |
|---|---|---|
| 결제 승인 webhook (재고 차감) | SERIALIZABLE | 재고 차감 race + 환불 race 모두 차단 (d17 §F-PAY 결합) |
| 카트 UPSERT (담기) | READ COMMITTED + UNIQUE(cart_id, sku_id) | 동일 sku_id 합산 UPSERT atomic |
| 상품 조회 (목록·상세) | READ COMMITTED | 읽기 위주 + ISR 캐시 |
| 재고 수동 조정 (PRD-A-010) | REPEATABLE READ | 관리자 작업, 중간값 오염 방지 |
| 자동취소 배치 (재고 복구) | SERIALIZABLE | 사용자 수동 취소 race 차단 |

#### 6.4.3 데드락 방지 락 순서 (Tier2 §3.7)

본 도메인이 락을 거는 테이블의 알파벳 정렬 순위 (멀티 락 시 본 순서 준수):

`coupon_issues → order_items → orders → payments → points → product_skus → refunds`

- 동일 테이블 다중 SKU 락 시 = `sku_id` UUID 정렬 후 `SELECT FOR UPDATE`
- PostgreSQL 데드락 감지 (40P01) 시 자동 재시도 1회

#### 6.4.4 낙관락 충돌 재시도 (Tier2 §3.2)

`product_skus`에는 현재 낙관락 version 컬럼 없음 — 본 도메인은 비관락(SELECT FOR UPDATE) 중심. 단, `time_sales.current_sold` 카운터 갱신 시 낙관락 적용:

- F-OPTLOCK-01: `time_sales.current_sold` 갱신 시 version 비교 (시스템 race) → 자동 재시도 50ms × 2회
- F-OPTLOCK-02: 재시도 후 충돌 시 422 SALE_RACE 응답
