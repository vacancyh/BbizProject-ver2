## 1. 도메인 개요·책임 범위

- **1줄 책임**: 관리자 계정·권한·시스템 정책·감사 로그·시스템 헬스 — **모든 도메인의 정책 변경 1차 진입점**.
- **포지션**: **다른 11개 도메인 모두에 의존** (참조 도메인). 다른 도메인의 정책·감사·계정 인프라를 제공하는 **횡단(cross-cutting) 도메인**.
- **양방향 매핑 정의 근거**: `00_개요.md §2 #3` "프론트 기능 = 관리자에서 컨트롤" 룰은 본 도메인이 관리자 페이지(s35~s49) + 시스템 정책 저장소(SystemPolicy)를 제공함으로써 실현됩니다.
- **s49 정책 결정 (I-01)**: 정보구조 `02_정보구조.md §8.1 I-01`에 따라 **관리자 계정·감사 로그·시스템 헬스 = s49 1 페이지로 통합** (SUPER 전용) — 사용 빈도 낮음.
- **보안 분리 원칙**: 관리자 인증·세션·DB pool = 사용자 영역과 **완전 분리**. JWT Secret 별도 (A-AUTH-017), 별도 DB pool, 별도 로그 스트림.
- **책임 경계 (out)**: 각 도메인의 비즈니스 룰 실행 자체는 해당 도메인 (본 도메인은 정책 저장 + 변경 API + 감사 박제만). 알림 발송은 notification 도메인.

### 2.7C outbox (이벤트 발행 보장 — Tier2 §3.6 신규, 횡단 단일 위치)

> at-least-once 이벤트 발행 패턴. 비즈니스 트랜잭션 내 INSERT → 별도 worker가 polling 후 dispatch. 모든 도메인 (d11~d20)이 본 테이블을 공유 사용 (중복 정의 X).

| 필드 | 타입 | 제약 |
|---|---|---|
| id | UUID | PK |
| event_type | VARCHAR(64) | NOT NULL | (예: `order.partial_cancelled` / `payment.refunded` / `delivery.delivered`) |
| aggregate_type | VARCHAR(40) | NOT NULL | order / payment / product / member / delivery 등 |
| aggregate_id | VARCHAR(64) | NOT NULL | aggregate ID (UUID 또는 도메인 PK) |
| payload | JSONB | NOT NULL | 이벤트 페이로드 (라인 N건 포함 시 items[] 배열) |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |
| processed_at | TIMESTAMPTZ | NULL | dispatch 완료 시 SET (멱등 보장) |
| retry_count | INTEGER | NOT NULL DEFAULT 0 | |
| last_error | TEXT | NULL | |
| next_retry_at | TIMESTAMPTZ | NULL | exponential backoff 다음 시도 시각 |

**인덱스**: `idx_outbox_processing` = `(processed_at, next_retry_at) WHERE processed_at IS NULL` — worker polling용.

**룰 (Tier2 §3.6 + §3.10)**:
- F-OUTBOX-01: 모든 이벤트 발행 = outbox 패턴 (in-transaction direct publish 금지) — `publish_outbox(event_type, payload)` 함수가 본 테이블 INSERT
- F-OUTBOX-02: outbox INSERT = 비즈니스 트랜잭션 일부 (commit과 함께 보장)
- F-OUTBOX-03: outbox worker = `SELECT ... FOR UPDATE SKIP LOCKED LIMIT 100` (다중 worker 안전)
- F-OUTBOX-04: 실패 시 exponential backoff (1s → 2s → 4s → 8s → 16s)
- F-OUTBOX-05: 5회 초과 = DLQ 이동 + 운영 알람 (Slack #ops)
- F-OUTBOX-06: 이벤트 소비자 = 멱등 처리 (`processed_events` 테이블에 event_id UNIQUE)
- F-OUTBOX-07: outbox 정리 배치 = `processed_at` 7일 경과 row 삭제 (성능)
- F-EVENT-01: 발행 = at-least-once
- F-EVENT-02: 소비 = 멱등 (event_id UNIQUE)
- F-EVENT-03: 같은 aggregate (예: `order_id`) 순서 보장 = aggregate_id 기반 partition (FIFO queue)
- F-EVENT-04: DLQ = 5회 실패 후 + 운영 알람

## 9. QA 추적

### 9.1 관리자 시나리오 (`쇼핑몰_전용_QA_v4.md §11 ⚙️ Admin 전용`) — ★ 2026-05-22~23 전면 정정

> v0.1 박제 시 사용한 가상 prefix(ADM-A-* / AUD-A-* / SYS-A-*)는 v4 §11에 존재하지 않음. v4 §11 실제 prefix 8종으로 재정정.

- **ADM-D 대시보드**: ADM-D-001 ~ ADM-D-005 (5건) — 매출·주문·신규회원·처리 필요 항목·그래프·실시간 알림·새로고침
- **ADM-N 공지사항**: ADM-N-001 ~ ADM-N-005 (5건) — 등록·수정·노출순서·기간 종료 자동 비노출·긴급 공지 고정
- **ADM-F FAQ**: ADM-F-001 ~ ADM-F-005 (5건) — 등록·수정·노출순서·고객 페이지 반영·카테고리 관리
- **ADM-B 배너·팝업**: ADM-B-001 ~ ADM-B-007 (7건) — 메인 배너 CRUD + 팝업 + '오늘 하루 안 보기' + SVG 악성 스크립트 검증 + 상단 공지 띠
- **ADM-M 마케팅 이메일·SMS·알림톡**: ADM-M-001 ~ ADM-M-012 (12건) — 발송 대상 필터·예약·야간 차단·광고 prefix·List-Unsubscribe·수신거부 스킵·SMS·카카오 알림톡 정책
- **ADM-P 회원 제재**: ADM-P-001 ~ ADM-P-008 (8건) — 단계별 제재(경고·7일·30일·영구)·이력·블랙리스트·본인 차단 차단·CS 메모

- **ADM-S 시스템 설정**: ADM-S-001 ~ ADM-S-011 (11건) — DB/Redis 헬스·Redis degraded·캐시 초기화·약관 관리·점검 모드·출석체크 포인트·연속 출석·매출 리포트·CS 통합 이력
- **합계**: 5 + 5 + 5 + 7 + 12 + 8 + 10 + 11 = **57건**
