|---|---|
| **초기 (회원 진입)** | 기본 배송지 자동 채움. 카트·쿠폰·포인트 데이터 fetch 후 정상 표시 |

| **포인트 입력 중** | onChange debounce 300ms 후 요약 카드 갱신. 50% 초과 입력 시 자동 클램프 + 캡션 "결제금액의 50%까지만 사용 가능해요" |

| E-010 | 포인트 100% 사용 (0원 결제) | §4 "포인트 100% 사용" 처리 — PG 미호출 (PAY-U-017B) |
| E-014 | 카테고리 한정 쿠폰 + 해당 카테고리 상품 미포함 | 쿠폰 드롭다운에서 회색 비활성 + 캡션 "특정 카테고리 상품에만 사용 가능해요" |

| **다음 우편번호 모달 차단 (광고 차단기)** | fallback: 수동 주소 입력 모드 + 안내 "팝업이 차단된 경우 직접 입력해주셔요" |

### 6.2 API 면 (가설 — Phase 4 기능정의서에서 확정)

| 엔드포인트 | 메서드 | 응답 | 캐시 |
|---|---|---|---|
| `/api/checkout/init` | GET | `{ cart_snapshot, addresses, available_coupons, point_balance, terms_version }`. 페이지 진입 시 1회 호출 | no cache |
| `/api/me/addresses` | GET / POST / PATCH / DELETE | 배송지 CRUD. POST 시 `is_default` 처리 | no cache |
| `/api/coupons/validate` | POST | body: `{ coupon_id, cart_id }`. 응답 `{ ok, discount, message }` | no cache |
| `/api/checkout/calculate` | POST | body: `{ cart_id, coupon_id?, point?, gift_wrap? }`. 응답 `{ subtotal, coupon, point, ship, gift, total, reward }`. 4-way 검증의 서버 권위 | no cache |

### 6.3 4-way 금액 검증 (필수)

| 단계 | 위치 | 비교 대상 |
|---|---|---|
| (1) Client 계산 | 브라우저 (요약 카드 표시) | 사용자 경험용 |
| (2) Server 계산 | `/api/checkout/calculate` | 권위 |
| (3) Order 저장 | `/api/orders` 시점 | DB 박제 |
| (4) PG 결제 금액 | 토스 결제창·콜백 | (3) 과 일치 검증 |

**4 값 모두 일치해야 결제 성공.** 1개라도 불일치 시 결제 차단 + 에러 로그 + 모달 "금액 검증에 실패했어요. 다시 시도해주셔요"

### 6.4 다건 라인 변동 시 PaymentIntent 재발급 룰 (Tier 1 §3.E)

본 화면에서 사용자가 결제 진입 후 라인 변동 (수량 ±, 옵션 변경, 쿠폰·포인트·기프트 옵션 변경) 시 토스 결제창에 이전 금액이 전달될 위험 (`AMOUNT_MISMATCH`) 차단 룰.

| 단계 | 동작 |
|---|---|
| (1) 주문서 진입 시 | `cart_payload_hash` 산출 (selected `item_ids` + `qty` + `coupon_id` + `point_used` + `gift_wrap` 조합 해시). 서버에 `POST /api/payments/intent` 호출하여 `PaymentIntent` (토스 `orderId`) 생성 |
| (2) 라인 변경 감지 | 사용자가 쿠폰·포인트·기프트 옵션 변경 시 `cart_payload_hash` 재계산. 변경 감지 시 자동으로 다음 (3) 실행 |
| (3) PaymentIntent 무효화 + 재발급 | (a) 기존 `PaymentIntent` 폐기 (`POST /api/payments/intent/{id}/invalidate`) (b) 새 `expected_amount` 산출 + 4-way 재검증 (c) 새 `Idempotency-Key` 발급 + 새 `PaymentIntent` 생성 |
| (4) [결제하기 →] 클릭 시 | `cart_payload_hash` 최종 검증 → mismatch 시 422 `PAYMENT_INTENT_STALE` → 토스트 "주문 정보가 변경되었어요. 결제 금액을 다시 확인해주세요" + 요약 카드 자동 갱신 + CTA 다시 활성 |
| (5) 토스 결제창 호출 | 새 `orderId` + 새 `amount` 전달. 토스 `orderId` 재사용 금지 (1회용 — F-PAY-04 보강) |

**룰 보강**:
- 다건 라인 변동 시 PaymentIntent 재발급 의무 (`cart_payload_hash` 검증)
- 토스 `orderId` 재사용 금지 (orderId 1회용)
- 같은 카트에 대해 동시 결제 진행 차단 (다른 탭 결제 진행 중 cart_snapshot lock — 본 화면 §5 "다른 탭에서 카트 변경" 케이스 보강)
