## 5. 예외·엣지 케이스

- **이벤트 콘텐츠에 외부 이미지 URL 사용** → CSP 화이트리스트 정책 (A-NET-005). 관리자가 외부 URL 입력 시 등록 단계에서 차단 또는 CDN 프록시 권장
- **이벤트 본문에 외부 링크 (`<a href>`)** → `rel="noopener noreferrer"` 자동 부여 + `target="_blank"` 허용
- **연계 쿠폰 발급 후 즉시 결제 시도** → s28 쿠폰함 → s17 카트 → s18 결제 흐름 보존 (별도 처리 없음)
- **연계 상품 비활성화 (관리자 즉시 비노출)** → ISR 1h 캐시 한계 / 카드 클릭 시 상품 상세에서 "판매 종료" 표시 (트레이드오프, E-015와 동일)
- **이벤트 본문 XSS 시도** → DOMPurify sanitize + 관리자 등록 시 서버 측 이중 sanitize (A-INJ-002 Stored XSS 방어)
- **SNS 공유 카카오 SDK 로드 실패** → 카카오 버튼만 비활성, 나머지 3종(페북·트위터·링크복사) 정상 동작
- **링크 복사 (navigator.clipboard) HTTPS 미적용 시** → fallback (textarea + execCommand) — HTTPS 강제(A-NET-001)로 사실상 미발생
- **종료된 이벤트 deep link 인입** → 정상 노출 (SEO 누적 + 히스토리), 단 쿠폰 발급 버튼 비활성
- **연계 쿠폰 발급 후 환불 시** → 쿠폰 자동 복원 (d20 PNT-S-009) — 본 화면은 미관여
- **이벤트 슬러그 중복 시도 (관리자)** → 관리자 등록 단계에서 슬러그 unique 검증 (본 화면 무관)

## 8. SEO · 접근성 · 성능

### 8.1 SEO
- `<title>`: "[이벤트명] | LUMI 이벤트"
- `<meta name="description">`: 이벤트 한줄 카피 (관리자 입력 `summary` 필드, 50~150자)
- OG: image (Hero 이미지) · title · description · type=article
- JSON-LD `Event` 스키마: name · startDate · endDate · location (online) · image · description · offers (연계 쿠폰 있을 경우)
- canonical: `/events/[slug]` (탭 파라미터 X)
- sitemap.xml에 자동 포함 (A-COMP-007)
- robots: `index, follow` (종료 이벤트도 인덱싱 유지)

### 8.2 접근성 (WCAG AA / KWCAG 2.2)
- Hero 이미지 `alt` 필수 (관리자 입력 + fallback = 이벤트명)
- 본문 이미지 `alt` (관리자가 등록 시 필수 입력 검증)
- H1 단일 / 본문은 H2·H3 위계 사용
- SNS 공유 버튼 = `aria-label` 명시 ("카카오톡으로 공유")
- [쿠폰 받기] 버튼 = `aria-disabled` (비활성 시) + 텍스트로도 상태 표시
- 키보드 Tab 순서: Breadcrumb → Hero → SNS 공유 → 본문 → 쿠폰 버튼 → 상품 카드 → 관련 이벤트

### 8.3 성능 (Core Web Vitals)

| 지표 | 목표 | 전략 |
|---|---|---|
| LCP | ≤ 2.5s | Hero 이미지 `priority` + WebP/AVIF |
| INP | ≤ 200ms | 쿠폰 발급 = 클라이언트 단일 POST (낙관적 UI 옵션 검토) |
| CLS | ≤ 0.1 | Hero `aspect-ratio: 16/9` / 카드 이미지 `aspect-ratio: 1/1` |

- 본문 이미지 lazy loading
- 폰트 = 본문은 시스템 폰트 + 헤드라인만 Cormorant Garamond (display: swap)

## 9. 디자인 트랙 연동

- LUMI 시안 미보유 → **디자인 트랙 Sprint 1+ 위임**

  - Hero 비율 (16:9 vs 3:2 vs 4:3)
  - 연계 쿠폰 카드 디자인 (티켓 모양 vs 카드 박스)
