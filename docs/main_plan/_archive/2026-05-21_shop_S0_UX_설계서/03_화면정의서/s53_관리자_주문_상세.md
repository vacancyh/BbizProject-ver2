## 1. 개요

| 항목 | 내용 |
|---|---|
| URL | `/admin/orders/{id}` (id = UUID 또는 nanoid) |
| 라우트 타입 | CSR — 관리자 운영 핵심 화면. SWR 1분 + 수동 새로고침 + 폴링 30초 (다른 관리자 동시 작업 감지) |
| 진입 경로 | (1) s40 주문 관리 목록 행 [상세] 클릭 (2) 대시보드 최근 주문 행 클릭 (3) 처리 필요 KPI 클릭 (4) 알림 라우팅 (`/admin/orders/{id}`) (5) deep link (s40-Q01 권장 — 새 탭 열기 UX) |
| 목적 | (1) 단일 주문의 모든 정보 통합 조회 (회원·상품·결제·배송·쿠폰/포인트·재고 변동·취소/환불·내부 메모·감사 로그) (2) 강제 전체 취소 (d16 ORD-A-005) (3) 강제 부분 취소 (ORD-A-007) (4) 환불 트리거 (d17 PAY-A-003, 이미 cancelled 상태일 때) (5) 운송장 등록 진입 (s41 위임) (6) 상태 변경 (단방향 전이, F3) (7) 내부 메모 작성 (ORD-A-032) (8) 고객 알림 즉시 발송 (배송 지연·취소·환불 등) |
| 액터 | **MANAGER + SUPER + CS (조회만, write 일부 제한)** — MARKETER 미진입 |
| SEO 인덱싱 | X (`<meta name="robots" content="noindex, nofollow">` + `robots.txt: Disallow: /admin/`) |
| 회원 가드 | middleware: admin JWT + role IN (SUPER, MANAGER, CS) + MFA TOTP 검증 (강제 액션 시) |

## 8. SEO · 접근성 · 성능

### 8.1 SEO

- `<title>`: "주문 상세 — {order_no} | LUMI ADMIN"
- `<meta name="robots" content="noindex, nofollow">`
- `robots.txt`: `Disallow: /admin/`
- OG 미설정 (공유 차단)

### 8.2 접근성

- 페이지 구조 `<main>` + 각 카드 `<section aria-labelledby="...">`
- 상태 변경 드롭다운 `<select>` + `aria-label="주문 상태 변경"`
- 강제 취소 confirm 모달 — focus trap + 사유 input 자동 포커스 + ESC 종료
- 내부 메모 textarea `aria-multiline="true"` + 문자 카운트 `aria-live="polite"`
- 색맹 대응: 상태 배지 = 컬러 + 텍스트 라벨 (예: paid=mint+"결제완료")
- BLACKLIST 배지 = 빨강 + 텍스트 + 아이콘 (⚠) 함께
- 좌·우측 사이드 패널 `role="complementary"` (좌측은 `main`, 우측은 `aside`)
- Tab 순서: breadcrumb → 회원·결제 정보 → 상태 변경 → 액션 CTA (좌→우) → 좌측 ① ② ③ ④ ⑤ → 우측 ⑥ ⑦ ⑧ ⑨
- 모든 모달 `role="dialog"` + focus trap

### 8.3 성능

| 지표 | 목표 | 전략 |
|---|---|---|
| LCP | ≤ 2.5s | 상단 요약·금액 카드 우선 렌더. 우측 패널 (감사·재고) lazy |
| INP | ≤ 200ms | 상태 변경 optimistic UI (실패 시 rollback). 메모 저장도 동일 |
| CLS | ≤ 0.1 | 패널 height 고정. 모달 fade-in |

- 통합 상세 API 1회 호출 (`Promise.all` 백엔드) — order + items + payment + delivery + coupon_point + status_history
- 감사 로그·재고 변동·배송 진행은 별도 API (개별 SWR 1분)
- 폴링 30초 (다른 관리자 변경 감지) — 변경 시 토스트 + 수동 새로고침 (자동 X)
- 통신: 모든 admin API는 SSL + admin JWT + MFA 헤더 의무
