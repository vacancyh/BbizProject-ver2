## 3. 컴포넌트 명세

| 컴포넌트 | 위치 | 데이터 source | 동작 / 상태 |
|---|---|---|---|
| **breadcrumb** | 상단 | static | "← 주문 상세로" |
| **페이지 제목** | ① | server | "교환 신청 - ORD-..." |
| **안내 카드** | ② | static | "옵션이 마음에 안 드셨나요? 교환해드릴게요" + 교환 가능 기간 D-N |
| **교환 대상 라인 선택 (다건 — Tier 1 §3.A 체크박스)** | ③ | `GET /api/orders/{id}/exchange/init` items[] | **다건 선택 지원 (`exchange_groups` 신규 모델)** — 체크박스 멀티 선택. 1회 신청 = 1 그룹 = N 라인 교환. 회수 배송비는 그룹 1회 청구 (라인 N건 묶어 1회 회수 → 사용자 회수 배송비 절감 + 회사 회수 효율). 이미 진행 중 라인 비활성 + 배지 "이미 다른 처리 진행 중" (Tier 1 §3.D #1 `LINE_ALREADY_IN_PROCESS` 차단) |
| **신옵션 선택 — 라인별 카드 (다건)** | ④ | `GET /api/products/{product_id}/options` | **선택된 각 라인마다 신옵션 카드 분리 노출**. 라인별 드롭다운 (색상·사이즈·길이 등) + 라인별 신옵션 재고 + 라인별 단가 + 라인별 차액 표시. 카드 헤더 = "라인 N — 상품명" |
| **신옵션 재고 표시** | ④ | `product.skus` 실시간 | 5개 미만 시 강조 (sale 컬러). 0개 시 "교환 불가" + 라인 자동 reject. **그룹 전체 사전 검증 (Tier 1 §3.A)** = 모든 신옵션 재고 ≥ 1 확인 후만 신청 가능. 일부 품절 시 모달 "교환 신청한 상품 중 일부가 품절되었습니다. 환불로 진행할까요? 또는 가능한 라인만 진행하시겠어요?" (Tier 1 §3.D #3 T1-Q04 권장 b) — 사용자 선택권 제공 |
| **차액 계산 — 합산 (Tier 1 §3.A)** | ④ / ⑨ | client 즉시 + server preview | 라인별: (신옵션 단가 − 기존 단가) × 수량. **그룹 합산** = `total_price_diff = SUM(line.price_diff)`. 양수 = 추가 결제 1회 (그룹 합산액), 음수 = 환불 1회 (그룹 합산액), 0 = 차액 없음. **회수 배송비** = 그룹 1회 청구 (라인 N건 묶음, 사용자 비용 절감) |
| **사유 선택 (라디오)** | ⑤ | static enum (exchanges.reason) | size_mismatch / color_mismatch / defect / etc. 불량 시 이미지 필수 |
| **상세 사유** | ⑥ | 회원 입력 | 100자, 선택 (기타 시 필수) |
| **이미지 첨부** | ⑦ | 회원 업로드 | 사유=불량 시 필수 1장 이상. 형식·용량 룰 s24와 동일 |
| **회수·재발송 주소** | ⑧ | `orders.address_snapshot` + 회원 배송지 | 기본=주문 배송지. 변경 시 다음 우편번호 위젯 |
| **차액 결제·환불 안내** | ⑨ | server preview | 양수: "추가 결제 OOO원" + 결제수단 (카드 단일 — 토스). 음수: "OOO원 환불 (카드 자동)". 0: "차액 없음" |
| **주의 사항 동의** | ⑩ | 회원 액션 | 2개 체크 필수 |
| **[교환 신청하기] CTA** | ⑪ | 검증 통과 | (1) 라인 선택 (2) 신옵션 선택 + 재고 ≥ 1 (3) 사유 (4) 불량 시 이미지 (5) 동의. 차액 +시: confirm 모달 → 토스 결제창 호출 (Idempotency-Key) → 성공 시 exchanges INSERT (status=requested). 차액 ≤ 0: 즉시 신청 |

## 6. 연결 도메인 · API 면

### 6.1 도메인

| 도메인 | 사용 영역 |
|---|---|
| delivery | exchanges INSERT (status=requested) |
| order | order_items 상태 (active 검증) |
| product | 신옵션 SKU·재고·단가 |
| payment | 차액 결제 (토스 MCP) 또는 환불 |
| member | 본인 검증 + 배송지 |

### 6.2 API 면

| 엔드포인트 | 메서드 | 응답 | 캐시 |
|---|---|---|---|
| `/api/orders/{id}/exchange/init` | GET | `{ exchangeable_items: [], delivery_address_snapshot, member_addresses, exchange_period_remaining_days, reasons_enum }` | no cache |
| `/api/products/{product_id}/options` | GET | `[{ sku_id, options: {}, price, stock, available }]` | 짧은 캐시 (10초) |
| `/api/orders/{id}/exchange/preview` | POST | body `{ exchanges: [{item_id, new_sku_id, reason, reason_detail?}] }`. 응답 `{ exchanges: [{exchange_id, item_id, price_diff}], total_price_diff, diff_action: "ADDITIONAL_CHARGE"\|"REFUND"\|"NO_DIFF", pickup_fee_total }` — **다건 그룹 합산 응답 (Tier 1 §3.A)** | no cache |
| `/api/orders/{id}/exchange` | POST + Idempotency-Key (Level 2 — `{order_id}:exchange_group:{nonce}`) | body `{ exchanges: [{item_id, new_sku_id, reason, reason_detail?, images?}], pickup_address_id, attachments?, version, payment_session_id? }`. 차액 +시 payment_session_id 검증 후 처리. **응답** = `{ exchange_group_id, exchanges: [{exchange_id, item_id, status, price_diff}], total_price_diff, diff_action, additional_payment_required, pickup_fee_total }` | no cache |
| `/api/payments/toss/exchange-diff` | POST | 토스 결제창 호출용 세션 발급 | no cache |

### 6.3 4-way 차액 검증

| 단계 | 위치 | 비교 |
|---|---|---|
| (1) Client 계산 | 브라우저 | 사용자 표시 |
| (2) Server preview | `/exchange/preview` | 권위 |
| (3) Exchange 저장 | `/exchange` 시점 | DB 박제 |
| (4) PG 결제 금액 (+ 차액 시) | 토스 콜백 | (3)과 일치 검증 |

- 모바일 sticky CTA 44×44px
