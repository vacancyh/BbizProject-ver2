## 4. 상태 (State Matrix)

| 상태 | UI / 동작 |
|---|---|
| **정상 (결제 직후 진입)** | §3 전체 정상 표시 + 알림 자동 발송 트리거 |
| **로딩 (주문 데이터 fetch)** | 진행 단계 표시 + 본문 skeleton (아이콘+카피+카드 3종) |
| **본인 아님 (다른 회원 orderId)** | 403 페이지 — "다른 분의 주문이에요. 본인 주문만 확인할 수 있어요" + `[홈으로]` CTA. A-API-002 IDOR 차단 |
| **잘못된 orderId (존재하지 않음)** | 404 페이지 — "주문을 찾을 수 없어요" + `[마이페이지로]` CTA |
| **비로그인 (직접 URL 접근)** | 로그인 게이트 (`/auth/login?next=/order/complete?orderId=XXX`) |
| **알림 발송 실패 (회원 채널 OFF)** | 페이지는 정상 표시. 알림 미발송 (회원 설정 존중) |
| **알림 발송 실패 (메일/SMS 서버 오류)** | 페이지는 정상 표시. 알림 실패는 백그라운드 재시도 (3회 후 dead letter). 사용자에게는 노출 X |
| **결제 완료 직후 백엔드 컨테이너 재시작** | order DB는 영속 (PAY-U-010). 페이지 새로고침 시 정상 표시. 알림 미발송 케이스는 cron 보정 (PAY-U-010 시나리오) |
| **회원 비활성화 직후 (MEM-U-043)** | 주문 자체는 결제 완료 상태 유지. 페이지 정상 표시 (단 다음 로그인은 차단). 알림은 발송 |

## 5. 예외·엣지 케이스 (`01_사용자_플로우.md §7` 참조)

| ID | 케이스 | 처리 |
|---|---|---|
| **PAY-U-010 (정합성)** | 결제 완료 콜백 직후 백엔드 재시작 | order는 DB 영속 (PAID 상태). 본 페이지는 새로고침 시 정상 표시. 알림 미발송이면 cron이 5분 내 발송 보정 |
| **MEM-U-043 (회원 비활성화)** | 결제 직후 회원 비활성화 (관리자 강제) | 주문은 PAID 유지. 본 페이지 진입 자체는 가능 (세션 유효 동안). 다음 로그인부터 차단. 알림은 발송 |
| **다이렉트 URL 접근 (본인)** | 회원이 직접 `/order/complete?orderId=XXX` 입력 | 본인 주문이면 정상 표시 (단 결제 직후 전용 화면이 아니므로, 결제 완료 후 마이페이지 사용 권장 안내 캡션 추가 가능) |
| **다이렉트 URL 접근 (타인)** | 다른 회원 orderId 입력 | 403 (§4 "본인 아님" 처리) |
| **브라우저 새로고침** | 본 페이지에서 F5 | 정상 표시. 알림 재발송 X (멱등성 보장 — 알림 발송 1회만) |
| **뒤로 가기** | 결제 직후 본 페이지에서 뒤로 가기 | s18 주문서는 redirect 패턴 (`router.replace`)이라 카트로 이동. 또는 홈으로 (브라우저 history 정책) |
| **alimtalk 채널 미설정 (회원이 알림톡 발신처 친구 미추가)** | 알림톡 발송 시도 → 실패 → SMS fallback | 회원에게는 노출 X |
| **선물 포장 주문** | 결제 금액 카드에 "선물 포장 +1,000원" 항목 추가 표시 |
| **0원 결제 (포인트 100%)** | 결제수단 카드에 "포인트 전액 사용 (PG 미경유)" 표기 |

## 8. SEO · 접근성 · 성능

### 8.1 SEO

- `<title>`: "주문 완료 | LUMI"
- `<meta name="robots" content="noindex, nofollow">`
- `robots.txt`: `Disallow: /order`
- 사이트맵 미포함

### 8.2 접근성 (WCAG AA / KWCAG 2.2)

- 큰 ✓ 아이콘 `aria-hidden="true"` (장식 요소) + 옆에 "주문이 완료되었어요" 텍스트로 의미 전달
- 주문번호 [복사] 버튼 `aria-label="주문번호 복사"`
- 상품 썸네일 `alt="상품명"`
- 결제 금액 카드 행은 `<dl>` / `<dt>` / `<dd>` 구조 권장
- CTA 2종 키보드 Tab 순서 좌→우 (모바일은 위→아래)
- 토스트 (복사 성공) `aria-live="polite"`
- 페이지 진입 시 `<h1>` 포커스 이동 (스크린리더 사용자가 즉시 인지)

### 8.3 성능 (Core Web Vitals)

| 지표 | 목표 | 전략 |
|---|---|---|
| LCP | ≤ 2.0s | 큰 ✓ 아이콘 (LCP 후보) 인라인 SVG로 즉시 렌더 |
| INP | ≤ 200ms | CTA 클릭은 단순 router 이동 — 즉시 응답 |
| CLS | ≤ 0.1 | 카드 영역 height 고정. 썸네일 width/height 명시 |

- `/api/orders/[id]` 1회 호출
