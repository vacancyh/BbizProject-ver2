## 1. 개요
| 항목 | 값 |
|---|---|
| URL | `/mypage/profile` · `/mypage/address` · `/mypage/notification` (3 페이지 묶음, 사이드 메뉴로 라우트 전환. 모바일에서는 상단 탭 토글로도 가능) |
| 라우트 타입 | App Router (인증 게이트) · 3 라우트 각각 별도 페이지 (탭 패턴은 모바일 UX 동일 그룹 묶음용) |

| 액터 | 로그인 회원 (MEMBER) |
| SEO 인덱싱 | `noindex, nofollow` |

## 3. 컴포넌트 명세

### 3.1 프로필

| 컴포넌트 | 위치 | 데이터 source | 동작 |
|---|---|---|---|
| 이메일 read-only | 상단 | `GET /api/me` | 변경 불가 안내 툴팁 (계정 식별자). **PII 마스킹 (Tier 3 §3.1 Level B)** = 기본 표시 `t****@gmail.com` + "전체 보기" 토글 (본인 인증 재확인 후 노출 — 화면 캡처·공유 시 PII 유출 방지) |
| 비밀번호 [변경] | 이메일 아래 | — | 모달 진입: 현재 비번 + 새 비번 (8자↑ 영+숫+특) + 확인 → `PATCH /api/me/password` → 전 세션 무효화 → 재로그인 안내 (d11 F3). **Tier 3 §3.11 비번 정책 강화** = (1) 최근 5개 비번 재사용 차단 (DB 해시 비교) — 위반 시 422 "최근에 사용하신 비밀번호는 다시 사용할 수 없습니다" (2) 자주 쓰는 비번 top 10000 차단 (3) 이메일·이름·생년월일 일부 포함 차단 (4) 변경 후 이메일·SMS 보안 알림 자동 발송 ("비밀번호가 변경되었습니다 — 본인이 아닐 경우 즉시 고객센터 문의") |
| 휴대폰 [재인증] | 비번 아래 | `GET /api/me` | 모달: 본인인증 (SMS OTP) → `PATCH /api/me/phone`. **PII 마스킹 (Tier 3 §3.1)** = 기본 `010-****-1234` + "전체 보기" 토글 |
| 이름 [수정] | 휴대폰 아래 | — | 인라인 편집 → `PATCH /api/me {name}`. **PII 마스킹 (Tier 3 §3.1)** = 기본 `김*수` (성+가운데 마스킹) + "전체 보기" 토글 |
| 생년월일 read-only | 이름 아래 | `GET /api/me` | 변경 불가 안내 ("CS 문의로 변경") — 만 14세 검증 보존 |
| 성별 셀렉트 | 생년월일 아래 | `PATCH /api/me {gender}` | F/M/N (선택 안 함) |
| 프로필 이미지 업로더 | 하단 | `POST /api/uploads` + `PATCH /api/me {image_url}` | 5MB, JPEG/PNG/WebP, MIME 검증 |
| 마케팅 동의 체크박스 | 하단 동의 영역 | `PUT /api/me/consents` | 변경 시 신규 row INSERT (이력 보존 — d11 § 2.3 룰). **Tier 5 §3.4·§3.10 옵트인·증빙·1클릭 수신거부** = (1) 동의 변경 시 IP·UA·시각·페이지·약관 텍스트 버전 박제 (member_consent INSERT only, UPDATE 금지 — 정보통신망법 증빙 2년 보관) (2) 동의 ON 시 안내 카드 노출: "마케팅 정보는 `[광고]` 표기로 발송됩니다 / 야간 21:00~08:00 KST 광고 발송 자동 차단 / 거래성 알림(주문·결제·배송)은 수신거부 불가 (법정 의무)" (3) 동의 OFF 시 즉시 next 발송 차단 (4) **본 화면 외 1클릭 수신거부 진입점 = 이메일·SMS·알림톡 본문 하단 링크 (24h 만료 1회용 토큰)** |
| 3자 제공 체크박스 | 마케팅 옆 | 동일 | 동일 — Tier 5 §3.10 증빙 적용 |

## 5. 예외·엣지 케이스

### 5.1 프로필
- **비번 변경 후 다른 기기 세션** → 전 세션 즉시 revoke (d11 F3) → 다른 기기에서 다음 API 호출 시 401 + 로그아웃
- **휴대폰 재인증 미완료 상태에서 저장 시도** → 422 "휴대폰 인증을 완료해주세요"
- **이메일 변경 요청 (변경 불가 항목)** → 본 화면에서 UI 자체 미노출 (계정 통합 정책)
- **생년월일 변경 요청** → CS 1:1 문의 안내 (어드민 수정 = 만 14세 재검증)
- **마케팅 동의 OFF → ON 전환** → 신규 row INSERT (UPDATE 금지, d11 § 2.3) + IP·UA 저장
- **3자 제공 OFF → 마케팅도 자동 OFF** (의존 관계 — 단 정책 명시화 필요, s32-Q03 박제)

### 5.2 배송지
- **활성 10개 + 추가 시도 (v4 정합)** → 클라이언트 차단 + 서버 422 이중 방어 (DEL-U-001/002)
- **기본 배송지 부재 상태에서 결제 진입** → 결제 화면(s18)에서 "배송지 등록 필요" + 본 화면으로 유도
- **배송지 삭제 후 진행 중 주문 영향** → 주문은 address_snapshot 보존 (d18 § 2.2) — 영향 없음
- **다음 우편번호 API 차단/장애** → 직접 입력 fallback + region_type 수동 선택 옵션
- **제주/도서산간 자동 분류 오인** → 사용자 수정 불가 (zipcode 기반 자동 분류 시스템 고정)

### 5.3 알림 설정
- **글로벌 채널 OFF 상태에서 사용자 ON 시도** → 클라이언트 차단 + 안내 "운영자가 일시 중지한 채널입니다"
- **거래 알림 강제 ON 토글 시도** → 잠금 + 툴팁 "법적 의무로 거래 알림은 받으셔야 합니다"
- **알림톡 미동의 회원에 알림톡 발송 시도** → notification 도메인이 발송 전 동의 확인 (본 화면 책임 X)
- **장애로 PUT 실패 시 부분 저장** → 트랜잭션 단위 PUT (15 토글 일괄 저장, 부분 성공 차단)

## 7. 권한·접근 제어

- 비로그인 = 3 라우트 모두 `/auth/login?next=<path>` 리다이렉트
- 본인 정보만 조회·수정 (서버 세션 member_id 강제, IDOR — A-API-002)
- 비번 변경 = 현재 비번 재확인 필수 (Brute-force 차단)
- 휴대폰 변경 = OTP 본인인증 필수
- 정지 회원 = 조회만, 수정 불가 (정책 강제)
- 블랙리스트 = 본 화면 접근 자체 차단 (탈퇴 처리 후 PII 마스킹)

## 8. SEO · 접근성 · 성능

- **SEO**: `noindex, nofollow`
- **접근성**:
  - 모든 input = label-id 명시적 연결 (`<label for="">`)
  - 비번 변경 모달 = focus trap + ESC 닫기
  - 알림 매트릭스 = `<table>` + `<th scope="col/row">` + 토글 = `role="switch"` + `aria-checked`
  - 강제 ON 항목 = `aria-disabled="true"` + 툴팁 = `aria-describedby`
  - 동의 체크박스 = 약관 본문 링크 (`/policy/marketing`) 명시
- **성능**:
  - 다음 우편번호 API = lazy load (모달 진입 시 script 삽입)
  - 프로필 이미지 업로드 = presigned URL (서버 우회) + WebP 변환 + 썸네일 생성
  - 알림 매트릭스 = debounce 500ms PUT (15 토글 빈번 변경 보호)
