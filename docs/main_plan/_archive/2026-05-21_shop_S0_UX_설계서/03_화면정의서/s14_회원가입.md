## 1. 개요

| 항목 | 내용 |
|---|---|
| URL | `/auth/signup?next=<encoded path>&social=<provider>&token=<temp>` |
| 라우트 타입 | CSR (Client) — 본인인증 + 약관 동의 동적 상태. SSR 부적합 |

| **비밀번호에 이메일/이름 포함** | 예: `cindy123!@example.com` 이메일에 비밀번호 `cindy123!` | 빨강 캡션 "비밀번호에 이메일이나 이름을 포함할 수 없어요" (보안 권장) |

## 8. SEO · 접근성 · 성능

### 8.1 SEO

- `<title>`: "회원가입 | LUMI"
- `<meta name="robots" content="noindex, nofollow">`
- `robots.txt`: `Disallow: /auth/`
- 사이트맵 미포함

### 8.2 접근성 (WCAG AA / KWCAG 2.2)

- 모든 입력 필드 `<label>` 명시 + `for`/`id` 연결
- 비밀번호 강도 체크리스트 `aria-live="polite"` (입력 시 실시간 안내)
- 인증번호 타이머 `aria-live="polite"` (남은 시간 안내)
- 약관 동의 체크박스 `<label>` 안에 약관명 + [보기] 분리 (`role="link"`)
- 전체 동의 체크박스 `aria-controls` 4종 약관 ID 연결
- 모달 (만 14세/이메일 중복/탈퇴 30일) `role="dialog"` + focus trap + ESC 닫기
- Tab 순서: 이메일 → 중복확인 → 비밀번호 → 비밀번호 확인 → 휴대폰 → 인증 요청 → 인증번호 → 성별 → 전체동의 → 약관 4종 → 가입하기 → 로그인 링크
- 에러 메시지 `aria-invalid` + `aria-describedby` 연결
- 빨강 캡션 색만으로 의미 전달 X — 아이콘 (⚠/✗) 병기

### 8.3 성능 (Core Web Vitals)

| 지표 | 목표 | 전략 |
|---|---|---|
| LCP | ≤ 1.5s | 로고·폼 critical CSS / 본인인증 SDK는 [인증 요청] 클릭 시 lazy load |
| INP | ≤ 100ms | 이메일 중복 체크는 debounce 500ms. 비밀번호 강도는 즉시 |
| CLS | ≤ 0.05 | 인증번호 필드·캡션 영역 height 예약 |

- PASS/NICE 본인인증 SDK는 lazy load (300KB+ 절감)
- 약관 전문 모달은 클릭 시 fetch (`/api/policies/[type]`)
