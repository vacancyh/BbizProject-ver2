## 1. 개요

| 항목 | 내용 |
|---|---|
| URL | `/mypage/orders/[orderId]` (orderId = UUID 또는 nanoid) |
| 라우트 타입 | CSR + 본인 검증 (server) |
| 진입 경로 | (1) s22 주문 내역 카드 "주문 상세" CTA (2) s19 주문완료 페이지 (3) s21 인덱스 최근 주문 |

| 액터 | 회원 전용 + **본인만** (IDOR 차단, F8) |
| SEO 인덱싱 | X |
| 회원 가드 | middleware: 비로그인 시 `/auth/login?next=/mypage/orders/[orderId]` |
| 본인 검증 | server side: `orders.member_id === session.member_id` 또는 admin 권한. 위반 시 403 (s23-Q01 미결 박제 — 정보 노출 최소화 권장) |

## 3. 컴포넌트 명세

| 컴포넌트 | 위치 | 데이터 source | 동작 / 상태 |
|---|---|---|---|
| **본인 검증 + breadcrumb** | 상단 | server | 본인 아니면 403 페이지. 본인이면 "← 주문 내역으로" |
| **주문 헤더** | ① | `GET /api/orders/{id}` | 주문번호 (UTF-8) · 주문일 (KST) · 상태 배지 · D-N 자동 구매확정 캡션 |
| **CTA — 전체 취소** | ① | status ∈ {paid, preparing} + 본인 | confirm 모달 (사유 입력 필수) → `POST /api/orders/{id}/cancel` (Idempotency-Key) → 성공 시 토스트 + 페이지 갱신 |
| **CTA — 부분 취소** | ③ 상품 라인 우측 | status ∈ {paid, preparing} + active 라인 + 본인 | 체크박스 멀티 선택 → 페이지 하단 sticky "선택 라인 취소" → confirm 모달 (사유) → `POST /api/orders/{id}/cancel-items` |
| **CTA — 구매확정** | ① | status=delivered + 미확정 + 본인 | confirm 모달 → `POST /api/orders/{id}/confirm` → 토스트 "포인트 적립" |
| **CTA — 반품 신청** | ① | status=delivered + 반품 기간 내 + 본인 + 미반품/교환 라인 존재 | s24로 이동 (`/return`) |
| **CTA — 교환 신청** | ① | 동일 조건 | s25로 이동 (`/exchange`) |
| **CTA — 리뷰 작성 (라인별)** | ③ 라인 우측 | status=confirmed + 라인 review 미작성 | s26 이동 (`/review?order_item_id=...`) |
| **CTA — 재구매** | ① | 본인 (항상) | `POST /api/orders/{id}/reorder` → 카트로 이동 |
| **배송 정보 카드** | ② | `orders.address_snapshot` + `deliveries` | 주문 시점 스냅샷 (이후 회원 주소 변경과 무관, F16). **PII 마스킹 정책 (Tier 3 §3.1)** — 받는 사람 이름 = `김*수` (성+가운데 마스킹) / 연락처 = `010-****-1234` / 주소 = `서울 강남구 ***로 12` (상세 주소 마스킹). 사용자 본인 화면이지만 화면 캡처·공유 시 PII 유출 방지 차원. "전체 보기" 토글 버튼 제공 (본인 인증 재확인 후 전체 노출 — 토글 onClick 시 비번 재입력 모달 또는 OTP) |
| **운송장 추적 링크** | ② | `deliveries.courier`, `tracking_no` | 새 창 외부 링크 (CJ/한진/롯데/우체국 url 매핑). 외부 링크 `target="_blank" rel="noopener noreferrer"` |
| **배송 진행 이력** | ② | `GET /api/orders/{id}/tracking` (`shipment_tracking`) | 시간순 타임라인 (집화·간선상차·하차·배송출발·배송완료). 빈 이력 시 "준비 중" |
| **다건 운송장 (1주문 N shipment, Tier 1 §3.F)** | ② | `GET /api/orders/{id}/shipments` (`shipments[]`) | 1주문 N운송장 분할 배송 지원. **각 shipment 별 카드** (shipment_id · 택배사 · 운송장 번호 · 포함 라인 목록 · 상태). 카드 헤더 = "박스 1/N" + 상태 배지. 각 카드에 운송장 추적 링크 + 배송 진행 이력. 일부 라인은 즉시 출고, 나머지는 예약 발송 시 "예약 발송 (입고 대기)" 라벨. **상태 전이** = 첫 shipment 등록 → `orders.status='shipping'` (잔여 라인 있어도) / 모든 shipment delivered → `delivered` / 일부 delivered → `partially_delivered` (Tier 1 §3.M) — 헤더 상태 배지에 캡션 "N건 중 M건 배송완료" |
| **상품 라인 테이블** | ③ | `order_items` snapshot | 라인별 상태 (active/cancelled/returned/exchanged) 배지. 취소·반품·교환된 라인은 취소선 + 배지 |
| **라인별 체크박스 (부분취소용)** | ③ | status ∈ {paid, preparing} + active 라인 | 체크 시 페이지 하단 sticky 액션 바 표시 |
| **결제 정보 카드** | ④ | `orders` 금액 필드 | 상품 합계 / 쿠폰 (사용 쿠폰명 + sale 컬러 −) / 포인트 (sale 컬러 −) / 배송비 / 선물 포장 / 결제 금액 / 결제수단 (카드 — 토스) / 할부 / 적립 예정 또는 완료 (mint) |
| **취소·반품·교환 이력 카드** | ⑤ | `order_cancellations` + `returns` + `exchanges` | 시간 역순. 각 항목 클릭 시 s24/s25 상세 (있다면) |
| **주문 상태 변경 이력** | ⑥ | `order_status_history` | 시간순 타임라인. 변경자 (member/admin/system) 표시 |
| **부분취소 sticky 액션 바 (모바일/데스크 공통)** | 페이지 하단 | 체크 라인 ≥ 1 | "선택 N건 취소 신청 (예상 환불 OOO원)" + `[취소 신청]` 버튼 |

## 4. 상태 (State Matrix)

| 상태 | UI / 동작 |
|---|---|
| **초기 (로딩)** | 페이지 skeleton (헤더·배송·상품·결제 카드 모두) |
| **데이터 OK** | 위 §3 정상 동작 |
| **본인 아님 (IDOR)** | 403 페이지 — "권한이 없어요" + `[주문 내역으로]` |
| **주문 없음** | 404 페이지 — "주문을 찾을 수 없어요" |
| **pending (결제 미완료)** | 결제 대기 안내 + "30분 후 자동 취소됩니다" + `[결제 재시도]` CTA (s18로 멱등 키 유지하여 이동, s23-Q02 미결 박제) |
| **paid·preparing (취소 가능)** | 취소·부분취소 CTA 활성. 반품·교환·리뷰는 비활성 |
| **shipping (취소 불가, 운송장 발급)** | 운송장 추적 활성. 취소·반품·교환 모두 비활성 (배송 시작 후 정책상 차단). 단 도착 전 취소는 정책 미결 (s23-Q03 박제) |
| **delivered (반품·교환·구매확정 가능)** | 반품·교환·구매확정 활성. 라인별 상태 확인 |
| **confirmed** | 모든 CTA 비활성, 리뷰 작성만 활성 (라인별) |
| **cancelled/partial_cancelled** | 취소된 라인 취소선 + 환불 내역 ⑤ 강조 |
| **partially_delivered (Tier 1 §3.M·§3.F)** | 일부 라인 배송완료 (1주문 N shipment 중 일부 delivered). 상품 라인 테이블에서 라인별 `line_status`에 따라 표시 — delivered 라인 = "배송완료" 배지 + 해당 라인 리뷰·반품·교환 가능 / shipping 라인 = "배송중" 배지 + 해당 운송장 추적 링크 / preparing 라인 = "출고 준비 중" |
| **partially_returned / partially_exchanged (Tier 1 §3.M)** | 일부 라인이 반품·교환 진행 중. 해당 라인 = 회색 + "반품 진행 중" / "교환 진행 중" 배지. 나머지 라인은 정상. ⑤ 이력 카드 강조 표시 |
| **다건 동시 처리 차단 (Tier 1 §3.D #1 — `LINE_ALREADY_IN_PROCESS`)** | 같은 라인에 반품·교환 중복 신청 시도 시 모달 "이 상품은 이미 다른 처리(반품/교환)가 진행 중입니다. 진행 상황은 [반품/교환 이력] 카드에서 확인하실 수 있어요" |
| **취소 진행 중 (낙관락 충돌)** | 모달 "다른 작업으로 인해 처리가 충돌했어요. 새로고침 후 다시 시도해주셔요" + 페이지 재로딩 |
| **환불 PG 실패 (강제 취소 롤백)** | "처리 중 오류 발생, 자동 복구됨" + 토스트 + 페이지 재로딩 |
| **동시 취소 경합 — `ORD-U-041` (v4.8 신규)** | 사용자 취소와 관리자 강제 취소가 동시 도달 시 → 1건만 처리되고 나머지는 모달 "이미 취소가 처리됐어요" + 재고·포인트·쿠폰 중복 복구 0건 확인. 페이지 자동 새로고침으로 정합 상태 표시 |
| **취소 중 결제 웹훅 중복 — `ORD-U-042` (v4.8 신규)** | 취소 처리 중 PG 결제 완료 웹훅이 재전달 → 취소 상태에 결제완료 덮어쓰기 차단 (서버 멱등 키 검증). UI는 cancelled 상태 유지 |
| **부분취소 동시 요청 (라인 독립) — `ORD-U-043` (v4.8 신규)** | 라인 A·B 부분취소가 거의 동시에 요청 → 각각 독립 트랜잭션, 재고·환불 금액 중복/누락 0. UI는 각 라인 cancelled 배지 즉시 갱신 |
| **취소 후 재고 복구 즉시 — `ORD-U-044` (v4.8 신규)** | 전체 취소 완료 → 해당 상품 상세 페이지 재고 즉시 증가 + 품절 해제. s23 페이지 캐시 PURGE 트리거 |
| **취소-복구-재주문 연속 일관성 — `ORD-U-045` (v4.8 신규)** | 사용자 A 취소 → 재고 복구 → 사용자 B 즉시 재주문 성공. 복구 전 재주문은 "재고 부족" 차단 |
| **배치 자동취소 + 수동 취소 경합 — `ORD-U-046` (v4.8 신규)** | 미결제 자동취소 배치 처리 중 사용자가 동일 주문 취소 시도 → 중복 처리 0, 재고 복구 1회만. UI는 cancelled 상태 즉시 표시 |
| **정지 회원** | CTA 모두 회색 + "고객센터 문의" 안내 |
| **블랙리스트** | 동일 |

### 6.2 API 면

| 엔드포인트 | 메서드 | 응답 | 캐시 |
|---|---|---|---|
| `/api/orders/{id}` | GET | 통합 상세 (order + items + payment + delivery + cancellations + returns + exchanges + status_history) | no cache |
| `/api/orders/{id}/tracking` | GET | shipment_tracking 이력 (배송 진행) | 5분 |
| `/api/orders/{id}/shipments` | GET | 다건 운송장 리스트 (Tier 1 §3.F) — `shipments: [{shipment_id, courier, tracking_no, status, items: [...], shipped_at, delivered_at}]` | 5분 |
| `/api/orders/{id}/cancel` | POST + Idempotency-Key (Level 1) | 전체 취소 | no cache |
| `/api/orders/{id}/cancel-items` | POST + Idempotency-Key (Level 1) + **Idempotency-Sub-Key (Level 2, Tier 1 §3.I — `{order_id}:partial_cancel:{nonce}`)** | 부분 취소 (`item_ids[]`, `reason`) | no cache |
| `/api/orders/{id}/confirm` | POST | 구매확정 | no cache |
| `/api/orders/{id}/reorder` | POST | 카트 일괄 담기 | no cache |

**Idempotency-Key 헤더 계층 (Tier 1 §3.I)**:
- `Idempotency-Key` (Level 1) = 주문 단위 — 같은 주문에 반복 요청 시 캐시 응답
- `Idempotency-Sub-Key` (Level 2) = 부분취소·반품·교환 등 각 부분 환불 단위 별도 발급 (`{order_id}:{action_type}:{nonce}` — nonce는 클라이언트 발급 — T1-Q07 권장)
- 같은 주문에 부분환불 2회 신청 시 같은 Level 1 키 재사용해도 Sub-Key는 매번 새로 발급 → 환불 누락 차단
