## 1. 개요

| 항목 | 내용 |
|---|---|
| URL | (1단계) `/auth/reset` (2단계) `/auth/reset?token=<jwt 30분 만료>` (3단계) `/auth/reset?token=<jwt>&step=new` (단일 URL + step 분기) |
| 라우트 타입 | CSR (Client) — 토큰 검증 + 폼 동적. SSR 부적합 |
| 진입 경로 | (1) 로그인 페이지 `[비밀번호 재설정]` 링크 (2) 재설정 이메일 본문의 링크 클릭 (토큰 동봉) (3) 헤더 회원가입·로그인 메뉴 |
| 목적 | (1) 이메일 입력 → 재설정 링크 발송 (2) 토큰 검증 → 새 비밀번호 입력 (3) 변경 완료 → 자동 로그인 + 기존 세션 전부 폐기 |
| 액터 | **비로그인** (또는 비밀번호 분실 회원). 이미 로그인 상태는 본 화면 대신 마이페이지 "비밀번호 변경" 사용 권장 (별도 화면) |
| SEO 인덱싱 | X (`<meta name="robots" content="noindex, nofollow">` + `robots.txt: Disallow: /auth/`) |
| 회원 가드 | 이미 로그인 상태도 본 화면 접근 허용 (분실 시뮬레이션 가능). 단 3단계 진입 시점에 동일 회원이면 경고 모달 |

### 3.4 Step 3 — 새 비밀번호 입력

| 컴포넌트 | 위치 | 데이터 source | 동작 / 상태 |
|---|---|---|---|
| **H1 "새 비밀번호 입력"** | 본문 최상단 | static | 중앙 정렬 |
| **새 비밀번호 입력 + 강도 체크리스트** | 폼 1행 | local state | s14와 동일 규칙 (8자/영문/숫자/특수). 우측 [👁] 토글. **Tier 3 §3.11 비번 정책 강화** = (1) **최근 5개 비번 재사용 차단** (서버에서 bcrypt 해시 비교 — 변경 시도 시 422 "최근에 사용하신 비밀번호는 다시 사용할 수 없습니다") (2) 자주 쓰는 비번 top 10000 차단 (3) 이메일·이름·생년월일 일부 포함 차단 (4) bcrypt cost=12 저장 |
| **[비밀번호 변경 성공 시 보안 알림 (Tier 3 §3.11)]** | 변경 성공 후 | `POST /api/auth/reset/notify` (자동) | 변경 성공 시 **이메일 + SMS 보안 알림 자동 발송** (마케팅 동의와 무관 — 거래성 알림) = "비밀번호가 변경되었습니다 · {YYYY-MM-DD HH:mm KST} · IP/디바이스 정보 · 본인이 아닐 경우 즉시 고객센터(s50/s51) 문의 + 비밀번호 재변경 권장". 알림 발송 실패 시에도 변경은 성공 처리 (실패 시 retry queue) |
| **비밀번호 확인 입력** | 폼 2행 | local state | 일치 검증 실시간 |
| **세션 폐기 경고** | 폼 하단 | static | "변경하면 모든 기기에서 자동으로 로그아웃됩니다" (회색 배경 카드) |
| **[비밀번호 변경하기] CTA** | 폼 하단 | `POST /api/auth/reset/confirm` | (1) 새 비밀번호 검증 (2) 토큰 동봉 전송 (3) 성공 시 모든 Refresh Token 폐기 + 자동 로그인 (새 토큰 발급) + 토스트 + `/` 또는 `/mypage` 리다이렉트 |

## 5. 예외·엣지 케이스 (`01_사용자_플로우.md §7` 참조)

| ID | 케이스 | 처리 |
|---|---|---|
| **A-AUTH-002** | 미등록 이메일로 발송 요청 | 동일한 "메일 발송 완료" 화면 표시 (사용자 열거 방지). 실제 발송은 안 함. 응답 시간 정규화 (DB 조회 여부 추론 불가) |
| **A-AUTH-004** | rate limit | 동일 이메일 10분 1회 / 동일 IP 분당 5회. 초과 시 토스트 안내 |
| **토큰 30분 만료** | 메일 수신 후 30분 초과 클릭 | Step 2 검증 단계에서 만료 에러 → Step 1로 복귀 안내 |
| **토큰 1회용** | 동일 토큰으로 비밀번호 변경 2회 시도 | DB에 토큰 사용 시각 박제. 사용된 토큰은 재사용 불가 (즉시 폐기) |
| **토큰 변조** | URL 토큰 임의 수정 | JWT 서명 검증 실패 → 에러 화면 |
| **다른 사람이 메일 링크 클릭** | 메일 탈취 또는 공유 PC | 토큰만 알면 누구나 변경 가능 (이메일 소유자 = 본인 가정). 추가 본인인증 X (UX 부담) — 사장님 결정 (s15-Q01) |
| **변경 성공 시 전 세션 폐기** | 비밀번호 변경 시 기존 Refresh Token 전부 무효화 | DB에서 user_id 기준 전체 Refresh Token DELETE. 본 세션은 변경 직후 새 토큰 발급 (자동 로그인 유지) |
| **변경 성공 후 자동 로그인** | UX 매끄럽게 처리 | 변경 API 응답에 새 세션 쿠키 동봉 → 즉시 `/mypage` 리다이렉트. 별도 로그인 단계 없음 |
| **소셜 가입 회원이 비밀번호 재설정 요청** | OAuth 가입 회원은 비밀번호가 없음 | (a) 일반 가입 비밀번호가 있는 회원만 발송 (사용자 열거 방지 위해 동일 화면 표시) (b) 메일 본문은 발송하지 않음. 사용자가 메일 미수신 시 "소셜 가입이실 거예요" 안내는 못 함 (열거 방지). FAQ 안내 권장 |
| **이메일 SMTP 발송 실패** | 메일 서버 장애 | 사용자에게는 동일 완료 화면 표시. 백엔드 alert + 재시도 큐 |
| **휴면 회원이 재설정 시도** | 본 화면에서는 발송 진행. 토큰 클릭 시 휴면 해제 플로우 안내 | Step 2 후 "휴면 해제 후 다시 시도해주세요" 모달 (S0 미설계) |
| **MEM-S-003** | 새 비밀번호 = 이전 비밀번호 차단 | DB 비밀번호 해시 비교 (bcrypt verify). 동일 시 토스트 + CTA 비활성 |
| **변경 직후 SMS 알림** | 보안 강화 옵션 | 회원의 휴대폰으로 "비밀번호가 변경됐어요. 본인이 아니라면 즉시 고객센터 문의" SMS 자동 발송 (s15-Q02) |

## 6. 연결 도메인 · API 면

### 6.1 도메인

| 도메인 | 사용 영역 |
|---|---|
| member | 이메일 존재 확인 (내부), 비밀번호 해시 갱신, Refresh Token 전체 폐기, 새 세션 발급 |
| notification | 재설정 링크 이메일 발송 (SMTP), 변경 완료 SMS 알림 (선택) |
| admin | rate limit 정책 조회 (10분 / IP 분당 5회 등 운영 가변) |

### 6.2 API 면 (가설 — Phase 4 기능정의서에서 확정)

| 엔드포인트 | 메서드 | 응답 | 비고 |
|---|---|---|---|
| `/api/auth/reset/request` | POST | body: `{ email }` → `{ ok }` (성공 여부 무관하게 동일 응답) | rate limit: 동일 이메일 10분 1회 / 동일 IP 분당 5회 |
| `/api/auth/reset/verify-token` | POST | body: `{ token }` → `{ ok, expires_in }` 또는 `{ ok: false, reason: 'expired'|'invalid'|'used' }` | JWT 서명 검증 + DB 토큰 상태 조회 |
| `/api/auth/reset/confirm` | POST | body: `{ token, new_password }` → `{ ok, redirect_url }` + 새 세션 쿠키 | 트랜잭션: (1) 토큰 사용 처리 (2) 비밀번호 해시 갱신 (3) 모든 Refresh Token DELETE (4) 새 세션 발급. 실패 시 rollback |
| `/api/auth/reset/sms-notify` (internal) | POST | (변경 성공 트리거) → SMS 발송 | 비동기 |

## 8. SEO · 접근성 · 성능

### 8.1 SEO

- `<title>`: "비밀번호 재설정 | LUMI"
- `<meta name="robots" content="noindex, nofollow">`
- `robots.txt`: `Disallow: /auth/`
- 사이트맵 미포함

### 8.2 접근성 (WCAG AA / KWCAG 2.2)

- 입력 필드 `<label>` 명시
- Step 전환 시 H1 변경 → 스크린리더 알림 (`aria-live="assertive"` 또는 focus 이동)
- 비밀번호 강도 체크리스트 `aria-live="polite"`
- 카운트다운 (메일 다시 보내기) `aria-live="polite"` (1초 단위 안내는 noisy → 30초/10초 단위 권장)
- 에러 화면 (토큰 만료/잘못된 토큰) `role="alert"`
- 모달 (이미 로그인 경고) `role="dialog"` + focus trap + ESC 닫기
- Tab 순서: 이메일 → 재설정 메일 보내기 → 로그인으로 돌아가기 (Step 1) / 새 비밀번호 → 비밀번호 확인 → 비밀번호 변경하기 (Step 3)
- 빨강 캡션 색만으로 의미 전달 X — 아이콘 (⚠) 병기

### 8.3 성능 (Core Web Vitals)

| 지표 | 목표 | 전략 |
|---|---|---|
| LCP | ≤ 1.5s | 폼 critical CSS |
| INP | ≤ 100ms | 이메일 형식 검증 즉시 / 비밀번호 강도 즉시 |
| CLS | ≤ 0.05 | Step 전환 시 layout shift 방지 (height 예약) |

- 메일 발송 API는 비동기 처리 (사용자에게는 즉시 완료 화면 표시)
- 토큰 검증은 클라이언트 mount 시 1회만
