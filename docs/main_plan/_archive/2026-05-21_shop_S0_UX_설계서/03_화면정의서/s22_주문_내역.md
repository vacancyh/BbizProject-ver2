## 1. 개요

| 항목 | 내용 |
|---|---|
| URL | `/mypage/orders` |
| 라우트 타입 | CSR + URL query 동기화 (`?period=3m&status=shipping&page=2`) |
| 진입 경로 | (1) 마이페이지 사이드 메뉴 "주문 내역" (2) s21 인덱스의 주문 상태 카드 클릭 (자동 status 필터 적용) (3) 주문완료 페이지 s19 "내 주문 보기" |
| 목적 | 본인 주문 전체 조회 + 기간·상태 필터 + 페이지네이션 + 상태별 빠른 액션 (취소·반품·교환·리뷰·재구매) |
| 액터 | 회원 전용 (정지·블랙리스트는 조회만 가능, 신규 액션은 차단) |
| SEO 인덱싱 | X |
| 회원 가드 | middleware: 비로그인 시 `/auth/login?next=/mypage/orders` |

### 2.2 태블릿 (769~1024)

- 사이드 메뉴 축소 (200px)
- 필터 영역 sticky 유지

### 2.3 모바일 (~768)

- 사이드 메뉴 → 상단 가로 칩
- 기간·상태 필터 → 상단 sticky 가로 스크롤 칩 그룹 (2 행)

## 3. 컴포넌트 명세

| 컴포넌트 | 위치 | 데이터 source | 동작 / 상태 |
|---|---|---|---|
| **페이지 제목 + 총 건수** | ① | `GET /api/orders?period=...&status=...` (응답 meta.total) | "주문 내역 (총 N건)" |
| **기간 필터 (택1)** | ② | URL query `period` | 1개월/3개월/6개월/12개월/전체. 기본값 3개월. 변경 시 URL query 갱신 + page=1 리셋 |
| **상태 필터 (택1)** | ② | URL query `status` | 전체/paid/preparing/shipping/delivered/cs (취소·반품·교환 통합). s21에서 진입 시 자동 적용 |
| **검색 입력** | ② | URL query `q` | debounce 500ms 후 검색. 상품명·주문번호 부분 일치 |
| **주문 카드** | ③ | `/api/orders` items[] | 주문번호 (ORD-YYYYMMDD-XXXXXX) · 주문일 · 상태 배지 · 상품 썸네일 (첫 3건 + "외 N건") · 결제금액 · 상태별 CTA |
| **상태 배지** | 카드 내 | `order.status` | paid (네이비) / preparing (남색) / shipping (파랑) / delivered (그린) / confirmed (mint) / cancelled (그레이) / partial_cancelled (오렌지) / **partially_delivered (파랑+캡션 "일부 배송완료" — Tier 1 §3.M·§3.F) / partially_returned (오렌지+캡션 "일부 반품 진행 중") / partially_exchanged (오렌지+캡션 "일부 교환 진행 중")**. **단 외부 노출 정책 (Tier 1 §3.M / T1-Q06 권장 b)** = 신규 partially_* 상태는 사용자 외부 노출은 단순화하여 기본 상태 (paid/shipping/delivered) + 별도 "부분 처리 N건" 캡션으로 표시 권장. 카드 안 액션 영역에 "부분 취소 N건 · 부분 반품 N건" 캡션 추가 |
| **CTA — 주문 상세** | 카드 하단 | (항상) | `/mypage/orders/[orderId]` 이동 (s23) |
| **CTA — 취소 신청** | 카드 하단 | status ∈ {paid, preparing} | s23 진입 후 취소 모달 (당 페이지에서 직접 처리 X — 본인 검증·트랜잭션 보호) |
| **CTA — 구매확정** | 카드 하단 | status=delivered + 미확정 | confirm 모달 후 `POST /api/orders/{id}/confirm`. 성공 시 카드 즉시 갱신 + 토스트 "포인트가 적립됐어요" |
| **CTA — 리뷰 작성** | 카드 하단 | status=confirmed + 미작성 라인 존재 | s26 `/mypage/orders/[orderId]/review` 이동 |
| **CTA — 반품 신청** | 카드 하단 | status=delivered + 반품 가능 기간 내 | s24 `/return` 이동 |
| **CTA — 교환 신청** | 카드 하단 | status=delivered + 교환 가능 기간 내 | s25 `/exchange` 이동 |
| **CTA — 재구매** | 카드 하단 | (항상) | `POST /api/orders/{id}/reorder` → 카트 일괄 담기 → 카트 페이지로 이동 + 결과 토스트 "N건 담김, M건 품절로 제외" |
| **페이지네이션** | ④ | meta.total + page | 페이지당 10건. 페이지 이동 시 URL query 갱신 |
| **빈 결과 카드** | ③ 자리 | items.length === 0 | 필터 결과 0건: "조건에 맞는 주문이 없어요" + `[필터 초기화]`. 신규 회원: "아직 첫 주문이 없어요" + `[쇼핑 둘러보기 →]` |

## 8. SEO · 접근성 · 성능

### 8.1 SEO

- `<title>`: "주문 내역 | LUMI"
- `<meta name="robots" content="noindex, nofollow">`

### 8.2 접근성

- 필터 칩 `role="tab"` + `aria-selected`
- 검색 입력 `<label>` 명시
- 주문 카드 `<article aria-label="주문 OOO">`
- 상태 배지 `aria-label="배송 상태: OOO"`
- CTA 버튼 `aria-label` 명시 ("주문 OOO 상세 보기")
- 페이지네이션 `<nav aria-label="페이지">` + 현재 페이지 `aria-current="page"`
- Tab 순서: 사이드 메뉴 → 필터 → 검색 → 첫 카드 → CTA → 다음 카드

### 8.3 성능

| 지표 | 목표 | 전략 |
|---|---|---|
| LCP | ≤ 2.5s | 페이지당 10건 페이징 + 썸네일 lazy (첫 3개만 즉시) |
| INP | ≤ 200ms | 필터 변경 debounce 200ms + URL query history.replaceState |
| CLS | ≤ 0.1 | 카드 height 가변이지만 skeleton 동일 height로 보호 |
