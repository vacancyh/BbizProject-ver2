## 1. 개요

| 항목 | 내용 |
|---|---|
| URL | `/order/fail?orderId=ORD-YYYYMMDD-XXXXXX&code=<error_code>&message=<encoded>` |
| 라우트 타입 | CSR (Client) — 사용자별 주문 상태 100% 동적. SSR 부적합 |
| 진입 경로 | 토스 MCP 결제 콜백 실패 시 자동 리다이렉트 (`router.replace`). s18 주문서에서 [결제하기 →] → 토스 결제창 → 실패 사유 발생 → 본 화면 |
| 목적 | (1) 결제 실패 사유 안내 (코드별 카피) (2) 재시도 동선 제공 (카드 정보 다시 입력 / 다른 카드) (3) 주문서로 복귀 (orderId 유지, 장바구니 보존) (4) 재고는 5분 후 자동 해제 (PAY-U-013 멱등성) |
| 액터 | **회원 전용** (본인 주문만). 비로그인 → 로그인 게이트 / 타인 orderId 접근 → 403 |
| SEO 인덱싱 | X (`<meta name="robots" content="noindex, nofollow">` + `robots.txt: Disallow: /order`) |
| 회원 가드 | middleware: 비로그인 시 `/auth/login?next=<현 URL>` 302 리다이렉트 |

## 4. 상태 (State Matrix)

| 상태 | UI / 동작 |
|---|---|
| **정상 (콜백 실패 후 진입)** | §3 전체 정상 표시. 사유 코드별 카피 노출. 5분 카운트다운 시작 |
| **로딩 (주문 데이터 fetch)** | 진행 단계 표시 + 본문 skeleton (아이콘+카피+카드) |
| **사유 코드 없음 (`?code` 누락)** | "UNKNOWN" 처리 → 기본 카피 + CS 안내 강조 |
| **잘못된 사유 코드 (매핑 안 됨)** | 동일 → "UNKNOWN" 처리 |
| **5분 카운트다운 중** | "재고가 해제되기까지 N분 N초" (1분 미만 시 강조 — 빨강) |
| **5분 경과 (재고 자동 해제 후)** | 안내 변경: "재고가 해제됐어요. 다시 결제하려면 장바구니에서 상품을 확인해주세요" + [장바구니로] CTA 강조 |
| **STOCK_SHORTAGE (E-001) 진입** | 본 화면에서 즉시 환불 안내 표시 + 해당 상품 장바구니에서 자동 제거 + 토스트 |
| **타인 orderId 접근 시도** | 403 페이지 또는 모달 "본인 주문이 아니에요" (A-API-002 IDOR 방어) |
| **존재하지 않는 orderId** | "주문 정보를 찾을 수 없어요" + [홈으로] / [장바구니로] |
| **이미 결제 성공한 orderId 접근** | (콜백 race condition 또는 사용자 새로고침) `/order/complete?orderId=<>` 자동 리다이렉트 |
| **이미 취소된 orderId** | "이 주문은 취소됐어요" + [장바구니로 돌아가기] |
| **재시도 클릭 (주문서 복귀)** | `/checkout?orderId=<>` 이동. 카드 정보만 빈 폼. 배송지·쿠폰·포인트·약관 동의는 유지 |
| **재시도 (다른 카드 강조)** | `/checkout?orderId=<>&change_card=1` 이동. 카드 정보 입력 영역에 자동 focus + 안내 카피 "다른 카드로 시도해보세요" |
| **rate limit (재시도 너무 많음)** | 동일 orderId 5분 내 3회 이상 실패 시 모달 "결제가 계속 실패해요. 고객센터로 문의해주세요" + CS 강제 안내 (s20-Q01 정책) |
| **네트워크 오류 (본 화면 fetch 실패)** | 토스트 + 본 화면 retry 버튼 |

## 5. 예외·엣지 케이스 (`01_사용자_플로우.md §7` 참조)

| ID | 케이스 | 처리 |
|---|---|---|
| **E-001** | 결제 승인 직후 재고 차감 실패 (다른 사용자가 마지막 재고 선점) | **서버 측 즉시 전액 환불 + 주문 자동 취소** (PAY-U-008B/C). 본 화면 진입 시 `?code=STOCK_SHORTAGE` 으로 분기 → 환불 진행 안내 + 해당 상품 카트 자동 제거 + 다른 상품은 카트 보존 |
| **E-002** | 동일 주문 PG 콜백 2회 도달 | 멱등성 키로 1회만 처리 (ORD-U-008C). 본 화면 진입 시 첫 콜백이 성공이면 `/order/complete` 자동 리다이렉트, 첫 콜백이 실패면 본 화면 유지 |
| **E-003** | 결제 중 세션 만료 → 토스 결제창 완료 | 토스 응답 기반 주문 상태 정합성 복구 (PAY-U-009). 본 화면 진입 시 서버에서 토스 status 재조회 → 결과 분기. 결과가 "DONE"이면 `/order/complete`, "ABORTED"면 본 화면 유지 |
| **PAY-U-013** | 결제 실패 후 재고 5분 락 유지 → 자동 해제 | 멱등성 키 기반. 5분 동안 동일 orderId 재시도 시 재고 락 유지. 5분 후 자동 unlock. 본 화면 카운트다운으로 사용자에게 시각화 |
| **5분 내 재시도 성공** | 동일 orderId + 새 결제 시도 → 토스 결제창 → 성공 | 동일 orderId 결제 완료. `/order/complete?orderId=<>` 리다이렉트 |
| **5분 경과 후 재시도** | 동일 orderId 만료 → 카트에서 새 주문 생성 | `/checkout` 진입 시 새 orderId 발급. 단 카트 상품은 유지 (재고는 재검증) |
| **장바구니 보존 (실패 후)** | 카트 그대로 유지 | 결제 실패는 카트를 비우지 않음. 단 STOCK_SHORTAGE 시 해당 상품만 자동 제거 |
| **자동 결제 재시도 (NETWORK_ERROR)** | 권장: 사용자 명시 클릭 후 재시도 | 자동 재시도 X (사용자 의사 확인 필수 — 중복 결제 방지) |
| **할부 불가 사유 응답** | 카드사가 선택 할부를 지원하지 않음 | 카피 안내 + 주문서 복귀 시 일시불 옵션 강조 (사장님 결정 — s20-Q02) |
| **위변조 콜백 진입** | URL `?code=<임의값>` 직접 조작 | 본 화면은 안내만 (사용자 직접 진입 가능). 단 주문 데이터는 서버에서 토스 status 재검증 → 위변조 무력화 |
| **로그아웃 상태 진입** | 본 화면 진입 시점에 세션 만료 | `/auth/login?next=<현 URL>` 자동 리다이렉트 (middleware) |
| **타인 주문 접근 (IDOR)** | URL의 orderId 임의 변경 | 서버에서 본인 주문 검증 → 403 (A-API-002) |
| **결제 실패 알림 발송 (선택)** | 카카오 알림톡 "결제가 완료되지 않았어요" + 재시도 링크 | 선택 옵션. Q-03 (마케팅 채널 우선순위) 확정 후 (s20-Q03) |
| **결제 실패 후 사용자 이탈 (탭 닫기)** | 카트는 유지, 재고는 5분 후 자동 해제 | 별도 처리 없음. 사용자 재진입 시 카트 그대로 |

## 8. SEO · 접근성 · 성능

### 8.1 SEO

- `<title>`: "결제 실패 | LUMI"
- `<meta name="robots" content="noindex, nofollow">`
- `robots.txt`: `Disallow: /order`
- 사이트맵 미포함

### 8.2 접근성 (WCAG AA / KWCAG 2.2)

- ✗ 아이콘 `aria-hidden="true"` (장식) + H2가 본문 의미 전달
- 사유 코드별 카피 `role="alert"` (페이지 mount 시 스크린리더 즉시 안내)
- 카운트다운 (5분 재고 해제) `aria-live="polite"` (1초 단위 안내는 noisy → 분 단위 안내 권장)
- 모달 (rate limit 차단) `role="dialog"` + focus trap + ESC 닫기
- Tab 순서: 주문서로 돌아가서 다시 결제하기 → 다른 카드로 결제하기 → 장바구니로 돌아가기 → 고객센터 전화
- 모바일 sticky bar의 [다시 결제하기 →] `aria-label="다시 결제하기 (주문서로 이동)"`
- 전화 링크 `tel:` 명시 + `aria-label="고객센터 전화 1588-XXXX"`
- 빨강 컬러만으로 의미 전달 X — 아이콘 (✗) 병기

### 8.3 성능 (Core Web Vitals)

| 지표 | 목표 | 전략 |
|---|---|---|
| LCP | ≤ 1.5s | ✗ 아이콘 + H2 critical CSS / 주문 정보 카드는 fetch 후 |
| INP | ≤ 100ms | CTA 클릭 즉시 router push |
| CLS | ≤ 0.05 | 주문 정보 카드 height 예약 (skeleton과 동일) |

- 본 화면 mount 시 토스 status 재조회 (E-003 race 방어) — 비동기, 사용자 노출 X
- 5분 카운트다운은 client-side setInterval (서버 시간 기준 동기화)
