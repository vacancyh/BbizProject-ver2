- **박제일**: 2026-05-21
- **단계**: S0 전체 단계 (Phase 1~4 + 도메인 + LUMI 트랙) 공통
- **목적**: 모든 단계에서 발견된 미결 사항을 단일 문서에 수집·append하여 **사장님이 한 번에 일괄 결정**할 수 있도록 관리
- **사장님 verbatim (2026-05-21)**: "미결은 모든 단계에서 한번에 처리 할꺼야 . 계속 관리하고 따로 문서로 append해서 관리 줘"

## 1. Append 규칙 (sub-agent / main 공통 의무)

1. **새 미결 발견 시** → 본 문서 §3 (미결 표) 에 신규 행 추가 (sub-agent도 본 파일에 append 허용)
2. **고유 ID 부여**: 다음 prefix 체계 사용
   - `Q-NN` = 비즈니스/정책 미결 (사장님 결정 영역)
   - `I-NN` = IA·정보구조 미결
   - `sNN-QXX` = 특정 화면 .md 내 미결 (예: s01-Q01)
   - `dNN-QXX` = 특정 도메인 .md 내 미결 (예: d17-Q01)
   - `T-NN` = 기술 미결 (백엔드·인프라·라이브러리 선정)
   - `L-NN` = LUMI 디자인 트랙 미결
3. **각 미결 행 필수 컬럼**: ID · 발견 단계 · 발견 출처 (파일:줄) · 내용 · 옵션 · 차단 영역 (Blocked-by) · 권장안 · 상태
4. **상태 라벨**: `OPEN` (사장님 결정 대기) / `CONFIRMED` (확정·이력 §4로 이동) / `OBSOLETED` (요건 변경으로 무효)
5. **확정 시 처리**:
   - §3 미결 표에서 해당 행을 §4 확정 이력으로 **복사** (append)
   - §3 행 상태 라벨 `CONFIRMED` 로 변경 (삭제 X — 참조 보존)
   - 영향받은 화면/도메인 .md 의 "미결" 섹션을 main 이 일괄 갱신 (sed 권장)
6. **사장님 결정 시점**: 본 문서가 일정 분량 누적 후 사장님이 "미결 일괄 처리" 명령 시 — 일괄 검토 회의 형태로 진행
