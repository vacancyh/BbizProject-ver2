## 4. 구현 전 반드시 해소 — BLOCKER 8건
### 법령 (운영 불가 직결)
- **L-01** 환불 기산점 오기: §18은 (배송 후 반품) "재화 반환받은 날" 기산인데 "통지일"로 오기. → 기산점 2분기 필수.
- **L-02** 환불 지연이자(연 15%) 전면 누락: 3영업일 초과 시 법 위반. → `refunds.due_date`+지연이자 산정 신설.
- **L-03** 상품정보제공고시 필수항목 검증이 "다음 단계"로 후순위: 누락 게시 = 법 위반. → immediate 승격.

### 도메인 간 (데이터 오염 직결)
- **B-01** 부분취소 반올림이 주문·결제·쿠폰 3도메인 미정합 → 환불액≠PG취소액≠정산액. (미결 #1)
- **B-02** 0원(포인트 100%) 결제 시 order.paid 이벤트 주체 미정의 → 주문 pending 고착.
- **B-03** 주문 status ↔ 배송 status ↔ state-machine config 3중 미정합(설계서 자인). → config 단일권위+매핑표.
- **B-04** 위시(상품)→카트(SKU) 단위 변환 + 한도 충돌 계약 미정의.
- **B-05** 리뷰 적립 포인트 금액 권위 충돌 + `order.confirmed` vs `order.purchase_confirmed` 이벤트명 불일치(4도메인 트리거 미작동).

## 5. 내 설계서(상품_카테고리) MAJOR 2건 — 정직한 적출
- **A1** 카테고리 트리를 S0(1-2단)와 달리 "4단"으로 임의 확장(d13 Q1 미결 건너뜀).
- **A2** "상품 다중 카테고리 배치"로 설계했으나 S0 d12는 단일 `category_id` NOT NULL — §2에서 "1상품=1분류"라 적고 §5.1에서 뒤집은 self-contradiction.
- → 둘 다 S0 스키마 변경이라 **사장님 결정** 필요(B-차단 #32 카테고리 단수와 연결). 미정 시 S0(단일분류·1-2단) 유지.
