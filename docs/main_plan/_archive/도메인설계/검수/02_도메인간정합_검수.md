# 02. 도메인 간 정합 검수 (Cross-Domain Consistency Audit)

> 검수 축: 도메인 간 모순·정합 오류 적출 (adversarial)
> 대상: `도메인설계/` 9개 설계서 + `상품_카테고리_설계.md`
> 작성일: 2026-05-31
> 원칙: 추측 금지. 파일 경로·줄 근거 명시. 단일 도메인 내부 문제는 본 검수 범위 외(2개 이상 도메인 충돌만 적출).

---

## 0. 검수 요약

- **검사 대상 도메인 10종**: 회원(d11) · 상품/카테고리(d12/d13) · 장바구니(d14) · 위시리스트(d15) · 주문(d16) · 결제(d17) · 배송(d18) · 리뷰문의(d19) · 쿠폰포인트(d20) · 관리자(d21).
- **BLOCKER**: 5건
- **MAJOR**: 9건
- **MINOR**: 6건

심각도 정의: **BLOCKER** = 구현 시 금액/재고/상태 불일치로 데이터 오염·법령 위반·런타임 충돌 직결(구현 전 필수 해소). **MAJOR** = 도메인 경계·계약 불일치로 통합 시 오작동 가능(설계 확정 전 정렬 필요). **MINOR** = 용어/기본값/표기 불일치(운영 혼선, 정렬 권장).

## 2. 최중대 3건 요약 (사장님 우선 결정 권고)

1. **B-01 (반올림·산출순서 3중 미정합)**: 부분취소 반올림 정책이 주문·결제·쿠폰포인트 3개 도메인에서 각각 미결·기본값 상이(절사 vs 미결 vs 미언급). 동일 부분취소의 환불액·정산액이 도메인마다 1원 단위로 달라져 PG 취소액 ≠ DB 환불액 ≠ 정산액 불일치 발생. **주문 도메인을 반올림 단일 권위로 확정 후 결제·쿠폰포인트가 동일 상수 참조** 필수.

2. **B-03 (주문 status ↔ 배송 status ↔ state-machine config 3중 미정합)**: 주문 설계서 스스로 state-machine config에 `preparing/confirmed/partially_*` 5종 누락을 지적. 배송은 fulfillment status를 별도 보유하며 주문 status와의 매핑표 부재. 구현 시 상태 전이 그래프 충돌·주문 상태 고착 위험. **state-machine 모듈 config를 단일 권위로 삼고 order/fulfillment rollup 매핑표 박제** 필수.

3. **C-02 (이벤트명 `order.confirmed` vs `order.purchase_confirmed` 불일치)**: 주문은 `order.confirmed` 발행하나 회원·쿠폰포인트·리뷰 3개 도메인이 `order.purchase_confirmed`를 구독. **존재하지 않는 이벤트 구독 → 구매확정 시 등급 가산·포인트 적립·리뷰 작성권한 부여가 전부 미작동**. 단순 명명 불일치이나 영향 범위가 핵심 비즈니스 흐름 4개 도메인이라 BLOCKER급 파급. 이벤트명 1개로 즉시 통일 필요.
