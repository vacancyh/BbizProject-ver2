# 주문(Order) 도메인 — 엣지케이스 강화 설계

> **대전제**: ① 오류 없음(전자상거래법 청약철회·정산 정합) ② 한국 친화 ③ 코드베이스 수렴(Medusa v2 native + 커스텀 모듈 격리). 추측 금지·근거 명시.
> **단일 권위 레이어 준수**: 본 문서는 `_보강설계_결정반영.md`(2026-05-31 사장님 권장안 확정)를 최상위 권위로 따른다. 충돌 시 보강설계 > 주문_설계 > S0 순.
> **확정 상수(보강 A-1·A-2 인용)**: `ROUNDING=FLOOR(절사, 고객 유리)` / 무료배송 임계 `50,000원`(권위=배송 `delivery_fee_policy`) / 0원 결제 = `payment.zero_payment_confirmed` 구독 / 구매확정 이벤트명 = `order.confirmed`(통일) / 자동확정 = `14일 + D-3 알림`(배송 권위) / 블랙리스트 진행주문 = 자동취소 안 함(운영 수동) + 신규만 차단.

| **E-D03** | 동시 주문 race(재고 1개에 2주문) | 마지막 재고 1개에 동시 주문 2건 | 재고 음수·오버셀 | 재고 차감 = `SELECT FOR UPDATE on product_skus` + SERIALIZABLE. 1건 성공, 2번째는 잔량 0 → 422/409(재고 소진) + 주문 롤백. serialization_failure(40001) 자동 재시도 50ms×2(F-ISO-05). | F1, F-ISO-01/05 |
| **E-D04** | 사용자 취소 + 관리자 강제취소 동시 | 동일 주문에 사용자 전체취소 + 관리자 force-cancel 동시 | 이중 환불·이중 재고복구 | `orders.version` 낙관락 — **사용자 의도 충돌(분류 1) = 즉시 409**(재시도 X, F-OPTLOCK-04). 1건만 처리, 나머지 "이미 취소됨" 응답(F4). | F4, F-OPTLOCK-02/04 |
| **E-D05** | 사용자 부분취소 + 관리자 강제 부분취소 동시(같은 라인) | 동일 `order_item`에 두 부분취소 | 라인 이중 취소 | `orders.version` 낙관락 + 라인 단위 `UNIQUE(order_item_id, cancelled_at)` → 1건만 성공(주문 §6.5 #5). 다른 라인이면 둘 다 허용. | F4, 주문 §6.5#5 |
| **E-D06** | 자동취소 배치 + 사용자 부분취소 동시 | 30분 경과 시점에 사용자가 일부 라인 취소 | 배치 전체취소 vs 부분취소 충돌 | 배치 `WHERE status IN (pending)` + 라인 `SELECT FOR UPDATE`. pending이면 미결제이므로 부분취소 무의미(전체 자동취소가 우선). paid 이후만 부분취소 유효 → 상태 조건으로 분기(주문 §6.5 #8, 멱등). | F10, 주문 §6.5#8 |
| **E-D07** | N회 부분환불 동시 도달(누적 검증 race) | 부분환불 webhook 콜백 N건 동시 | 누적 환불액 > 결제액(과환불) | `refunds.idempotency_sub_key` UNIQUE + `payments.version` 낙관락(d17). 누적 검증 race = `REFUND_AMOUNT_RACE` 자동 재시도(주문 §6.5#4, §6.5.1). | F-IDEM-02, 주문 §6.5#4 |
