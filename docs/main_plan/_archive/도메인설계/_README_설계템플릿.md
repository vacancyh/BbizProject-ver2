# 도메인 설계 (코드베이스 정합) — 표준 템플릿

본 폴더는 각 도메인을 **"우리 S0 설계 + 성숙 플랫폼(Spree/Vendure) + 한국 관행(웹) + Medusa 코드 매핑"** 으로 종합 설계한 문서를 담습니다.

## 대전제 (모든 설계 공통)
1. **오류 없음** — 법령(전자상거래법·전자금융거래법 등)·정합성 최우선.
2. **한국 친화** — 한국 쇼핑몰 관리자에게 익숙한 용어·구조·운영 흐름.
3. **코드베이스로 수렴** — 모든 설계는 Medusa(v2.15.3) 코드에 매핑되어 구현으로 이어진다. 문서만 남기지 않는다.

## 파일 명명
- `{도메인한글}_설계.md` (예: `회원_설계.md`, `주문_설계.md`)

## 표준 섹션 (고정 순서)
1. **도메인 개요** — 1줄 책임 + 범위 경계
2. **우리 S0 설계 요약** — `05_도메인정의서/d1X_*.md` + 짝 기능정의서 핵심 요약 (엔티티·룰·이벤트)
3. **성숙 플랫폼 패턴** — Spree/Vendure 해당 도메인 설계에서 배울 점 (출처 파일 경로 명시)
4. **한국 관행 (웹 근거)** — 카페24·스마트스토어·고도몰·토스페이먼츠 등 실제 관행 (출처 URL 명시)
5. **종합 설계 결정** — 위 3개를 종합한 우리 설계 (엔티티·관계·룰·정책). 추측 금지, 근거 명시.
6. **Medusa 코드 매핑** — ⓐ 활용할 Medusa native 모듈 ⓑ 필요한 커스텀 모듈/defineLink/API route/admin route ⓒ 마이그레이션 계획. `legal-kr/withdrawal-7day` 격리 패턴 준수(코어 무수정).
7. **현 코드와의 관계 + 구현 단계** — 이미 있는 코드(있으면)와의 관계 + immediate / 다음 단계 분리

## 근거 의무
- 우리 문서·Medusa 패키지·웹 출처를 **실제로 읽고** 근거로 삼는다. 확인 못한 항목 = "(추가 확인 필요)".
- 모든 문서 한국어 존댓말.
