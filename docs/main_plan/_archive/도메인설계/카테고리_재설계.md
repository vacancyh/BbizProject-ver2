## 0. 한 장 요약 (핵심 재설계 결정)

1. **진열 카테고리는 Medusa native `product_category` 1개로 끝낸다** — 커스텀 트리 테이블 신설 금지. native가 (a) Materialized Path 기반 nested 트리(parent_category / category_children) (b) product↔category **N:N pivot** 을 이미 제공하므로, 우리가 원하는 "4단 트리 + 진열 다중"이 코어 무수정으로 완성된다. (출처: Medusa 공식 — Announcing Product Categories)
2. **primary 분류는 `product.metadata.primary_category_id`(또는 격리 link)로 1개 지정** — N:N 위에 "1차 진열 홈/빵부스러기/canonical 권위" 를 얹는 얇은 규칙. 스키마 변경 없이 SEO 중복(외부 관행이 정확히 요구하는 패턴)을 해소한다.
3. **3축 분리 확정**: 진열 카테고리(어디에 진열) ≠ 상품유형(무엇을 파는가=옵션+법정고시) ≠ 컬렉션(마케팅 묶음). 한국 주요 몰(카페24·스마트스토어·고도몰)·성숙 플랫폼(Medusa·Spree)이 모두 동일하게 분리한다.
4. **자동분류(가상 카테고리)는 MVP 제외, 컬렉션으로 대체** — "신상·세일·BEST" 는 카테고리가 아니라 컬렉션/뱃지(d12 is_new/is_best/is_sale) 책임. 진열 카테고리는 **수동 트리만** (오류 0 · 관리 단순).
5. **비활성·이동·병합·slug 변경 규칙을 트리 전파 룰로 명문화** — 부모 비활성 → 자손 cascade 비활성, slug 변경 시 301 보류(MVP 404)+canonical 고정, 삭제는 상품·자식 0건일 때만.

## 2. 외부 관행 비교 (출처 명시)

### 2.1 한국 주요 몰 — 진열 카테고리 트리
| 몰 | 트리 단수 | 정렬 | 진열 방식 |
|---|---|---|---|
| **카페24** | **대 > 중 > 소 > 상세 (4단)** | 드래그 후 "분류 이동 저장" | 상품을 분류에 연결, 하위분류 상품 노출 옵션 |
| 스마트스토어 | 카테고리 관리 + 상품-카테고리 연결 | — | 카테고리 단위/개별 상품 단위 연결 |
| 고도몰 | 진열 카테고리 + 상품정보제공고시 별도 | — | 분류↔상품 매핑 |

→ **4단 트리 + 드래그 정렬 + 상품-분류 다대다 연결**이 한국 표준. 사장님 확정값과 정확히 일치. (출처: 카페24 Help Center "상품 분류는 어떻게 등록하나요" / "상품 분류 관리")

### 2.2 한국 — 진열 카테고리와 "상품정보제공고시 품목"의 분리
- 전자상거래법 「상품 등의 정보제공에 관한 고시」 = **약 40개 표준 품목**(의류 / 신발·가방 / 가구 / 영상·음향기기 / 휴대폰 / 화장품 / **(19) 시계·안경·선글라스** / 식품·신선식품 / 유아용품 / 악기 / **(29) 보석류** / 도서 / 여행 / 생활용품 등). 품목별 필수 기재항목 상이.
- **귀금속/보석/시계 필수항목** = 상품명 · **소재** · **중량** · 가공 관련 상세 · **제조국** · **치수** · 사용·관리방법 · 필수 부품 정보 · **A/S 및 품질보증기준**. (출처: 고도몰 상품정보제공 고시 가이드 / law.go.kr 전자상거래 상품정보제공 고시)
- 모든 한국 몰은 상품 등록 시 **"고시 품목 드롭다운"** 을 진열 카테고리와 **별도**로 제공한다 → 우리 **상품유형(product_type) 축**이 정확히 이 역할.

### 2.3 성숙 플랫폼 — 카테고리 vs 컬렉션 분리 (Medusa)
- **Product Category** = 계층(nested), **상품 다중 소속 가능**(N:N pivot), 조직화 목적. Materialized Path 트리(parent_category / category_children).
- **Product Collection** = 평면, nesting 미지원, **마케팅/세일 한정 묶음**(예: 봄 컬렉션).
- → "신상/세일/기획전" 을 카테고리로 만들면 트리가 오염된다. **컬렉션·뱃지로 분리**가 정답. (출처: Medusa Docs — Announcing Product Categories / Discussion #3865 "categories vs collections" / nested-categories)

### 2.4 카테고리 SEO (글로벌 표준)
- **primary 경로 1개 선정 + canonical 로 중복 경로 통합** — 같은 상품이 여러 카테고리에 진열될 때 SEO 중복을 막는 표준 패턴. 우리의 primary_category 결정과 정확히 일치.
- **빵부스러기(BreadcrumbList)는 필터 조합이 아니라 primary 카테고리 경로** 를 표시(Home > 반지, 필터값 포함 금지).
- **faceted(필터) URL = canonical 은 파라미터 없는 정적 URL** 로 고정, 다중 필터 조합은 `noindex, follow`. 페이지네이션 2·3페이지는 1페이지로 canonical.
(출처: Search Engine Land — SEO breadcrumbs / faceted navigation, Search Engine Journal — Faceted Navigation Best Practices, Uproer — Category Page SEO)

> **종합**: 우리 확정값(4단 트리 + 진열 다중 + primary 1개 + 카테고리/유형/컬렉션 분리)은 한국 관행과 글로벌 SEO·플랫폼 표준 양쪽에 모두 부합한다. 추가로 외부가 강하게 권고하는 두 가지를 본 설계에 반영한다 — (a) **자동분류는 카테고리가 아닌 컬렉션** (b) **filter URL의 noindex+canonical 정책 명문화**.

## 3. 재설계 / 강화 — 진열 카테고리 정밀 명세

### 3.1 엔티티·관계 (Medusa native 매핑 기준)

진열 카테고리는 **신규 테이블을 만들지 않고** Medusa native `product_category` 의 필드에 우리 d13 의미를 매핑한다.

| d13 개념 | Medusa native `product_category` 필드 | 비고 |
|---|---|---|
| id | `id` (prefix `pcat_`) | |
| name(한글) | `name` | 화면 표기 "한국어명" |
| slug(영문 UNIQUE) | `handle` (UNIQUE) | URL용. 영문·숫자·하이픈 패턴 검증은 admin route에서 |
| parent_id (트리) | `parent_category_id` | Materialized Path → 4단까지 depth 제한은 룰로 강제 |
| is_active | `is_active` | native 보유 |
| (트리 노출 여부) | `is_internal` | native — 관리자만 보는 운영용 분류에 활용 가능(MVP 미사용) |
| display_order | **`metadata.display_order`** 또는 native `rank`(존재 시) | 드래그 정렬 결과 |
| thumb_url | **`metadata.thumb_url`** | 홈 카드 썸네일(선택) |
| (1차 진열 권위) | — (상품 측) | §3.2 primary 참조 |

- **상품 ↔ 카테고리 = native N:N pivot** (`product_category_product`). 1상품 → N개 진열 카테고리. 이로써 검수 A2 self-contradiction 해소.
- **트리 depth = 4단(대>중>소>상세) 강제**: native는 무제한 nesting 이므로 **5단 이상 생성 시도 = 422 차단** 룰을 admin route에 둔다. (s39 §4.1 "트리 2단까지" 토스트 문구 → "4단까지" 로 갱신)

### 3.2 primary 분류 (1차 진열 권위)

- **저장**: `product.metadata.primary_category_id`(string). 스키마 변경 0, native metadata 활용.
  - 대안(2단계 권장): `src/links/product-primary-category.ts` defineLink 로 명시 link 1건(읽기 정합·인덱싱 유리). MVP는 metadata로 시작, 트래픽/쿼리 필요 시 link 승격.
- **불변식(invariant)**: primary_category_id ∈ 해당 상품의 N:N 진열 카테고리 집합. (등록·수정 시 서버 검증 — primary가 진열 목록에 없으면 422)
- **권위 책임**:
  - (a) **빵부스러기·canonical** = primary 경로 1개 (§3.4 SEO).
  - (b) **연관 상품(F16)** = primary 카테고리 기준 ∩ 자기 제외 ∩ 품절 제외.
  - (c) 사용자 목록 `/shop/[cat]` 진입 = 해당 cat 의 N:N 소속 상품 전체(primary 무관).
- **기본값**: 등록 시 진열 카테고리 1개만 선택하면 그것이 자동 primary. 다중 선택 시 첫 선택을 primary 기본 + 라디오로 변경 가능.

### 3.3 상품유형(고시 품목)과의 연계 — 카테고리 ↔ 유형 매핑

핵심: **진열 카테고리는 옵션·고시를 결정하지 않는다. 상품유형이 결정한다.** 둘은 독립 축이되 **권장 매핑(추천)** 으로 등록 UX를 돕는다.

- **연계 모델**: `product_category.metadata.suggested_product_type_id`(선택) — 카테고리 선택 시 상품유형을 **추천**(강제 아님). 예: 진열 "반지" 선택 → 상품유형 "악세서리(손가락 호수)" 추천.
- **권위 분리(불변식)**:
  - 옵션 템플릿 + 고시 필수항목 = **상품유형(product_type_template) 단일 권위** (현 코드 정합).
  - 진열 카테고리 = 추천만. 관리자가 다른 유형으로 덮어쓰기 가능.
- **고시 검증(대전제① 오류 0)**: 게시(status=active) 전, 상품의 product_type 에 정의된 `disclosure_field.required` 누락 시 게시 차단(`_보강설계 §L-03` = 단계1.5로 승격). **진열 카테고리 비활성/이동은 고시 검증과 무관** (분리 유지).
- 주얼리 MVP 매핑 예시:

| 진열 카테고리(대) | 추천 상품유형 | 고시 품목 코드 | 고시 필수항목(주얼리) |
|---|---|---|---|
| 반지 / 목걸이 / 귀걸이 / 팔찌 | 악세서리(주얼리) | `accessory`(→ 정밀화 시 `jewelry`) | 소재·중량·제조국·치수·사용관리·A/S·품질보증 |

> 주의: 현 시드 `disclosure_code: "accessory"` 는 주얼리 고시(보석류/시계 (19)·(29)) 정밀화 시 `jewelry` 로 세분 권장. 단 MVP 옵션(손가락 호수)은 유지.

### 3.4 카테고리 SEO 강화 (F5·F6 정밀화)

| 항목 | 룰 | 근거 |
|---|---|---|
| title | `<카테고리 한국어명> + 브랜드` (F5 유지) | CAT-U-007, s03 §8.1 |

### 3.5 비활성 · 이동 · 병합 · 삭제 · slug 규칙 (트리 전파)

|---|---|---|
| **CAT-F11 (비활성 cascade)** | 부모 카테고리 비활성 → **자손 전체 effective 비활성** | 사용자 영역: 부모 OR 임의 조상이 비활성이면 미노출·404. is_active 자체는 자식 보존(복구 시 자동 회복) |
| **CAT-F12 (비활성 상품)** | 비활성 카테고리에만 진열된 상품 = 사용자 검색·홈·목록 제외. **다른 활성 카테고리에도 진열돼 있으면 노출 유지** | N:N 이므로 "전 진열 카테고리가 모두 비활성/비가시일 때만" 상품 제외 (E-014 정합, F3 정밀화) |
| **CAT-F13 (이동)** | 드래그로 parent_id 변경 = 순환참조 차단(본인·자손으로 이동 금지) + depth 4단 초과 차단 | s39 §4.1 룰 정합. 이동 후 자손 depth 재계산 → 4단 초과 발생 시 422 |
| **CAT-F14 (병합, 신규)** | 카테고리 A → B 병합 = A 진열 상품을 B 로 재배치 + A 의 primary 상품은 primary 를 B 로 갱신 + A 삭제. (MVP는 수동: 상품 일괄 재배치 후 A 삭제 — 별도 병합 API는 2단계) | 운영 안전(삭제 차단 F2 우회 경로) |
| **CAT-F15 (삭제)** | 진열 상품 0건 **AND 자식 카테고리 0건** 일 때만 삭제(409 차단) | F2 강화 — 자식 보유도 차단 추가 |
| **CAT-F16 (slug 변경)** | slug(handle) 변경 허용 + 캐시 PURGE + **MVP는 구 URL 404** (canonical 은 신규로 고정). 301 redirect 는 2단계(s39-Q08 = Q-LATER) | s39 §5, F6 |
| **CAT-F17 (primary 정합)** | 상품의 진열 카테고리에서 primary 카테고리를 제거하려 하면 차단(다른 진열로 primary 재지정 강제) | §3.2 불변식 |

### 3.6 자동분류 / 가상 카테고리 — MVP 제외, 컬렉션 대체 (결정)

- **결정**: 진열 카테고리는 **수동 트리만**. "신상/세일/BEST/기획전" 류 룰기반 자동분류는 **카테고리로 만들지 않는다**.
- **대체 경로**:
  - 신상/BEST/SALE = d12 파생 필드(`is_new`/`is_best`/`is_sale`) + 뱃지 + 홈 큐레이션(PRD-A-025~027). 카테고리 아님.
  - 시즌/기획전 = **컬렉션(Medusa product_collection)** (3축 ③). 평면·마케팅.
- **근거**: ① 자동분류 룰엔진은 오류·캐시 정합 리스크 ↑(대전제① 위배 가능) ② 카테고리 트리에 마케팅 묶음을 넣으면 SEO·네비 오염(외부 표준 위배) ③ 한국 몰도 진열 카테고리는 수동, 자동은 "추천/기획전" 별도 영역.

## 4. Medusa 매핑 (코어 무수정 격리)

| 축 | Medusa native | 우리 커스텀 | 격리 위치 |
|---|---|---|---|
| ① 진열 카테고리 | **`product_category`** (nested 4단 + N:N pivot + is_active + handle) **그대로** | 신규 테이블 0. `metadata.display_order/thumb_url/suggested_product_type_id` + admin route(트리 CRUD·reorder·slug-check·thumb) | `src/api/admin/categories/` (route만, 모델 신설 X) |
| ① primary | `product.metadata.primary_category_id` | (2단계) `src/links/product-primary-category.ts` defineLink | metadata → link 승격 |
| ② 상품유형 | (라벨만 `product.type`) | **`product-type` 모듈(구현 완료)** = 옵션 템플릿 + (단계1.5) 고시 필드 정의·검증 | `src/modules/product-type/` |
| ③ 컬렉션 | **`product_collection`** | 룰기반/타임세일 연계만 커스텀(d12) | native + 일부 hook |

- 옵션/variant/SKU = Medusa native(`product_option`/`product_variant`) 그대로. 상품유형 템플릿이 등록폼에 옵션을 **주입**(현 GET /admin/product-types 흐름).
- **코어 product_category 테이블 무수정** — 모든 확장은 metadata + admin route + (선택)link. `legal-kr`·`product-type` 격리 원칙 동일.
- 캐시 무효화(F4): 카테고리 CRUD/활성/reorder 시 (a) 트리 캐시(헤더 메가메뉴·홈·s02) (b) 목록 캐시(s03 쿼리키별) (c) 검색 인덱스(E-014) PURGE. Medusa event(`product-category.created/updated/deleted`) 구독 subscriber.

### 4.1 admin API 면 (s39/d13 §5.2 정합, native 위에 얇게)
- `GET /admin/categories?status=` — 비활성 포함 트리(CAT-A-011). native list + metadata 머지.
- `POST /admin/categories` — 생성(name·handle·parent·thumb·is_active·display_order), depth 4단 검증, handle 패턴·UNIQUE 검증.
- `PATCH /admin/categories/:id` / `/:id/active` / `reorder` — 수정·활성토글·드래그 일괄(순서+계층).
- `GET /admin/categories/slug-check?slug=` — 중복 검증.
- `POST /admin/categories/:id/thumb` — S3 multipart + MIME magic 검증(A-FILE).
- `DELETE /admin/categories/:id` — 상품 0 AND 자식 0 차단(CAT-F15).
- 권한: SUPER + (MANAGER→)OPERATION (s39 §7, `_보강설계 §A-1 #2` role 정합).

### 4.2 사용자 API 면 (d13 §5.1 정합)
- `GET /api/categories` — 활성 트리(N:N count 동봉, ISR 60m).
- `GET /api/categories/:handle` — 상세(404: 미존재/비활성/조상 비활성, CAT-F11).
- `GET /api/products?cat=:handle&...` — 해당 카테고리 N:N 소속 상품(primary 무관) + 필터·정렬·페이지.
